# 学习记录

## 2026-07-29 全局英文缩写释义治理

### 学习问题
- 当前 MES 与工业自动化内容中存在大量 ERP、MOM、SCADA、PLC、OPC UA、MQTT、BOM、NCR 等缩写，学习者无法仅凭字母理解英文原词、命名逻辑和实际含义。
- 如何让所有 Markdown 与静态页面中的缩写既能就地理解，又能进入独立页面学习“为什么这样定义”？

### 已知背景
- 项目现有 MES 八阶段、模块、岗位、系统、Java 专题和 ISA-95 工业自动化体系，共 55 个入口与详情页面需要统一治理。
- 部分术语是标准首字母缩写，部分是历史名称或品牌名称；不能为 ISO、MQTT、Modbus 等名称强行编造逐字母展开。

### 分析依据与明确假设
- 先全局扫描 HTML 与 Markdown 的大写术语，再依据标准组织、协议组织或权威产品说明核实英文全称。
- HTML 中使用静态 `abbr` 语义提供英文全称与中文含义；独立术语页解释直译、为什么这样命名、体系位置和智能锁场景。
- 企业自定义缩写、字段码和产品型号不纳入行业词典，仍需由企业数据字典确认。

### 内容决策
- 新建统一英文缩写词典 Markdown 和静态学习页，并从全局页面提供入口。
- 首次出现和高频出现的缩写不只给中文简称，还需要明确英文全称；非首字母缩写明确标注“专名/历史名称”。
- 为防止术语漂移，新增自动化检查，验证词典覆盖、HTML 语义和内部链接。

### 验证与待确认
- 已全局扫描 Markdown 与 HTML 中的大写术语，统一词典覆盖 94 个标准、系统、业务、质量、通信和控制术语。
- 已为 56 个现有学习页面加入静态词典入口，并生成 1,512 处 `abbr` 语义释义；桌面端可悬停查看英文全称和中文含义，触屏端可进入完整词典阅读命名原因。
- 已核验并明确：ISO 不是首字母缩写；OPC 由历史上的 OLE for Process Control 演进为 Open Platform Communications；MQTT 的 OASIS 委员会名称与现代发布/订阅语义不能机械等同；Modbus 是协议专名。
- 已执行 `node --check assets/app.js && node --check scripts/annotate-acronyms.mjs && node --test`，54 项检查全部通过，失败、取消、跳过和待办均为 0。
- 待确认企业内部缩写、厂商设备型号、字段缩写和公司专有英文命名。

## 2026-07-29 ISA-95 与工业自动化体系学习文档

### 学习问题
- 如何基于 ISA-95 理解 ERP、PLM、MOM/MES、WMS、QMS、APS、EAM、SCADA、Historian、设备网关、HMI、PLC、机器人/运动控制、传感器和执行器组成的完整 IT/OT 制造体系？
- 如何让每个节点既有标准或官方来源解释，又能通过智能锁实际场景理解其职责、数据、状态、接口、异常和 Java 开发边界？

### 已知背景
- 学习者为 Java 全栈开发，已经具备 MES 八阶段业务主线知识，当前需要补齐从企业经营到物理设备的纵向架构。

### 分析依据与明确假设
- 以 ISA-95 / IEC 62264 的企业—制造控制分层为主要认知框架；以工业控制系统和 ISA/IEC 62443 的分区思想补充 OT 控制与安全边界。
- ISA-95 描述的是功能与信息边界，不强制每个层级必须对应一个独立软件产品；企业实际可能合并或拆分系统。
- DCS、CNC 等节点在智能锁离散装配中的使用程度不同，文档会说明适用场景，不假设企业已经部署。

### 内容决策
- 新建独立工业自动化体系知识文档，与现有 MES 文档并列，不改写现有八阶段领域文档。
- 采用“官方定义与来源、通俗释义、所在层级、业务职责、核心数据、状态、输入输出、智能锁案例、异常、Java 关注点、自测”统一模板。
- 先解释 L4 到 L0 的纵向分层，再分别设计各节点系统，最后通过一把智能锁的完整制造链验证跨层关系。
- 所有企业特定产品、协议、网络区划、设备程序责任和实时性要求均标记为待确认。

## 2026-07-29 Java MES 与生产设备开发边界

### 学习问题
- Java 开发 MES 时，是否还需要开发生产机器，以及 MES、设备系统、PLC、设备程序和嵌入式软件之间如何分工？

### 已知背景
- 企业场景为智能锁离散制造，现场可能包含扫码器、标签打印机、扭矩工具、固件烧录设备、功能测试台、视觉检测、老化设备和自动化装配线。
- 学习者岗位为 Java 全栈开发，重点是 MES 业务系统和设备集成，不预设同时承担自动化、电气或嵌入式岗位。

### 分析依据与明确假设
- 行业中通常由设备/自动化团队负责 PLC、运动控制、安全互锁、设备驱动和实时控制，MES Java 团队负责业务上下文、设备接口、采集会话、结果判定与追溯。
- 若企业已有 SCADA、IIoT 平台或边缘网关，Java MES 可能只对接统一平台；若设备仅提供 TCP、串口或厂商 SDK，则可能需要开发设备适配器或边缘采集服务。
- 实际设备协议、网络区划、程序下发权限和异常责任人为待确认事实。

### 内容决策
- 将“生产机器开发”区分为机器控制开发、设备接入开发、MES 业务开发三层，避免把设备对接误解为使用 Java 编写 PLC 或机器固件。
- 智能锁案例优先说明烧录机、功能测试台、扭矩工具、扫码器和标签打印机与 MES 的会话及数据交互。
- Java 关注点包括协议适配、会话关联、幂等重发、超时未知态、离线缓存、版本校验、安全、监控和可追溯证据。

### 验证与待确认
- 待确认企业是否已有设备网关/SCADA、设备支持的协议、哪些工位允许 MES 下发参数、原始数据保存位置及断网生产策略。
