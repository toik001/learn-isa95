# 智能锁制造 IT/OT 与工业自动化体系

> 面向 Java 全栈开发者的 ISA-95 纵向架构学习文档
> 场景：智能锁离散制造与销售
> 文档性质：行业通用教学参考，不代表目标企业已经采用相同产品、网络、协议、单据或职责划分。

> 缩写阅读说明：IT = *Information Technology*（信息技术），OT = *Operational Technology*（运营技术），MES = *Manufacturing Execution System*（制造执行系统）。本文全部缩写的英文全称与命名原因见 [MES 与工业自动化英文缩写词典](acronym-glossary.md)。

## 1. 先建立正确的总图

MES 不是直接控制电机和气缸的软件，也不是孤立在 ERP 与 PLC 中间的一台服务器。完整体系至少包含四条同时运转的链：

1. **业务指令链**：销售需求 → 产品版本 → 计划 → 工单 → 工序任务 → 设备执行参数。
2. **现场控制链**：传感器 → 控制器 → 执行器 → 物理过程；这一闭环必须满足确定性、安全和断网自治。
3. **生产证据链**：设备测点/报警 → 测试会话 → 工序结果 → 整锁 SN 履历 → 箱码 → 发货去向。
4. **治理保障链**：身份、授权、审计、版本、网络分区、时间同步、备份、变更和应急处置。

对 Java 开发者最重要的结论是：

- Java 通常负责业务事务、跨系统接口、设备会话、结果解释、追溯与监控，不负责毫秒级运动控制和安全互锁。
- MES 可以下发“生产什么、使用哪个已批准参数集”，不应绕过设备控制器直接控制危险动作。
- PLC 返回的 `PASS` 只是设备结果；MES 还要校验工单、SN、路线、版本、身份和重复提交，才能形成有效过站事实。
- 高频原始曲线通常留在 Historian、测试系统或对象存储；MES 保存业务结果、关键摘要、哈希和原始数据定位信息。

## 2. 来源等级与事实边界

本文每个节点按三类来源组织：

- **A 级：标准发布组织**，如 ISA、IEC、ISO、NIST、OPC Foundation、OASIS/Modbus Organization。
- **B 级：权威产品或行业组织**，用于解释 ERP、PLM、WMS、MES 等产品类别，如 SAP、IBM、Siemens。
- **C 级：本文教学模型**，用于把标准映射到智能锁装配线；它是设计建议，不是企业现状。

“官方解释”均为中文转述，并附原始链接，不冒充标准逐字翻译。标准全文可能需要购买；本文只依据发布组织公开的范围说明、摘要或公开指南。

## 3. ISA-95 / IEC 62264：体系的主坐标

### 3.1 官方解释

[ISA 官方](https://www.isa.org/standards-and-publications/isa-standards/isa-95-standard)将 ISA-95（亦称 IEC 62264）描述为企业与控制系统集成的国际标准系列，用层级模型组织企业技术和业务流程，并明确各层活动及接口。其当前公开层级说明可转述为：

| 层级 | ISA 官方活动含义（转述） | 通俗释义 | 智能锁例子 |
|---|---|---|---|
| Level 4 | 业务计划与物流 | 决定接什么单、做多少、何时交、成本和库存如何核算 | ERP 销售订单、采购、主生产计划、财务结算 |
| Level 3 | 制造运营管理 | 把经营目标转成车间可执行任务，并记录人、机、料、法、环、测的生产事实 | MOM/MES、质量运营、维护、仓储运营、站点级历史数据 |
| Level 2 | 监视、监督与自动控制 | 保证某台设备或某段产线按控制逻辑稳定运行 | PLC、机器人控制器、运动控制、线体 SCADA/HMI |
| Level 1 | 感知与操纵物理过程 | 测量现场状态并作用于物理对象 | 传感器、扫码器、阀岛、伺服驱动、扭矩工具 |
| Level 0 | 实际物理过程 | 真正被加工、装配、测试和搬运的对象与过程 | 锁体装配、螺钉锁付、固件烧录、开锁测试、装箱 |

[IEC 62264-1](https://webstore.iec.ch/en/publication/6675)给出企业系统与制造控制系统集成的术语和模型；[IEC 62264-2](https://webstore.iec.ch/en/publication/75127)进一步规定 Level 3 与 Level 4 交换信息的对象模型属性。

### 3.2 最容易混淆的一点：层级是活动，不是产品货架

网络资料常把“PLC 固定画在 L1、SCADA 固定画在 L2”。这是一种常用工程简图，但不能代替标准语义。应采用以下判断规则：

1. 先问“这项活动在做什么”，再判断层级。
2. 同一个产品可能承载多个层级的活动。例如一体化 PLC 既读取传感器，也执行监督控制。
3. SCADA 可能是设备/产线监督，也可能汇总站点运营数据，因此可跨 L2/L3。
4. 边缘网关是连接能力，不天然属于某一层；协议采集靠近 L1/L2，业务语义转换靠近 L3。
5. 分层不能替代网络分区。安全区与通信管道应另用 ISA/IEC 62443 思想设计。

### 3.3 ISA-95 不是只有 L0—L4

学习体系还需同时掌握：

- **设备层级**：企业 → 站点/工厂 → 区域/车间 → 工作中心/产线 → 工作单元/工位设备。
- **资源模型**：人员、设备、物料、物理资产及其能力。
- **四类制造运营**：生产运营、质量运营、维护运营、库存运营。
- **四类信息交换**：定义、能力、请求/计划、绩效/响应。
- **调度闭环**：详细排程 → 派工 → 执行 → 数据采集 → 跟踪 → 分析。

对智能锁而言，不能只有“生产工单表”。至少要能回答：哪个工厂、哪条线、哪个工位、哪台设备、哪个程序版本、哪批物料、哪个人员，在什么时间，对哪个 SN 执行了什么操作，结果和原始证据在哪里。

## 5. 节点 01：ISA-95 架构与设备层级

### 官方解释与释义

- **官方转述**：ISA-95 为企业系统和制造控制系统之间的活动与信息交换提供模型和术语。
- **通俗释义**：它像制造企业的“城市规划和地址体系”，告诉我们每类事情由谁做、数据从哪里来、应该通过什么边界交接。
- **不能误解为**：一张固定品牌产品清单，或要求企业必须采购五套独立软件。

### 设计

- 设备路径：`enterprise_id/site_id/area_id/work_center_id/work_unit_id/equipment_id`。
- 每个对象保存业务编码、显示名称、时区、状态、父级、有效期和外部系统映射。
- 能力使用“资源 + 能力项 + 数量/速率 + 有效期 + 限制条件”表达，不把日产能写死在产线主表。
- L4→L3 交换生产请求与定义；L3→L4 返回生产绩效和实绩。
- L3→L2 下发业务上下文、已批准程序引用和授权；L2→L3 返回会话、事件、结果与证据索引。

### 智能锁实际场景

华东工厂（Site）下设总装车间（Area），其中智能锁总装 1 线（Work Center）包含主板绑定、固件烧录、整锁装配、功能测试和包装（Work Unit）。工单被派到产线，具体 SN 被派到工位；测试结果必须同时带上完整设备层级，才能区分“同名测试台”。

### Java 关注点

- 层级编码不是数据库自增 ID；对外接口使用稳定业务键。
- 组织层级和设备层级不要混为一棵树。
- 设备换线、工位改造使用有效期，不覆盖历史归属。
- 所有事件保存 `occurred_at`、`received_at`、来源时钟质量与时区。

### 自测

1. 为什么 PLC 不能仅凭产品名称决定烧录程序？
2. 设备从 1 线搬到 2 线后，旧履历如何保持原归属？

## 6. 节点 02：OT 安全、区域与通信管道

### 官方解释与释义

- [NIST SP 800-82 Rev.3](https://csrc.nist.gov/pubs/sp/800/82/r3/final)将 OT 概括为通过监视或控制设备、过程和事件，与物理环境交互并造成或检测直接变化的可编程系统或设备，同时强调其安全、可靠性和性能要求。
- [ISA/IEC 62443-3-2 公开预览](https://www.isa.org/getmedia/661c718f-8e64-446d-acf9-2c6286db1b33/isa-62443-3-2-preview.pdf)要求定义评估系统边界，将系统划分为区域和通信管道，并分别评估风险与目标安全等级。
- **通俗释义**：不要只画“办公网、工厂网”两块；要把相同风险和安全要求的资产放入区域，只允许经过受控管道进行必要通信。

### 建议区域

| 区域 | 资产示例 | 允许的主要通信 | 禁止或严格限制 |
|---|---|---|---|
| 企业 IT 区 | ERP、PLM、办公终端 | 经 API/消息与制造 DMZ 交换 | 直接访问 PLC |
| 制造运营区 | MES、APS、QMS、WMS | 与 DMZ、站点服务通信 | 无审批的互联网访问 |
| 工业 DMZ | 反向代理、消息中继、跳板机、补丁/文件中转 | 双向分段代理 | 透明桥接两侧网络 |
| 现场监督区 | SCADA、Historian、工程站 | 与控制区白名单通信 | 普通办公终端长期驻留 |
| 单元控制区 | PLC、机器人、测试 IPC | 单元内确定性通信、向上报送 | 被 ERP/MES 直接轮询控制 |
| 安全相关区 | 安全 PLC、光栅、急停 | 仅批准的安全与诊断通信 | 业务系统写控制变量 |

### 关键控制

- 人员账户、服务账户、设备身份分开管理；禁用共享管理员。
- 远程维护采用审批、限时授权、MFA、跳板、全程审计和会后撤权。
- 防火墙规则以源、目标、端口、方向、用途和责任人登记。
- 配方/程序发布需要签名或哈希、版本和回滚路径。
- 备份不仅包含数据库，还包括 PLC/机器人程序、SCADA 组态、网关配置和证书。
- 安全事件响应不得破坏设备安全状态；不能照搬 IT 的“立刻断电/重启”。

### 智能锁实际场景

MES 不能打开到 PLC 的任意写端口。MES 将“SN + 工序 + 期望程序版本”发送给单元网关；网关只允许写入约定握手区。PLC 控制夹具、气缸和测试节拍，返回会话号与结果。工程师远程修改 PLC 必须经跳板机和变更单，修改后重新验证测试站。

### Java 关注点

- API、MQTT、OPC UA 凭证不得固化在代码或镜像。
- 设备命令需要命令白名单、操作者授权、双向 TLS、重放防护和审计。
- 权限应区分“查看设备”“下发已发布参数”“进入维护模式”“发布新程序”。

## 7. 节点 03：ERP

### 官方解释与释义

- [SAP 对 ERP 的说明](https://www.sap.com/products/erp/what-is-erp.html)将其描述为连接财务、人力、制造、供应链、销售和采购等核心业务流程的企业资源计划系统。
- **通俗释义**：ERP 管“企业承诺和账”，回答卖什么、买什么、做多少、什么时候要、库存账和成本如何变化。
- **边界**：ERP 不应记录每个 PLC 点位或替代工序级实时过站。

### 数据主权

- 组织、客户、供应商、基础物料、计量单位和财务维度。
- 销售订单、采购订单、计划订单/生产订单的经营版本。
- 库存账、成本、应收应付和财务凭证。
- MES 只缓存生产所需快照，并保留 `source_system/source_id/source_version/synced_at`。

### 接口

- ERP→MES：生产订单、交期、数量、物料与版本引用、计划优先级。
- MES→ERP：开工/完工数量、合格/报废数量、物料消耗、成品入库请求。
- 幂等键示例：`erp_order_no + operation_type + business_sequence`。
- 禁止用“更新整张订单”掩盖事件；数量变化必须能审计差额和原因。

### 智能锁实际场景

ERP 接到 2,000 把 A100 智能锁销售需求，生成生产订单并要求 8 月 10 日交付。MES 接收订单后选择已发布的 MBOM 和工艺版本，拆成生产工单；完工后回传 1,980 合格、15 报废、5 在制，而不是把每把锁的扭矩曲线写回 ERP。

### Java 关注点

- 防止重复完工、重复扣料和跨期间冲销错误。
- ERP 暂时不可用时使用出站箱与重试，业务状态区分“MES 已完成”和“ERP 已确认”。
- 对账任务比较累计请求量、成功量、冲销量和双方版本。

## 8. 节点 04：PLM

### 官方解释与释义

- [Siemens 对 MBOM 的公开说明](https://www.siemens.com/en-us/technology/manufacturing-bill-of-materials-mbom/)指出，制造 BOM 定义制造产品所需零件和装配件，并结合制造意图组织产品定义。
- **通俗释义**：PLM 管“允许制造什么”，包括型号、EBOM、图纸、规格、固件、工程变更和发布状态；MBOM/工艺系统把设计定义转换成“现场怎么造”。
- **边界**：MES 消费受控发布版本，不应让班组在现场直接修改正式 BOM 和工艺规范。

### 核心对象与状态

- 产品型号、硬件版本、区域/客户配置。
- EBOM、MBOM、替代料、生效范围和有效期。
- 图纸、检验规范、固件包、参数规范与文档校验值。
- 工程变更：草稿 → 评审 → 批准 → 发布 → 生效 → 失效。

### 接口

- PLM→MES：发布包 ID、型号、MBOM/工艺/固件版本、有效期、校验和、替代料规则。
- MES→PLM：可制造性问题、现场偏差、试制数据引用；正式工程变更仍在 PLM 闭环。
- 工单必须冻结使用的定义快照，不能因“当前最新版”改变历史或在制任务。

### 智能锁实际场景

A100 从主板 V2 切换到 V3，同时固件由 1.6.2 升级至 1.7.0。变更规定指定日期后的新工单生效，旧主板库存只能用于特批工单。MES 在派工时锁定硬件、MBOM、工艺和固件的兼容组合，烧录站不能自行选“最新固件”。

### Java 关注点

- 建立兼容矩阵，而非只比较单个版本字符串。
- 发布包按内容寻址或保存哈希，防止同版本号内容被替换。
- 生效日期、批次、序列号区间和工单特批可能同时构成适用条件。

## 9. 节点 05：MOM / MES

### 官方解释与释义

- [ISA 对 MOM/MES 的说明](https://www.isa.org/standards-and-publications/isa-publications/isa-books/authors-corner/a-q-a-with-the-co-authors-of-the-new-isa-book-manu)把 MOM 描述为支持制造运营的流程、数据结构和通信的整体能力，而 MES 是承载这些能力的主要信息系统之一。
- **通俗释义**：MOM 是 L3 的管理体系，MES 是常见落地系统。MES 回答“这张工单在现场如何被正确执行，实际发生了什么”。
- **不要混淆**：MOM 不等于某个菜单，MES 也不必把质量、维护、仓储所有功能都装在一个产品中。

### 四类运营与核心能力

| 运营 | 关键能力 | 智能锁例子 |
|---|---|---|
| 生产运营 | 详细排程、派工、执行、采集、跟踪、分析 | SN 生成、工序过站、关键件绑定 |
| 质量运营 | 检验执行、判定、隔离、处置和复验 | 功能测试 FAIL 后冻结整锁 |
| 库存运营 | 现场物料请求、移动、消耗和在制跟踪 | 主板批次上线、余料退库 |
| 维护运营 | 设备可用、保养、维修和恢复确认 | 扭矩枪校准过期禁止派工 |

### 关键状态

- 工单：创建 → 已发布 → 已下达 → 执行中 → 暂停 → 已完工 → 已关闭/取消。
- SN：创建 → 已上线 → 工序在制 → 合格/冻结/返工 → 已包装 → 已入库 → 已发货。
- 工序执行：待执行 → 已授权 → 执行中 → 结果未知 → 通过/失败 → 已确认/作废。
- 设备会话：已创建 → 已接受 → 运行中 → 待确认 → 完成/失败/取消。

### 上下游接口

- 接收 ERP 订单、PLM 发布定义、APS 计划、WMS 物料实物、QMS 质量规则、EAM 设备可用状态。
- 向设备侧发送业务上下文和批准参数引用。
- 返回 ERP 实绩、WMS 消耗/产出、QMS 不合格事实、EAM 故障线索和全链追溯。

### 智能锁实际场景

操作者扫描工单和整锁 SN。MES 校验工单已发布、当前工位是路线下一站、主板批次合格、固件版本兼容、测试台校准有效，然后创建测试会话。测试台完成后上传结果；MES 校验会话和参数规则后写入过站，同时将主板 SN、指纹模组 SN、固件哈希和整锁 SN 建立绑定。

### Java 关注点

- 聚合根与事务边界围绕工单、SN、工序执行和设备会话设计。
- 唯一约束和状态守卫必须在数据库层配合，不能只靠前端按钮。
- 超时是“结果未知”，先查询/重放同一会话，不能自动创建新会话。
- 关键动作写入操作者、原因、前后值、来源和关联证据。

## 10. 节点 06：APS

### 官方解释与释义

- [Siemens 对 APS 的说明](https://www.siemens.com/lt-lt/technology/advanced-planning-scheduling-aps/)强调利用高级算法和约束进行生产计划与排程。
- **通俗释义**：ERP 说“什么时候需要多少”，APS 计算“在哪条线、哪个班次、以什么顺序做，才能在产能、物料和换型约束下尽量兑现”。
- **边界**：APS 输出计划建议；MES 负责现场派工和实际执行反馈。

### 输入、约束与输出

- 输入：需求、BOM、工艺路线、标准工时、班次、设备/人员能力、物料可用、维护窗口、在制状态。
- 硬约束：设备不兼容、物料未到、安全资质不足、维护锁定。
- 软约束：减少颜色/型号切换、降低延期、均衡负荷、优先重点客户。
- 输出：计划版本、工单顺序、资源分配、开始/结束时间、约束冲突和迟交风险。

### 状态

草案 → 求解中 → 可行/部分可行 → 已发布 → 已冻结 → 重新排程 → 失效。

### 智能锁实际场景

A100 与 B200 共用固件烧录站和老化区。APS 发现 B200 的指纹模组晚到，同时 A100 有紧急订单，于是调整装配顺序并保留烧录能力；MES 接收已发布计划，现场设备故障后回传能力下降，APS 重新计算尚未冻结的部分。

### Java 关注点

- 计划版本不可原地覆盖；MES 执行记录引用明确版本。
- 区分建议时间、承诺时间和实际时间。
- 重排只影响未开始或允许调整的任务，不能改变已发生事实。

## 11. 节点 07：WMS

### 官方解释与释义

- [SAP 对 WMS 的说明](https://www.sap.com/products/scm/extended-warehouse-management/what-is-a-wms.html)将其描述为管理从物料进入仓库到移出的完整仓储运营的软件系统。
- **通俗释义**：ERP 管库存账，WMS 管“实物在哪个库位、由谁执行什么仓内任务、哪个批次实际移动了”。
- **边界**：MES 管线边投料和生产消耗事实；WMS 管仓库任务、库位和实物移动，双方通过交接点对账。

### 核心对象与状态

- 仓库、库区、库位、容器/LPN、物料、批次、序列号、质量状态。
- 任务：创建 → 已分配 → 执行中 → 已确认 → 已取消/异常。
- 库存：可用、待检、冻结、已分配、线边、在途。

### 接口

- MES→WMS：齐套需求、备料/补料/退料请求、成品交接请求。
- WMS→MES：实发批次、容器、数量、库位、任务状态。
- 投料扫描必须核对 WMS 实发事实、MES 工单需求和物料质量状态。

### 智能锁实际场景

WMS 按工单把主板批次 B240701 和指纹模组容器 LPN88 送到总装 1 线。MES 扫描容器并锁定可投料范围；实际绑定每个主板 SN 与整锁 SN。余料退库时，WMS 重新接管实物位置，MES 保留已消耗和未消耗数量证据。

### Java 关注点

- 移动、分配、消耗是不同业务事件，不能共用一个“库存状态”字段。
- 采用交接事务号和累计数量对账，处理部分发料、短发、替代料和退料。

## 12. 节点 08：QMS

### 官方解释与释义

- [ISO 对 QMS 的说明](https://www.iso.org/quality-management/what-is-qms)把质量管理体系解释为组织为满足客户和法规要求、持续改进质量而建立的过程和程序体系。
- **通俗释义**：QMS 不只是“检验录入页面”，而是标准、问题、原因、处置、纠正预防和改进的闭环；软件 QMS 是这一管理体系的数字承载。
- **边界**：MES 执行现场检验和门禁，QMS 管企业级质量规则、NCR/CAPA 和批准处置；企业也可能把部分能力合并。

### 核心对象与状态

- 检验规范、抽样方案、缺陷代码、限值版本、检验特性。
- NCR：发现 → 已登记 → 已隔离 → 评审中 → 返工/报废/让步/退货 → 复验 → 关闭。
- CAPA：问题定义 → 根因 → 措施 → 实施 → 效果验证 → 关闭。

### 智能锁实际场景

功能测试站连续出现电机电流偏高。MES 记录失败 SN 和原始曲线索引并触发批次冻结；QMS 建立 NCR，按主板批次和电机批次扩展影响范围，评审后决定返工。返工必须走批准路线，复验通过后才能解除冻结。

### Java 关注点

- 检验结果与质量处置分开建模；`PASS/FAIL` 不能表达让步接收。
- 限值和抽样规则按版本保存，历史结果按当时规则解释。
- 冻结是跨 MES/WMS/ERP 的业务锁，需要分布式状态与补偿对账。

## 13. 节点 09：EAM / CMMS

### 官方解释与释义

- [IBM 对 CMMS 的说明](https://www.ibm.com/think/topics/what-is-a-cmms)将其概括为用于集中维护信息、支持维护运营的软件；同时区分 EAM 覆盖更广的资产全生命周期管理。
- **通俗释义**：CMMS 关注“设备怎么保养维修”，EAM 还关注“资产从规划、采购、使用到退役如何管理”。
- **边界**：MES 需要知道设备此刻是否可用于生产；EAM/CMMS 管设备台账、保养工单、维修和备件。

### 核心对象与状态

- 资产、部件层级、位置、技术参数、保养策略、计量器具、备件。
- 维护工单：请求 → 评估 → 计划 → 执行 → 验证 → 关闭。
- 设备能力状态：可用、降级、维护锁定、故障、校准过期。

### 智能锁实际场景

扭矩枪累计锁付次数达到保养阈值，EAM 创建保养工单并将设备置为维护锁定；MES 停止向该设备派工。维修后必须完成校准和首件验证，EAM/质量释放能力状态，MES 才恢复生产。

### Java 关注点

- `RUNNING` 不等于“适合当前工艺”；能力还受校准、程序和工装限制。
- 设备事件可触发维护建议，但正式维护工单和资产履历由 EAM 主导。

## 14. 节点 10：SCADA

### 官方解释与释义

- [NIST SP 800-82 Rev.3](https://csrc.nist.gov/pubs/sp/800/82/r3/final)把 SCADA 纳入工业控制系统范畴，典型能力包括集中采集远端状态、向操作者展示、报警、趋势和监督控制。
- **通俗释义**：SCADA 是现场的“集中监视与监督台”，让操作人员知道整线发生了什么，并在受控范围内下达启停、模式切换或设定值。
- **边界**：SCADA 不拥有生产订单和整锁追溯主线；MES 不应代替 SCADA 做实时画面和控制联锁。

### 设计

- 点位模型：资产、点位、数据类型、工程单位、量程、质量码、采样/变化策略。
- 报警模型：条件、等级、延迟、抑制、确认、恢复、责任区域。
- 模式：自动、手动、维护、故障；模式切换要有权限和审计。
- 命令：只对允许的控制点开放，并需要当前状态、操作权限和控制器确认。
- 趋势：区分原始值、压缩值、聚合值和计算值。

### 智能锁实际场景

总装线 SCADA 显示各工位运行、堵料、故障和节拍趋势。班组长可确认报警并请求产线停止；急停与防护门互锁仍由安全回路执行。SCADA 将停机事件上送 MES，MES 关联当时工单和在制 SN，用于生产影响分析。

### Java 关注点

- 不通过数据库轮询代替工业实时采集。
- 点位值必须携带时间戳、质量码和来源；`0` 与“通信失败”不是一回事。
- 命令接口区分“已接收、控制器已确认、动作已完成、动作失败”。

## 15. 节点 11：HMI / Andon

### 官方解释与释义

- NIST 工业控制指南中的 HMI 指操作者观察过程状态并与控制系统交互的人机界面。
- **通俗释义**：HMI 是一台设备或一段产线的操作窗口；Andon 是让异常、停线、缺料、质量呼叫被及时看见并升级的可视化机制。
- **边界**：按钮不是权限。HMI 可以发起操作，但 PLC/安全系统仍需验证控制条件；Andon 事件也不能自动等同于设备故障。

### 页面与事件设计

- 首页只显示关键状态、当前模式、主要告警和安全状态，避免“仪表盘堆满点位”。
- 手动动作按设备单元分组，显示前置条件和拒绝原因。
- 报警必须可确认、可追溯、可抑制但不可无痕删除。
- Andon：创建 → 已受理 → 响应中 → 已恢复 → 已确认关闭。
- 记录呼叫类型、工位、工单、SN、开始/响应/恢复时间、响应人和原因。

### 智能锁实际场景

操作者在锁付站发现螺钉来料异常，通过 Andon 选择“物料质量”。系统通知班组与质量，记录首次响应时间。HMI 保持设备安全状态；MES 冻结受影响 SN，QMS 决定处置。异常关闭不能只按“复位”按钮，而要确认物理问题和业务影响均已处理。

### Java 关注点

- Web HMI 仅适用于非确定性业务操作；安全和实时控制不依赖浏览器。
- Andon 通知可重试，但事件本体只能创建一次；升级规则需要版本和静默策略。

## 16. 节点 12：Historian

### 官方解释与释义

- NIST OT 架构将数据历史库描述为收集过程信息、用于趋势分析和后续运营分析的组件。
- **通俗释义**：Historian 是为工业时间序列优化的“现场黑匣子”，保存温度、电流、扭矩、状态、报警等随时间变化的数据。
- **边界**：Historian 保存过程证据，MES 保存业务上下文和判定；两者通过资产、会话、SN 与时间窗口关联。

### 数据设计

- 每条样本至少有 `tag_id/value/source_timestamp/ingest_timestamp/quality`。
- 点位元数据保存单位、精度、量程、资产、采样策略和版本。
- 压缩/降采样规则必须可解释；质量关键曲线不应因普通压缩丢失峰值。
- 保留策略分级：原始高频、分钟聚合、事件片段、法规/质量关键数据。
- 时钟同步和漂移监控是追溯成立的前提。

### 智能锁实际场景

功能测试台以高频记录电机电流曲线。测试系统为会话 `TS-20260729-001` 保存原始文件，Historian 保存关键时序和索引，MES 保存整锁 SN、测试程序、阈值版本、PASS/FAIL、峰值摘要和原始证据 URI。售后异常时从 SN 反查当时曲线。

### Java 关注点

- 避免把百万级采样点写进 MES 关系表。
- 查询 API 对时间范围、点位数量和聚合精度设限。
- 原始证据 URI 需要访问控制、保留期限、哈希和不可抵赖审计。

## 17. 节点 13：边缘网关

### 官方解释与释义

- [OPC UA 官方规范](https://reference.opcfoundation.org/specs/OPC-10000-1/1)强调平台无关的信息模型、安全通信和互操作；NIST OT 指南则描述现场协议转换、数据汇聚和分区通信需求。
- **通俗释义**：边缘网关是设备世界与业务世界之间的“翻译、缓冲和边界代理”，不是把各种 TCP 报文转成 JSON 就结束。
- **边界**：网关可做协议、质量码、缓冲和标准化；工单是否合法、SN 能否过站仍由 MES 决定。

### 能力设计

- 南向：OPC UA、Modbus TCP/RTU、厂商 SDK、串口、文件、数据库等。
- 北向：OPC UA、MQTT、HTTPS/gRPC、消息总线。
- 点位与事件映射：原始地址 → 标准资产/属性/单位/质量。
- 存储转发：断网缓冲、序号、去重、限额、补传和磁盘水位告警。
- 设备影子只表达已知状态，不应伪造实时在线。
- 配置、证书、驱动和映射规则都需版本化、签名和回滚。

### 状态

未注册 → 已配置 → 已连接 → 降级/离线 → 补传中 → 正常；单设备连接状态与网关自身状态分开。

### 智能锁实际场景

旧扭矩枪只提供厂商串口协议，网关读取扭矩、角度、程序号和结果，补充设备 ID、时间质量、会话号后上送。网络中断时本地按序缓存；恢复后用原序号补传。MES 按会话幂等处理，不重复锁付记录。

### Java 关注点

- Java 适合网关管理面、适配服务和非硬实时协议；严格周期控制交给控制器或实时组件。
- 每个驱动做资源隔离和熔断，单台坏设备不能拖垮整站。
- 未识别的单位、质量码或映射版本应进入隔离队列，不能默认当成好数据。

## 18. 节点 14：PLC

### 官方解释与释义

- [IEC 61131-3](https://webstore.iec.ch/en/publication/68533)规定可编程控制器编程语言，包括结构化文本 ST、梯形图 LD、功能块图 FBD，并定义顺序功能图 SFC 的相关元素。
- **通俗释义**：PLC 是工业设备的大脑之一，按确定周期读取输入、执行控制逻辑、刷新输出，并处理顺序、联锁、报警和设备模式。
- **层级说明**：按 ISA 官方活动口径，PLC 常承载 L2 监视/监督/自动控制，也直接处理 L1 感知与操纵接口；不要只凭产品名机械归层。

### PLC 程序结构建议

- 输入映像与信号质量。
- 模式与状态机：停止、准备、自动、手动、故障、维护。
- 顺控步骤：等待上料 → 夹紧 → 执行 → 检查 → 松开 → 完成。
- 设备互锁和过程联锁。
- 报警、诊断和首次故障保留。
- MES/网关握手区：命令号、会话号、参数版本、接受/完成/错误和序号。
- 安全逻辑应使用符合风险要求的安全系统，不依赖普通业务通信。

### 典型握手

1. MES/网关写入命令 ID、SN、工序和已批准配方号。
2. PLC 校验当前模式、设备空闲、配方存在和本地条件。
3. PLC 回应 `ACCEPTED` 或明确拒绝码。
4. PLC 执行并持续更新步骤，不要求 MES 保持连接。
5. PLC 冻结完成结果，直到上位系统确认收到。
6. 超时后双方查询同一命令 ID，不生成第二个动作。

### 智能锁实际场景

整锁功能测试 PLC 控制夹具、电源、开关量和电机动作。MES 给出 SN 与测试方案 ID；PLC 校验方案存在后执行。即使 MES 短时断开，PLC 也能安全完成或停止，并保留结果。MES 恢复后读取同一会话结果。

### Java 关注点

- 不在 Java 中实现急停、门锁或毫秒级伺服闭环。
- 不频繁写 PLC 零散点位模拟业务事务；使用明确命令块和状态块。
- 地址变化应通过版本化标签映射隔离，不把寄存器地址散落在业务代码。

## 19. 节点 15：机器人与运动控制

### 官方解释与释义

- [ISO 10218-1:2025](https://www.iso.org/standard/73933.html)规定工业机器人本体设计的安全要求；机器人应用集成的安全要求由该系列第二部分覆盖。
- **通俗释义**：机器人控制器负责坐标、轨迹、速度、工具和动作程序；运动控制器负责多轴同步与定位。它们擅长“怎么精确地动”，MES 负责“为什么为哪个工单/SN 执行”。
- **边界**：MES 下发已批准程序引用或产品参数，不下发未经验证的临时轨迹。

### 核心对象

- 机器人/轴、工具中心点、工装、坐标系、程序、配方、速度限制。
- 程序状态：草稿 → 仿真验证 → 现场验证 → 批准 → 发布 → 退役。
- 执行状态：空闲 → 已装载 → 运行 → 暂停 → 完成/故障。

### 智能锁实际场景

机器人抓取前面板并放入夹具，伺服压合结构件。MES 下发产品型号和已发布配方 ID；机器人程序决定轨迹，PLC 协调夹具与安全。控制器返回实际程序、循环号和结果，MES 将其关联整锁 SN。

### Java 关注点

- 程序/配方发布与生产执行分开授权。
- 控制器完成不等于产品合格；还需质量测量与业务校验。
- 机器人安全区、协作速度和防护设计由风险评估与安全工程决定。

## 20. 节点 16：测试控制器 / 工业 PC

### 官方解释与释义

- 这是本文依据 NIST OT 架构形成的**教学节点**，不是 ISA-95 强制产品名称。
- **通俗释义**：复杂测试常需要工业 PC 或专用控制器调用电源、万用表、通信适配器、相机和夹具，把多个测量步骤编排成一次可追溯测试。
- **边界**：测试控制器拥有原始测量和执行日志；MES 拥有待测对象、业务授权与最终过站事实；QMS/工程拥有已发布判定规则。

### 测试配方

- `test_plan_id/version/hash`。
- 步骤、仪器、通道、激励、等待、采样、单位、限值、重试和失败策略。
- 软件版本、驱动版本、工装版本和仪器校准状态。
- 原始数据位置、摘要算法和结果签名。

### 会话状态

已创建 → 设备自检 → 已接受 → 执行中 → 待上传 → 已上传 → MES 已确认；异常进入结果未知、设备故障或产品失败，三者不可混淆。

### 智能锁实际场景

测试 IPC 通过 BLE/Zigbee/UART 与锁主板通信，控制电源和机械夹具，执行指纹、密码、电机、低电压和通信测试。某一步通信超时不能直接当成产品 FAIL；若仪器自检失败，应标记设备故障并隔离该会话。

### Java 关注点

- 会话必须记录计划、软件、驱动、仪器和校准快照。
- 测试步骤结果不可只存一段不可检索日志。
- 同一 SN 重测要创建新的 `attempt_no`，并保留重测授权和前次失败。

## 21. 节点 17：传感器、执行器与驱动

### 官方解释与释义

- ISA-95 的 L1 活动是感知和操纵生产过程；NIST 将传感器、执行器和控制设备作为 OT 与物理环境交互的基础。
- **通俗释义**：传感器把物理世界变成信号，执行器把控制命令变成物理动作，驱动器把目标转成电机可执行的电流、速度或位置控制。

### 设计清单

- 信号身份：资产、通道、类型、单位、量程、精度、刷新率。
- 状态质量：Good、Uncertain、Bad，以及断线、超量程、校准过期。
- 模拟量缩放和工程单位统一，禁止上层猜测 `32767` 的含义。
- 执行器默认状态、失气/失电行为、反馈确认和动作超时。
- 智能传感器的配置和固件也需资产与版本管理。

### 智能锁实际场景

光电传感器确认锁体到位，位移传感器确认压合行程，扭矩枪驱动器执行锁付并返回扭矩/角度，气缸推动夹具。若“夹紧输出为 1”但夹紧到位反馈未到，PLC 必须超时停机，而不是由 MES 继续放行。

### Java 关注点

- Java 通常消费标准化状态，不直接实现输入滤波与快速闭环。
- 单位、精度和质量码必须进入接口契约。
- 数据异常要区分真实过程异常、传感器故障和通信故障。

## 22. 节点 18：机器安全系统

### 官方解释与释义

- [IEC 62061:2021](https://webstore.iec.ch/en/publication/59927)规定机械安全相关控制系统的设计、集成与验证方法。
- **通俗释义**：机器安全系统的目标不是“设备不报错”，而是在人员进入危险区、急停、门锁断开或安全元件失效时，使风险降到可接受水平并达到定义的安全状态。
- **边界**：MES、普通 HMI、普通 PLC 或网络消息不能代替经过风险评估的安全功能。

### 安全生命周期

1. 界定机器和使用方式。
2. 识别危险并评估风险。
3. 定义安全功能和所需性能。
4. 设计安全回路、安全控制和机械/电气措施。
5. 验证与确认。
6. 管理变更、定检、旁路和失效。

### 智能锁实际场景

机器人单元防护门打开后，安全系统停止危险运动并防止意外重启。MES 只接收“安全停机”事件用于影响分析；不能通过接口远程屏蔽门锁。维修旁路必须受控、限时、可见并由规定岗位执行。

### Java 关注点

- 应用页面显示安全状态时必须标注来源和更新时间，不能给人“网页就是安全装置”的错觉。
- 安全事件可审计和分析，但业务系统不得成为安全动作成功的前置条件。

## 23. 节点 19：工业协议与信息语义

### 官方解释与释义

- [OPC UA](https://reference.opcfoundation.org/specs/OPC-10000-1/1)：平台无关、支持信息模型和安全通信，适合表达资产、属性、事件和方法。
- [MQTT 官方](https://mqtt.org/)：基于发布/订阅的轻量消息协议，适合受限环境和异步遥测，但主题名称本身不等于制造语义。
- [Modbus Organization](https://www.modbus.org/modbus-specifications)发布 Modbus 应用协议；其模型以功能码和寄存器/线圈访问为主，语义通常需要双方另行约定。
- [EtherCAT Technology Group](https://www.ethercat.org/en/technology.html)介绍 EtherCAT 面向高性能实时工业以太网和灵活拓扑。

### 不是“选一个协议走天下”

| 需求 | 适合的能力 | 注意事项 |
|---|---|---|
| 控制器与远程 I/O、伺服实时循环 | 工业实时以太网/现场总线 | 确定性、拓扑、诊断和安全能力优先 |
| PLC/SCADA/网关结构化互操作 | OPC UA | 建模、证书、权限、订阅和信息模型 |
| 网关向平台异步遥测 | MQTT | 主题、QoS、保留消息、会话和语义契约 |
| 简单仪表/旧设备寄存器读取 | Modbus | 地址、字节序、缩放、单位、轮询和异常码 |
| MES 与业务系统 | HTTPS/gRPC/消息总线 | 业务幂等、版本、事务、审计和补偿 |

### 契约的最低字段

`message_id/event_id`、`schema_version`、`source`、`equipment_id`、`session_id`、`sequence`、`occurred_at`、`received_at`、`quality`、`payload`、`trace_id`。

协议只解决传输的一部分。真正可用还要定义：

- 资产与点位命名。
- 数据类型、单位、量程和精度。
- 状态与错误码。
- 顺序、重复、补传和超时语义。
- 身份、授权、加密、证书更新。
- 版本兼容和退役策略。

### 智能锁实际场景

扭矩枪用 Modbus 暴露寄存器，网关转换为带单位和质量码的标准事件，再用 MQTT 上送；新测试台直接提供 OPC UA 信息模型；MES 通过 HTTPS 创建业务会话。三种协议可以共存，但都必须关联同一个设备、会话和 SN。

### Java 关注点

- `QoS 1` 代表至少一次传递，不代表业务只执行一次；消费端仍要幂等。
- OPC UA `Bad` 质量值不能当默认数值。
- Modbus 多寄存器数值注意字节序、字序、无符号和原子快照。

## 24. 节点 20：智能锁示范线

### 24.1 从销售到物理动作

| 八阶段 | L4/L3 业务动作 | 现场动作 | 形成的证据 |
|---|---|---|---|
| 销售需求 | ERP 创建销售与生产需求 | 无 | 订单、型号、数量、交期 |
| 产品与工艺准备 | PLM 发布 MBOM、路线、固件与测试规范 | 工程验证程序和工装 | 发布包、版本、哈希、有效期 |
| 计划排产 | APS 计算产线/班次，MES 发布工单 | 设备能力检查 | 计划版本、资源分配、约束 |
| 物料齐套 | WMS 配送批次，MES 接收线边实物 | 容器/批次扫码 | 实发批次、LPN、数量、质量状态 |
| 生产执行 | MES 派工、授权、绑定、过站 | PLC/机器人/工具执行装配和烧录 | 会话、程序、参数、关键件绑定 |
| 质量管控 | MES 执行门禁，QMS 处置异常 | 测试 IPC/仪器采样 | 结果、限值版本、原始曲线、NCR |
| 成品入库 | MES 完工并与 WMS 交接 | 打印标签、扫码装箱 | SN—箱码—托盘、入库任务 |
| 发货与追溯 | ERP/WMS 发货，MES 提供谱系 | 扫描出库 | 客户/订单/物流与 SN 去向 |

### 24.2 一次功能测试的跨层时序

1. **L4/L3 准备**：ERP 订单与 PLM 发布包已同步；MES 工单锁定型号、硬件、固件、工艺和测试计划。
2. **L3 门禁**：操作者扫码 SN；MES 校验路线、批次、人员资格、设备能力、校准和冻结状态。
3. **L3→L2 授权**：MES 创建唯一会话，发送 SN、工序、测试计划 ID、版本和哈希。
4. **L2 接受**：测试 IPC/PLC 校验模式、夹具和本地计划，返回接受或拒绝码。
5. **L1/L0 执行**：传感器确认到位，执行器夹紧，仪器激励并采样，控制器保证顺序与安全。
6. **L2 取证**：控制器保存步骤、软件版本、仪器、原始数据、报警和本地结果。
7. **L2→L3 上传**：网关以会话 ID 与序号可靠上传摘要、结果和原始证据地址。
8. **L3 判定**：MES 验证版本、完整性和幂等，形成通过、失败或结果未知；QMS 处理质量异常。
9. **L3→L4 回馈**：累计实绩、报废和完工回 ERP；详细 SN 证据保留在制造体系。

### 24.3 必须设计的失败场景

| 失败 | 正确语义 | 恢复原则 |
|---|---|---|
| MES 请求超时 | 不知道设备是否已执行 | 用原命令 ID 查询，不新建动作 |
| 设备完成但上送失败 | 本地已完成、平台未确认 | 冻结结果并按序补传 |
| 测试 FAIL | 产品不符合判定规则 | 冻结 SN，进入质量/返工流程 |
| 仪器故障 | 测试无效，不代表产品 FAIL | 隔离会话和受影响范围，维修后重测 |
| PLC 程序版本错误 | 过程合规性未知 | 停止派工，评估已生产 SN |
| 错批次上线 | 物料谱系风险 | 阻断投料，按扫描和时间窗追溯 |
| 网络区间中断 | 控制层继续安全自治 | 按离线策略生产或安全停机，恢复后对账 |
| 时钟漂移 | 事件顺序不可信 | 标记时间质量，校时并人工评估 |

### 24.4 整锁 SN 的最小追溯图

```text
销售订单
  └─ 生产订单 / 工单
      ├─ 型号 + MBOM + 工艺路线 + 发布包
      ├─ 主板批次 / 主板 SN
      ├─ 指纹模组批次 / 模组 SN
      ├─ 电机批次、锁体批次、包装批次
      └─ 整锁 SN
          ├─ 工序执行（人、线、工位、设备、时间）
          ├─ 固件版本 + 哈希 + 烧录会话
          ├─ 扭矩/装配/功能测试会话 + 原始证据
          ├─ NCR / 返工 / 复验 / 放行
          └─ 箱码 → 托盘 → 入库 → 发货单 → 客户去向
```

## 25. Java 服务边界建议

| 服务 | 主要聚合 | 不应承担 |
|---|---|---|
| 主数据/发布包服务 | 产品制造定义快照、版本和适用性 | 替代 PLM 审批 |
| 工单与派工服务 | 工单、任务、资源分配和状态 | 求解复杂 APS 约束 |
| SN/WIP 服务 | SN、路线位置、冻结和返工 | 保存全部高频测点 |
| 物料谱系服务 | 批次、关键件绑定、消耗和拆换 | 替代 WMS 库位账 |
| 设备会话服务 | 命令、会话、序号、结果和未知态 | 毫秒级控制和安全互锁 |
| 质量执行服务 | 检验任务、结果、门禁和处置引用 | 无授权修改质量标准 |
| 追溯查询服务 | 跨对象图查询、证据定位和召回范围 | 改写来源事实 |
| 集成服务 | 契约、幂等、重试、对账和死信 | 用共享库直接跨系统写表 |

### 通用实现规则

- 事件入站唯一键：`source + event_id`；业务动作唯一键另行定义。
- 状态变更采用期望版本或数据库锁，拒绝迟到事件回退终态。
- 外部调用与本地事务使用 outbox/inbox、补偿和对账，不假装分布式 ACID。
- 命令、事件、当前状态、原始证据分开保存。
- 全链路 `trace_id` 不能替代业务键；SN、会话和工单仍须显式字段。
- 可观测性至少包含延迟、失败、重试、积压、重复、时钟偏差、设备离线和磁盘水位。

## 26. 现场调研清单

以下均为“待确认”，不能从行业通用模型推断为企业事实：

1. ERP、PLM、APS、MES、WMS、QMS、EAM、SCADA、Historian 和网关的实际产品与部署边界。
2. 工厂、车间、产线、工位、设备和资产编码规则。
3. PLC、机器人、测试 IPC、仪器、扫码器、打印机的品牌、协议和程序责任人。
4. 哪些参数由 PLM/工艺批准，哪些允许班组调整，哪些禁止远程修改。
5. 工厂断网、MES 宕机、网关磁盘满、设备换机时的生产策略。
6. 原始曲线、图像、日志和视频的保存位置、期限、访问权限与删除规则。
7. OT 网络区域、工业 DMZ、远程维护、账户、证书和补丁流程。
8. 校准、首件、巡检、放行、返工和让步接收的真实职责。
9. 主板/模组/电机是否逐件追溯，哪些物料只追批次。
10. 程序与固件发布、回滚、签名和已生产影响评估规则。

## 27. 学习自测

1. 为什么“ERP—MES—SCADA—PLC—传感器”是入门图，而不是完整标准定义？
2. PLC 已返回 PASS，MES 还要验证哪些条件？
3. SCADA 报警、Andon 呼叫、设备故障和质量不合格有何区别？
4. Historian 与 MES 分别保存什么，如何通过会话关联？
5. MQTT QoS 1 为什么不能保证业务不重复？
6. MES 超时后为什么不能直接重新发一个新命令？
7. 机器人控制器完成轨迹为什么不等于整锁质量合格？
8. 为什么安全 PLC 与 MES 之间不应存在“MES 在线才安全”的依赖？
9. 工程变更生效时，如何保护旧工单和在制 SN 的版本一致性？
10. 如何从客户投诉的一把锁反查主板、固件、工位、设备程序、测试曲线和发货去向？
