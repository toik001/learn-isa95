# 智能锁离散制造 MES 八阶段领域知识地图

## 使用范围与事实边界

本文面向 Java 全栈开发者，描述智能锁离散制造与销售场景下，MES 如何承接从销售需求到发货与追溯的端到端数字线程。文中的流程、单据、字段、状态和职责划分是**行业通用参考模型**；“某型号智能锁”“某工厂”“审批角色”等内容均是教学示例或显式行业假设，不代表任何特定公司已经采用。实际项目必须通过业务访谈、现场走查、系统接口清单和主数据字典确认差异，未确认项应登记为“待确认”，不能直接固化进代码。

学习时始终用四层视角交叉检查：

- **业务层**：谁在什么条件下完成什么动作，异常由谁闭环。
- **数据层**：动作产生什么单据、状态和关联键，数据由谁维护。
- **系统层**：ERP、PLM、MES、WMS、QMS 和设备系统分别拥有哪类事实。
- **实现层**：状态机、幂等、并发、事务、权限、审计和追溯怎样落到 Java 服务。

## 端到端总览

| 阶段 | 核心问题 | 典型输入 | 关键输出与完成标志 | 主要系统 |
| --- | --- | --- | --- | --- |
| 1. 销售需求 | 要什么、要多少、何时交 | 预测、客户需求、产品配置 | 已评审销售订单、可承诺交期 | CRM/ERP，MES 提供能力反馈 |
| 2. 产品与工艺准备 | 产品能否按受控版本制造 | 产品定义、设计变更 | 已发布 MBOM、工艺路线、检验与烧录参数 | PLM/ERP/MES/QMS |
| 3. 计划排产 | 何时、在哪条线、生产多少 | 需求、库存、BOM、产能 | 已下达生产工单与工序计划 | ERP/APS/MES |
| 4. 物料齐套 | 工单所需物料是否可用且可追溯 | 工单需求、库存批次 | 已配送/已领料的合格物料 | ERP/WMS/MES/QMS |
| 5. 生产执行 | 人、机、料、法是否按要求完成装配 | 工单、物料、工艺版本 | 完工数量、过站记录、关键件与整锁 SN 绑定 | MES/设备系统 |
| 6. 质量管控 | 产品和过程是否满足质量标准 | 检验方案、采集与抽样数据 | 合格放行或不合格闭环 | QMS/MES/设备系统 |
| 7. 成品入库 | 完工实物如何包装并形成可用库存 | 合格整锁、包装要求 | SN—箱码绑定、成品入库单、库位库存 | MES/WMS/ERP |
| 8. 发货与追溯 | 发给谁、发了哪些序列号、问题如何定位 | 发货通知、库存、客户订单 | 出库交付记录、正反向追溯与召回闭环 | ERP/WMS/MES/QMS/售后系统 |

八个阶段不是八个信息孤岛。销售订单的产品、数量和交期驱动计划；产品版本决定 EBOM、MBOM、工艺路线、检验方案和固件版本；生产工单消耗指定物料批次；工序过站把主板、指纹模组等关键件绑定到整锁 SN；测试结果决定质量状态；整锁 SN 与包装箱码、成品入库、发货客户继续关联，最终支持从客户故障向前查制造过程，也支持从缺陷物料批次向后找受影响产品和客户。

## 系统职责与数据归属

| 系统 | 典型主责数据 | 与 MES 的主要交互 | 边界提醒 |
| --- | --- | --- | --- |
| CRM/订单前台 | 商机、报价、客户需求、渠道信息 | 向 ERP 形成可执行订单或需求 | 不应直接修改生产工单或过站记录 |
| ERP | 客户、销售订单、组织、物料、采购、库存财务账、MPS/MRP、生产订单 | 下发需求与工单；接收领退料、完工、入库等业务结果 | ERP 是经营与账务主线，MES 不自行创造财务库存 |
| PLM | 产品型号、图纸、EBOM、设计版本、工程变更 | 向 ERP/MES 发布受控产品定义 | 未发布或失效版本不得被 MES 默认为可生产 |
| APS | 有限产能排程、资源日历、换线优化 | 读取需求/工单/产能，向 MES 下发工序计划 | 没有 APS 时可由 ERP/MES 简化承接，但数据所有权要明确 |
| MES | 生产工单执行、派工、工序过站、在制品、SN、装配绑定、电子作业指导、采集记录 | 接收计划和受控版本，反馈执行实绩 | MES 记录现场事实，不替代 PLM 的设计审批和 ERP 的结算 |
| WMS | 仓库、库位、容器、库存批次、拣配和搬运任务 | 接收备料/入库/出库请求，反馈实物移动结果 | 线边仓由 WMS 或 MES 管理必须单一口径 |
| QMS | 检验标准、抽样方案、不合格、评审、CAPA | 下发检验要求，接收结果并回传处置结论 | 简单检验可在 MES 执行，企业级质量闭环仍需明确主系统 |
| 设备/SCADA/烧录平台 | 设备参数、原始测点、程序日志、报警 | 向 MES 回传工位执行与测试结果 | 高频原始数据可保留在时序库，MES 保存业务判定和索引 |

这里的“主责”不是“只有该系统能保存”。同一字段可被多系统复制用于执行或查询，但只能有一个权威来源；副本需要携带来源系统、来源版本和同步时间，不能通过双向任意编辑制造多个真相。

## 智能锁数字线程

可将端到端关系理解为一条以版本和标识为连接点的有向链：

```text
需求预测/销售订单行
  → 产品型号 + 销售配置 + 需求日期
  → PLM 产品版本 → EBOM
  → ERP/MES 制造版本 → MBOM + 工艺路线 + 检验方案 + 固件版本
  → MPS/MRP → 生产计划 → 生产工单
  → 工单用料需求 → 物料批次/供应商批次 → 领料与线边库存
  → 工序过站 → 主板 SN/指纹模组 SN/锁体批次等关键件绑定
  → 烧录记录 + 测试记录 → 整锁 SN
  → 包装箱码 → 成品入库单/库位
  → 销售出库单 → 客户/渠道/交付时间
  → 售后故障、不合格、召回与改进
```

最小可用关联键通常包括：销售订单号与行号、产品编码与版本、EBOM/MBOM 版本、工艺路线版本、生产工单号、工序与工位、物料编码与物料批次、供应商批次、关键件 SN、整锁 SN、固件版本、测试记录号、包装箱码、入库单号、出库单号和客户/渠道标识。跨系统接口应同时传业务键和来源系统唯一 ID；业务键用于人理解与对账，来源 ID 用于防重和稳定关联。

## 横贯八阶段的控制原则

1. **版本受控**：工单一经下达，应冻结或快照所用 MBOM、工艺路线、作业参数、检验方案和固件版本。后续工程变更不能悄悄改变已开工产品的制造依据。
2. **状态有守卫条件**：状态不是页面标签。每次迁移都要验证角色、前置状态、版本、数量、质量和实物条件，并写入操作者、时间、原因与关联凭证。
3. **接口可重放**：ERP、MES、WMS、QMS 和设备消息会超时、重复、乱序。消费者需以来源事件 ID 或“来源单号+业务动作+版本”幂等，并保留重试、死信和人工补偿入口。
4. **账、卡、物一致**：系统库存账、批次/SN 追溯卡和现场实物要可对账。任何手工调整必须有权限、原因、审批和审计日志。
5. **追溯不可覆盖**：错误数据通过冲销、撤销、补录或新版本修正，不直接覆盖历史。追溯查询应能解释“当时使用了什么”和“后来如何处置”。

## 1. 销售需求

### 业务目标

本阶段把市场预测和客户订单转换成可评审、可承诺、可变更控制的制造需求。起点可能是滚动预测、渠道补货、项目订单或客户定制请求；完成标志是销售订单及其配置、数量、交期、优先级和变更基线已经确认，ATP（可承诺库存）或 CTP（可承诺能力）给出有依据的答复。MES 在此阶段通常不是订单主系统，但必须向上游提供在制、产能损失、预计完工和质量隔离等事实，避免交期承诺只看 ERP 账面库存。

### 触发与前置

- 触发包括预测周期到期、客户下单、渠道安全库存跌破阈值、促销计划或销售订单变更。
- 前置主数据至少有客户/渠道、销售组织、产品型号、销售配置规则、计量单位、交付地点和有效价格/合同条件。
- 可制造性评审需要已知产品版本或明确“待工程确认”的临时配置；需要 ATP 的库存状态定义、需要 CTP 的产能日历和关键物料供给口径也必须先统一。
- 对颜色、开门方向、通信制式、面板材质、锁体规格等智能锁选项，必须区分销售选项与制造物料，不能让销售自由文本直接驱动生产。

### 参与岗位

销售/渠道运营录入需求并沟通客户；订单运营检查合同、配置和交付条件；计划员评估产能与物料；产品/工艺工程师判断特殊配置是否可制造；采购提供长周期物料信息；仓储和质量提供可用库存、冻结库存等口径；必要时财务或管理者审批价格、信用和插单。系统职责上，CRM/ERP 保存商业承诺，MES 只反馈执行能力与制造风险。

### 业务步骤

1. 汇总预测和确定订单，按产品族、区域、渠道和需求日期去重，保留预测被订单冲减的规则。
2. 对订单行进行产品配置校验，将销售选项映射为受控产品型号、配置代码或待评审特征。
3. 执行 ATP：按现有合格库存、已分配库存、预计入库和安全库存计算可用量；不足时执行 CTP，结合工单负荷、瓶颈产能、物料到料和换线窗口给出可行日期。
4. 由计划、工程、采购、质量等角色评审异常配置、超量需求、急单和特殊检验/包装要求。
5. 将承诺日期、拆批交付方案和风险说明回写销售订单；确认后的订单进入计划需求池。
6. 订单取消、数量/配置/交期变化时创建变更版本，识别对采购、排产、已领料和在制品的影响，再决定接受、部分接受或拒绝。

### 关键单据与字段

| 单据/对象 | 关键字段 | 说明 |
| --- | --- | --- |
| 需求预测 | 预测版本、产品族/型号、周期、数量、渠道、置信度 | 版本化保存，避免覆盖历史预测 |
| 销售订单/订单行 | 订单号、行号、客户、产品编码、配置代码、数量、需求日期、承诺日期、优先级 | 订单行是后续需求追踪的基本粒度 |
| ATP/CTP 评审记录 | 评审号、可用库存、预计入库、瓶颈资源、物料到料日、建议交期、风险 | 记录计算快照和人工调整原因 |
| 订单变更单 | 原版本、新版本、变更类型、差异字段、生效时间、影响对象、审批结论 | 关联受影响计划与工单 |

订单数量要区分订购、已承诺、已分配、已发货和取消数量；日期要区分客户要求日期、计划承诺日期和实际发货日期；配置字段应引用有效代码及版本，不能只有描述文本。

### 状态流转

销售订单行的参考状态机为：

```text
草稿 → 待配置校验 → 待供给评审 → 已承诺 → 已释放计划
  ├─评审不通过→ 已拒绝
  ├─客户取消→ 已取消
  └─发生变更→ 变更评审中 → 已承诺/部分接受/已取消
```

“已承诺”守卫条件包括配置有效、数量和日期完整、信用/合同条件满足及 ATP/CTP 有结论；“已释放计划”后不能直接改原订单行，必须走变更单并评估下游影响。状态迁移应记录操作者、时间、来源、原因和版本号。

### 数据关系

一个销售订单包含多行，一行可拆成多个交付批次，也可生成多个计划需求和生产工单；多个订单行也可能由同一标准工单合并供给，但必须通过需求分配表保留“工单数量分配给哪个订单行”的关系。销售配置映射到产品版本、选配特征或配置 BOM；承诺记录引用当时的库存、计划和产能快照。订单变更通过影响关系连接未下达计划、已下达工单、采购申请、已领物料和在制整锁，便于判断沉没成本。

### 系统边界

CRM/ERP 拥有客户、合同、销售订单与承诺日期；ERP/APS 负责 ATP/CTP 的经营口径和需求计划；PLM 拥有可销售/可制造配置规则的工程来源；MES 提供工单进度、在制数量、设备停机和预计完工等现场事实。MES 不应自行修改客户交期，ERP 也不应把账面“在制”当作已通过质量放行的成品。接口通常是 ERP 向 MES 下发已批准需求关联或工单，MES 向 ERP/APS 回传进度和风险事件。

### 智能锁案例

**行业假设示例**：某渠道订购 2,000 套“深灰色、右开、支持 Zigbee”的智能锁，要求分两周交付。ERP 的 ATP 发现首周只有 600 套同配置合格库存；CTP 根据主板到料、喷涂颜色批次和总装线换线能力，建议首周交付 600 套，次周生产 1,400 套。配置校验同时确认 Zigbee 主板需匹配指定固件分支。销售接受拆批交付后，订单行保留两个交付计划，后续工单仍能追溯到同一订单行和配置版本。该示例用于说明方法，不代表企业真实产品或规则。

### 异常分支

典型异常是客户在工单已下达后把 Zigbee 改成 Wi-Fi。闭环应为：销售提交订单变更单 → 系统冻结原需求的继续释放 → 计划识别未开工、已领料、已装配三类数量 → 工程验证主板、固件、标签和认证差异 → 仓储核对可退/可转用物料 → 评审成本与新交期 → 批准后取消或重建对应工单并释放新版本 → 对已产生实物执行退料、返工或另单消耗 → ERP 和 MES 对账 → 销售回告客户并关闭变更。任何一步失败都保留责任人、截止时间和处置证据，不能只把订单字段直接改掉。

### 关键指标

- 订单准时承诺率 = 在目标响应时间内完成承诺的订单行数 / 待承诺订单行数。
- 承诺达成率 = 按承诺日期与数量交付的订单行数 / 已到期承诺订单行数。
- 预测准确率，可按产品族和周期比较预测与实际订单，需明确 MAPE 或偏差口径。
- 订单变更率与变更后受影响在制数量，用于识别前端需求稳定性。
- ATP/CTP 人工改期比例，用于发现主数据或能力模型不可信。

### 常见误区

1. 把销售订单等同于生产工单，忽略库存供货、合并生产、拆批交付和需求分配。
2. 只计算账面库存，不区分合格、冻结、待检、已分配和在途状态，导致虚假 ATP。
3. 将颜色、通信制式等配置写成自由文本，直到车间才发现没有对应 MBOM 或固件。
4. 直接覆盖订单日期和数量，不保存变更版本，也不分析已采购、已领料和在制影响。

### Java 全栈开发关注点

- **配置与状态校验**：用领域服务验证产品配置、日期和数量；状态迁移通过显式命令处理，不允许通用 CRUD 绕过守卫条件。数据库使用版本号实现乐观锁，避免销售和计划同时改写承诺。
- **幂等接口**：订单创建/变更事件以来源系统、订单 ID、行 ID 和变更版本组成幂等键；重复消息返回已有处理结果，乱序旧版本进入告警而不是覆盖新版本。
- **可解释计算**：ATP/CTP 结果不仅返回日期，还保存输入快照、规则版本和人工调整原因，前端能够展开“为什么承诺这个日期”。
- **权限与审计**：销售可提交变更但不能代替计划批准产能；特殊插单、承诺提前等敏感动作需分权并记录审计事件。
- **时间语义**：区分业务日期、工厂时区时间和事件时间；跨时区客户交期必须在接口契约中明确。

### 阶段自测

1. 为什么一个销售订单行可能关联多个生产工单，一个生产工单也可能服务多个订单行？应如何保存分配关系？
2. 当客户在工单开工后改变通信制式时，哪些数据和实物必须纳入影响分析，为什么不能直接修改订单？
3. ATP 与 CTP 的输入有何差异？MES 应向上游提供哪些现场事实才能让承诺更可信？

## 2. 产品与工艺准备

### 业务目标

本阶段把“设计上是什么”转换成“现场按什么版本、顺序、参数和质量标准制造”。其完成标志不是图纸已经存在，而是目标产品版本对应的 EBOM、MBOM、工艺路线、工位参数、作业指导、检验方案和固件版本均已批准、已发布、相互兼容，并能被生产工单冻结引用。该阶段建立后续可追溯性的技术基线：同一个整锁 SN 必须能回答当时用了哪个产品版本、哪些物料替代规则、哪版工艺与固件。

### 触发与前置

- 新产品导入、量产版本发布、工程变更、供应商/物料替换、质量改进或设备升级都会触发准备。
- 前置包括物料编码、单位、图纸/规范、工作中心与工位、设备能力、人员技能分类等主数据。
- 需要明确 PLM 中 EBOM 的发布状态，以及 ERP/MES 侧 MBOM、工艺路线和检验方案的转换责任人。
- 固件须具备唯一版本、适用硬件范围、校验值、签名/发布状态和烧录包存储位置；试制版本与量产版本必须可区分。

### 参与岗位

研发工程师维护产品设计和固件；结构/电子工程师维护 EBOM；工艺工程师完成 MBOM、工序、工时和工位参数；质量工程师制定检验特性、抽样与判定规则；设备工程师验证烧录器、测试台和工装；主数据管理员保证编码一致；生产代表参与可制造性评审；信息化团队维护 PLM—ERP—MES—QMS 接口。发布与审核应职责分离，避免同一人无审查地创建并生效量产版本。

### 业务步骤

1. 在 PLM 建立产品型号与设计版本，维护 EBOM，关联图纸、技术规范和工程变更。
2. 工艺工程师进行 EBOM 到 MBOM 的转换：按装配层级调整虚拟件、工序投料点、损耗和替代组，保留来源对应关系。
3. 定义工艺路线，包括工序顺序、可选/返工路径、工作中心、标准工时、前后置条件和关键质量点。
4. 为工位配置作业指导、工具/夹具、设备程序、采集项、参数上下限、防错规则和人员资质要求。
5. 质量工程师发布 IQC/IPQC/FQC/OQC 所需检验方案，定义特性、抽样、判定、缺陷代码和处置入口。
6. 将主板硬件版本、通信模组和产品配置映射到允许的固件版本，验证烧录、回读和签名校验流程。
7. 执行试制和可制造性验证；问题关闭后，由授权角色发布制造基线，并同步 ERP/MES/QMS。
8. 工程变更时选择立即生效、按日期/批次/工单生效或旧料耗尽后生效，显式评估在制品和已下达工单。

### 关键单据与字段

| 单据/对象 | 关键字段 | 说明 |
| --- | --- | --- |
| 产品版本 | 产品编码、版本、生命周期状态、生效/失效时间、配置范围 | 产品编码不替代版本 |
| EBOM | 父件版本、子件编码/版本、用量、位号、替代说明、工程变更号 | 描述设计组成 |
| MBOM | 制造版本、工序投料点、用量、损耗率、替代组、来源 EBOM 行 | 描述实际制造用料 |
| 工艺路线 | 路线版本、工序号、顺序、工作中心、标准工时、控制码 | 支持主路线与返工路线 |
| 工位参数 | 参数编码、目标/上下限、单位、采集方式、设备程序版本 | 需与工序和产品版本关联 |
| 检验方案 | 检验阶段、特性、方法、抽样规则、判定规则、缺陷代码 | QMS 主责或 MES 执行副本 |
| 固件发布单 | 固件版本、适用硬件、文件摘要、签名、发布状态、回滚版本 | 二进制不可只靠文件名识别 |
| 工程变更单 | 变更号、原因、差异、生效策略、受影响对象、验证和审批 | 贯穿设计与制造版本 |

### 状态流转

制造基线可使用以下参考状态机：

```text
草稿 → 评审中 → 待试制 → 已验证 → 已发布 → 已冻结/已失效
          └─不通过→ 退回修改
已发布 ─工程变更→ 新草稿版本（旧版本继续按生效策略受控）
```

“已发布”的守卫条件至少包括 EBOM—MBOM 转换校验通过、路线有效、关键工位参数和检验方案齐全、固件兼容性验证完成、审批完整。已被工单引用的版本不可物理删除或原地改写；“失效”只禁止新工单引用，不影响历史追溯。

### 数据关系

产品型号有多个产品版本；每个产品版本关联一版或多版 EBOM，EBOM 行通过转换映射到 MBOM 行。MBOM 物料行指定投料工序，工艺路线的工序再关联工位参数、作业指导、设备程序和检验特性。硬件版本、通信模组与固件版本是多条件兼容关系，不宜仅在产品表放一个 `firmware_version`。工程变更引用旧/新版本和影响对象；生产工单保存制造基线快照 ID，使后来打开文档仍能还原“当时批准的内容”。

### 系统边界

PLM 权威管理产品定义、图纸、EBOM 和工程变更来源；ERP 管理物料经营主数据及通常的制造 BOM/生产版本；MES 消费已发布 MBOM 与工艺路线，管理现场可执行的工位参数、作业指导呈现和版本快照；QMS 主责检验标准与不合格分类；烧录平台或制品库保存固件二进制和签名。任何跨系统转换都要保存来源 ID 与版本，不能把 MES 内临时修正伪装成 PLM 已批准设计。紧急临时偏离应有单独偏离许可、适用范围和到期时间。

### 智能锁案例

**行业假设示例**：某智能锁 V2 产品由锁体、前后面板、主板、指纹模组、电机、电池组件、结构件和包装材料组成。EBOM 表达设计层级，MBOM 将螺钉包并入“面板预装”工序，把主板和指纹模组安排在“电子装配”投料，并将标签和说明书安排到“包装”工序。硬件为主板 HW-B 时允许固件 `2.3.x`，但 HW-A 只能使用 `2.1.x`。工单下达时冻结 MBOM-R05、路线-R03、检验方案-Q07 和固件 `2.3.4`；后续 `2.3.5` 发布不会自动改变已经开工的整锁。

### 异常分支

典型异常是新主板已到线边，但 MES 找不到与产品配置兼容的已发布固件。闭环为：工位防错阻止烧录和过站 → 操作者创建技术异常并隔离对应物料批次/在制品 → 工艺与研发核对主板硬件版本、MBOM 替代关系和固件发布状态 → 若是同步失败，修复接口并以原版本重放；若确需新固件，走构建、测试、签名和发布审批 → 质量决定已尝试烧录品的复验范围 → MES 更新允许关系但不覆盖历史 → 受影响 SN 重新烧录、回读校验和复验 → 记录问题原因与防再发措施后解锁工位并关闭技术异常。不得通过前端临时输入任意文件路径绕过发布。

### 关键指标

- 制造基线一次发布通过率 = 无退回完成发布的基线数 / 提交评审基线数。
- EBOM—MBOM 转换差异关闭周期，按变更提交到所有差异有结论的时间统计。
- 工艺/版本原因停线时长，反映准备质量对现场的影响。
- 工程变更按期落地率，以及发生在已开工工单上的紧急变更比例。
- 固件错版拦截次数和烧录首次成功率，需区分工艺防错价值与真实缺陷趋势。

### 常见误区

1. 认为 EBOM 与 MBOM 只是字段名不同，忽略制造层级、投料点、损耗和替代关系。
2. 路线只存工序名称，不保存版本、顺序、工位能力、参数和返工路径，导致无法执行。
3. 用固件文件名当版本标识，没有哈希、签名、硬件兼容和发布状态。
4. 工程变更直接更新公共 BOM，使已下达工单历史依据随之变化，追溯失真。

### Java 全栈开发关注点

- **不可变版本模型**：已发布实体采用新版本变更而非原地更新；工单引用快照或不可变版本 ID。数据库唯一约束覆盖“对象+版本”，API 的 ETag/版本号防止并发覆盖。
- **转换与一致性校验**：EBOM—MBOM 转换要检查遗漏、重复、单位换算、用量和有效期；大对象发布可采用事务内落库加事务外 Outbox 事件，避免数据库成功而消息丢失。
- **固件安全**：制品使用内容哈希、数字签名和只读存储；下载采用短期授权，工位上报实际摘要，服务端验证适用硬件和发布状态。
- **缓存失效**：工位为低延迟会缓存路线和参数，发布/失效事件必须带版本并可重放；离线缓存要有过期与安全降级策略。
- **差异可视化**：前端展示旧/新 BOM、路线、参数逐项差异和影响工单，避免审批者只看到“版本号变了”。

### 阶段自测

1. EBOM 转 MBOM 时为什么必须保存行级来源关系？工序投料点和虚拟件如何改变制造表达？
2. 已发布工艺路线被工单引用后发生工程变更，数据模型如何同时支持新工单生效和旧工单追溯？
3. 防止主板烧错固件至少需要哪些版本、兼容、签名和工位校验信息？

## 3. 计划排产

### 业务目标

本阶段把已确认需求转换成时间、数量、产线和优先级明确的可执行计划。它综合 MPS/MRP 输入、现有库存、在制、物料到料、人员/设备产能、换线和维护约束，决定生产工单如何拆分、何时冻结、何时下达。完成标志是工单拥有受控产品/工艺版本、计划数量、计划起止、工作中心与需求来源，并通过物料和产能基本校验进入 MES 待执行队列；计划员还能解释排程选择和变更影响。

### 触发与前置

- 销售订单、预测补库、安全库存、返工补产或售后备件需求触发 MPS/MRP 与排程。
- 前置为有效物料/产品版本、MBOM、工艺路线、库存与在制快照、采购/委外到料、工作中心日历和标准工时。
- 需要明确有限产能还是无限产能、冻结区间长度、急单权限、工单最小/最大批量和合批拆批规则。
- 设备保养、人员班次、夹具数量、颜色/型号换线矩阵等约束应有可靠来源；没有数据时必须标注人工假设。

### 参与岗位

主计划员管理 MPS 和优先级；物料计划员运行 MRP、跟踪缺料；车间计划/调度员执行有限排程和派工准备；生产主管确认班次与现场约束；采购反馈到料；仓储反馈可用库存；工艺/质量确认版本和试制/检验资源；设备工程师维护设备日历。ERP 生成经营计划与生产订单，APS 优化排程，MES 承接已下达计划并反馈实绩。

### 业务步骤

1. 汇总独立需求并扣减可用成品、已确认在制和已分配供给，形成 MPS 建议。
2. 依据 MBOM 展开 MRP，考虑损耗、提前期、安全库存、在途和替代关系，生成采购、调拨或生产建议。
3. 将计划订单转换为生产工单，按产线能力、物料批次、交付批次、追溯粒度和换线经济性进行合并或拆分。
4. 进行粗/细能力校验，把各工序负荷分配到工作中心、设备、班次；识别瓶颈、维护窗口和关键夹具限制。
5. 以交期、优先级、最小换线、物料可用日等目标排程，保留约束违反原因和人工调整。
6. 冻结近期计划，锁定工单版本、数量和时间；通过审批后向 MES 下达。
7. MES 接收后做版本、工艺、资源和重复性校验，回传接收结果；执行中持续回报开工、完工、暂停和预计延迟。
8. 滚动重排时只调整允许窗口内工单，已开工工单变更走专门的改制、拆单或取消流程。

### 关键单据与字段

| 单据/对象 | 关键字段 | 说明 |
| --- | --- | --- |
| MPS | 计划版本、产品、周期、需求量、供给量、净需求、来源 | 保留订单/预测分配 |
| MRP 建议 | 物料、需求日期、毛需求、现有量、在途、净需求、建议动作 | 计算口径要可解释 |
| 生产计划 | 计划号、产品版本、数量、起止时间、工作中心、优先级 | 可在工单前作为中间层 |
| 生产工单 | 工单号、产品/制造版本、计划数量、工厂/产线、计划起止、需求来源、状态 | MES 执行核心对象 |
| 工序计划 | 工单、工序、资源、排程起止、标准工时、前后关系、锁定标记 | 有限排程的落点 |
| 排程约束/版本 | 资源日历、换线矩阵、物料可用日、优化目标、违反项、人工原因 | 支撑重算与审计 |

### 状态流转

生产工单的参考状态机：

```text
计划建议 → 已创建 → 已排程 → 已冻结 → 已下达 → 执行中 → 已完工 → 已关闭
              ├─校验失败→ 待修正
已冻结/已下达 ─变更→ 变更评审中 → 已重排/已拆分/已取消
执行中 ─异常→ 已暂停 → 执行中/已终止
```

“已下达”守卫条件包括制造版本已发布、数量大于零、工序计划完整、工作中心有效、需求来源可追踪；“已完工”由 MES 实绩驱动，不等于 ERP 财务关闭；“已关闭”还需数量差异、领退料、质量和入库对账完成。取消必须区分未开工、已备料和已开工，不能一个状态覆盖不同补偿。

### 数据关系

一个 MPS 项连接多个订单行和预测需求；MRP 由 MPS/工单需求与 MBOM 展开得到。生产计划可拆为多个生产工单，工单再包含按工艺路线生成的工序计划。需求分配记录每个工单供给哪个销售订单/库存需求；父子工单表达半成品与整机生产；拆单需保存原工单、子工单、数量迁移和已发生实绩。排程版本关联输入快照、约束和结果，使重新计算后仍可回看旧计划。

### 系统边界

ERP 主责 MPS/MRP、生产订单和经营数量；APS 主责有限产能计算与排程建议；MES 主责接收已下达工单、现场派工及实绩反馈。小型场景可能由 ERP 或 MES 同时承担部分排程，但必须定义唯一计划版本和下达入口。MES 不应自行扩大工单计划数量来“消化超产”；ERP/APS 不能绕过 MES 直接把已过站实绩改成新计划。WMS 提供物料可用日，QMS 提供质量冻结，设备系统提供资源可用性。

### 智能锁案例

**行业假设示例**：一周需生产深灰、银色两种面板的同平台智能锁共 3,000 套。两者总装工艺相近，但喷涂颜色、标签和包装不同，且产线从深灰切换银色需清线和首件确认。APS 将需求拆为三个 1,000 套工单，先连续排两个深灰工单，再排银色工单，减少一次换色；同时因指纹模组只有 2,400 件可按期到料，把第三个工单计划开始时间放到补料后。每个工单冻结对应配置、MBOM、路线和固件版本，MES 收到后显示物料风险而不擅自提前。

### 异常分支

典型异常是关键指纹模组供应延迟，而近期工单已冻结。闭环为：WMS/采购更新预计可用日并触发缺料事件 → 计划系统定位受影响工单、订单交期和产线空档 → 评估替代料、工单换序、拆分可生产数量或跨仓调拨 → 工程/质量批准替代时更新受控适用关系 → 计划员创建重排版本并说明违反冻结的原因 → ERP/APS 更新计划，MES 以工单版本应用变更 → 仓储撤销或调整原备料任务 → 销售收到交期风险 → 到料后恢复排程并对比实际影响。异常关闭需要供给、计划、现场和客户承诺四方状态一致。

### 关键指标

- 计划达成率 = 按计划窗口完成的工单数或数量 / 应完成工单数或数量，必须固定统计粒度。
- 排程稳定性 = 冻结窗口内未发生起止/资源/数量变化的工单比例。
- 产能负荷率和瓶颈资源利用率，需结合停机、换线和等待原因解释。
- 工单准时下达率与平均提前期。
- 因缺料、版本或设备约束导致的重排次数/工单，以及换线时间占比。

### 常见误区

1. 把 MRP 净需求直接当现场排程，忽略有限产能、换线、班次和工装约束。
2. 用一个“计划状态”表示创建、冻结和下达，导致谁还能改、现场是否应执行不清楚。
3. 为追求设备利用率盲目提前生产，造成库存增加、版本过期或订单配置错配。
4. 每次重排覆盖旧结果，没有输入快照和人工调整原因，无法解释计划为何变化。

### Java 全栈开发关注点

- **工单状态机与并发**：下达、撤销、拆分、暂停采用显式命令；对工单行使用乐观锁或条件更新，防止计划员重排与 MES 开工同时成功。
- **排程长任务**：大规模排程异步执行，任务带输入版本、进度、可取消标志和结果版本；重试不得重复下达工单。
- **时间与约束模型**：统一班次跨日、节假日、设备维护和时区语义；持续时间不能简单用自然时间相减。
- **事件一致性**：ERP 工单落库与 Outbox 同事务，MES 消费按来源工单 ID+版本幂等；回执区分已接收、业务拒绝和暂时失败。
- **可解释前端**：甘特图显示物料、产能、换线和冻结约束；拖拽调度提交的是变更命令与原因，不是直接修改坐标字段。

### 阶段自测

1. MPS、MRP、生产工单和工序计划分别回答什么问题，它们之间如何建立来源关系？

## 4. 物料齐套

### 业务目标

本阶段确保生产工单需要的正确物料，以正确数量、合格状态和可追溯批次，在正确时间送到正确线边位置。业务范围包括备料、拣配、领料、配送、线边仓、替代料、超领、退料和缺料闭环。完成标志不是 WMS 已打印拣货单，而是工单需求与实物扫描核对完成，关键物料批次可用且已移交到规定库位/工位，账、卡、物数量一致；未齐套项有明确风险和处置。

### 触发与前置

- 已下达或即将开工的生产工单触发备料，也可按拉动信号、最小库存或配送节拍补料。
- 前置包括有效 MBOM、工序投料点、计划数量、损耗、仓库/线边库位、库存状态、批次规则和物料替代组。
- 物料必须完成相应 IQC 或放行；冻结、待检、过期、保质期不足和已被其他工单分配的库存不能作为可用量。
- 需约定批次分配策略，如先进先出 FEFO/FIFO、同工单尽量同批、客户指定供应商批次，以及关键件是否逐件 SN 管控。

### 参与岗位

物料计划员发起齐套检查；仓库拣货、复核和配送；线边物料员接收、上料和退料；生产班组确认实物；质量人员处理冻结、让步和来料异常；采购跟催缺料；工艺工程师审批替代料；计划员决定换序或拆单。WMS 管理仓库实物，ERP 管理库存账务与工单领料，MES 管理工单消耗和线边投料事实，边界必须对齐。

### 业务步骤

1. 按生产工单和 MBOM 展开物料需求，扣减已领、线边可用和可复用余料，生成齐套清单。
2. WMS 根据批次策略和库存状态分配库存，生成拣货/配送任务；关键件可预分配具体批次或 SN。
3. 仓库按库位拣货，扫描物料、批次、容器和数量，复核防止混料；必要时执行拆包和重新贴标。
4. 通过领料单或调拨单把物料从原料仓转到线边仓/工单占用，接口回传实际批次与数量。
5. 线边接收时再次扫描，MES 校验工单、产品版本、替代关系、质量状态、有效期和投料工序。
6. 生产中按实际用量进行投料/消耗，区分正常损耗、报废、超领和退料；剩余合格物料经复核退回。
7. 缺料时生成异常，评估调拨、替代、分批生产、换序或延期；处置结果同步计划。
8. 工单完工/关闭前对工单需求、领料、退料、消耗和现场余料进行对账。

### 关键单据与字段

| 单据/对象 | 关键字段 | 说明 |
| --- | --- | --- |
| 齐套清单 | 工单、物料、需求/已分配/已领/缺口数量、需求时间、齐套状态 | 可按全部或关键件齐套 |
| 备料/拣货单 | 任务号、来源工单、库位、物料批次、容器、计划/实拣数量 | WMS 执行对象 |
| 领料/调拨单 | 单号、工单、发出/接收仓位、物料、批次、数量、库存状态 | 连接库存账与现场 |
| 投料记录 | 工单、工序、工位、物料批次/关键件 SN、数量、人员、时间 | MES 制造事实 |
| 替代料申请 | 原料、替代料、适用产品/工单、比例、有效期、工程/质量结论 | 不能只有口头许可 |
| 退料/补料/超领单 | 原因、原领料记录、物料批次、数量、质量状态、去向 | 支持闭环对账 |
| 缺料异常 | 缺口、需求时间、影响工单、责任人、处置方案、预计关闭 | 驱动计划风险 |

### 状态流转

齐套任务参考状态机：

```text
待计算 → 待分配 → 已分配 → 拣货中 → 待配送 → 已到线边 → 已齐套
              ├─库存不足→ 缺料处理中 → 已分配/部分齐套/已关闭未解决
已到线边 ─质量冻结/错料→ 已隔离 → 已更换/已退回
已齐套 ─工单取消→ 退料中 → 已结清
```

“已齐套”守卫条件要明确是关键件齐套还是全部用料齐套，并验证质量、数量、批次和线边接收；“已分配”不代表实物已经移动；“工单关闭”前应阻止存在未处理超领、负库存或未退余料。

### 数据关系

生产工单通过 MBOM 形成多条物料需求；需求行可被多个库存批次满足，一个物料批次也可分配给多个工单，二者通过分配/领料明细形成多对多关系。领料记录产生线边库存，投料记录把批次或关键件 SN 绑定到工序和整锁 SN。替代料申请连接原物料、替代物料、适用制造版本和有效范围。退料必须引用原领料/投料来源，以恢复正确批次、状态和工单余额，而不是只增加仓库总量。

### 系统边界

WMS 权威管理库位、容器、实物批次和仓内任务；ERP 权威管理采购、库存财务账和工单领退料凭证；MES 权威管理线边投料、工序消耗与产品绑定；QMS 决定待检、合格、冻结和让步状态；PLM/ERP 提供受控替代关系。若线边仓由 MES 管理，仍要通过明确接口与 WMS/ERP 对账，禁止两个系统同时自由调整同一库存。MES 不能因“需要开工”把冻结批次改成合格。

### 智能锁案例

**行业假设示例**：工单需要 500 套主板、指纹模组、电机和锁体。主板按供应商批次管控，指纹模组逐件 SN 管控，螺钉按数量管控。WMS 为主板分配批次 `PCB-0721-A` 300 件和 `PCB-0722-B` 200 件；MES 在线边接收时发现第二批质量状态仍为待检，只允许第一批进入可投料区。计划员决定先生产 300 套，剩余数量等待 QMS 放行。装配时扫描指纹模组 SN 与整锁 SN 绑定，螺钉则按工单汇总扣料，体现不同追溯粒度。

### 异常分支

典型异常是操作员扫描上料时发现到线边的主板批次与领料单不符。闭环为：MES 拦截上料并创建错料异常 → 线边将容器物理隔离，保留扫描照片/标签信息 → WMS 复核拣货、容器换标和库存账 → QMS 判断是否有已使用该批次的在制品并冻结相关整锁 SN → 正确物料重新拣配并交接 → 错误物料按原批次退库或转到正确工单 → ERP/WMS/MES 三方冲销或补记原单 → 对已装配品执行拆解/验证处置 → 盘点确认账卡物一致 → 记录根因（如相邻库位混放）和防错措施后关闭。

### 关键指标

- 工单齐套率 = 在计划开工前满足定义齐套条件的工单数 / 应开工工单数。
- 缺料停线时长及按物料/供应商/原因分类的缺料次数。
- 拣配准确率 = 无错料、错批、错量的任务数 / 完成任务数。
- 线边库存周转天数与呆滞金额/数量。
- 领退料差异率、超领率和工单物料对账一次通过率。

### 常见误区

1. 把“系统已分配”当作“物料已到线边”，忽略拣货、配送、接收和质量状态。
2. 所有物料都做逐件序列化，成本过高；或所有物料只按数量，关键件追溯不足。
3. 替代料只在现场口头批准，不限定产品版本、工单、比例和有效期。
4. 退料不引用原批次与原领料，导致库存恢复到错误状态或追溯链断裂。

### Java 全栈开发关注点

- **库存并发与预留**：库存分配使用条件更新、预留表或数据库锁，确保 `可用量 >= 申请量`；为超时预留设置受控释放，避免重复分配。
- **扫码幂等**：移动端弱网会重发，领料、接收、投料事件以扫描事件 ID 幂等；接口返回已处理结果，不能二次扣减库存。
- **分布式一致性**：WMS 实物移动、ERP 凭证和 MES 工单消耗跨系统不可使用单库事务，采用状态化 Saga/Outbox、可重试步骤和明确冲销命令。
- **批次规则引擎**：FIFO/FEFO、同批优先、保质期和客户限制要版本化、可解释；规则失败时给出具体原因而非笼统“不可用”。
- **权限与设备体验**：替代、超领、库存调整需授权和原因；扫码页离线缓存基础校验，但恢复联网后仍由服务端进行最终版本/质量校验。

### 阶段自测

1. “已分配”“已领料”“已到线边”“已投料”分别代表哪些业务事实，为什么不能合成一个状态？
2. 主板按批次、指纹模组按 SN、螺钉按数量追溯时，数据关系和扫描流程有什么不同？
3. WMS 移库成功但 ERP 领料凭证失败时，如何保证可恢复且不重复扣账？

## 5. 生产执行

### 业务目标

本阶段把已下达生产工单转化为真实、受控、可证明的制造过程。范围包括派工、开工、人员/设备/物料校验、工序过站、关键件装配绑定、固件烧录、测试设备采集、在制品暂停、返工、完工与实绩反馈。完成标志是每个整锁 SN 按冻结工艺完成必经工序，关键件、物料批次、固件版本、参数和测试结果关联完整，执行数量平衡且没有未关闭的执行异常。这里的“制造已完工”只结束生产执行维度，不预先断言 FQC 已放行。

### 触发与前置

- 已下达且具备开工条件的生产工单触发派工；也可由节拍拉动、班组接班或上游工序完成触发。
- 前置包括工单制造基线、物料齐套、可用设备/工装、人员资质、工位登录、作业指导和 SN 编码规则。
- 开工前应确认路线版本、首件要求、设备程序和校准状态；质量冻结或工程停用版本必须阻止执行。
- 设备离线、网络不稳和条码损坏等现场条件需有预先设计的降级与补录规则，不能临时绕过追溯。

### 参与岗位

生产主管释放班组任务；班组长派工、开停工和处理节拍异常；操作员按工位执行与扫描；物料员补料；设备工程师处理设备/工装；工艺工程师处理参数和路线异常；质量人员放行首件、隔离和返工；MES 管理员处理账号、终端和接口。设备系统采集原始信号，MES 形成有业务语义的制造记录。

### 业务步骤

1. 根据工序计划生成派工队列，班组确认人员、工位、设备和目标数量，启动工单/工序。
2. 为产品生成或接收整锁 SN，在首工序校验唯一性、工单和产品版本；扫描上游半成品时建立继承关系。
3. 每个工位登录后校验人员资质、设备校准、工装、物料和最新允许的执行版本，展示对应作业指导。
4. 操作者扫描主板 SN、指纹模组 SN 或物料批次，MES 校验 MBOM、替代、重复绑定和质量状态，再绑定整锁 SN。
5. 烧录工位按主板硬件与产品配置获取受控固件，设备执行烧录与回读校验，上报实际固件版本、摘要、结果和日志索引。
6. 装配/测试设备采集扭矩、电流、指纹识别、通信、开闭锁等结果；MES 按规则判定或接收设备判定，成功后过站。
7. 异常时暂停单件、工序或工单，记录原因；返工必须进入批准的返工路线并保留原失败记录。
8. 末工序核对所有必经工序、关键绑定、质量结果和数量，申报完工并向 ERP/后续入库反馈。

### 关键单据与字段

| 单据/对象 | 关键字段 | 说明 |
| --- | --- | --- |
| 派工单/任务 | 工单、工序、班组、工位、计划数量、优先级、班次 | 面向现场可执行队列 |
| 在制品/整锁 SN | SN、产品/工单、当前工序、在制状态、质量状态、路线版本 | 单件追踪主实体 |
| 过站记录 | SN、工序、进入/完成时间、人员、工位、设备、结果、重试序号 | 成功与失败均应保留 |
| 装配绑定 | 父 SN、子件 SN/物料批次、装配工序、绑定/解绑时间、原因 | 支持绑定历史 |
| 烧录记录 | 主板 SN、整锁 SN、固件版本、摘要、设备、开始/结束、结果、日志地址 | 记录实际而非期望版本 |
| 参数采集 | SN、参数编码、数值、单位、上下限、来源设备、采集时间、判定 | 高频原始数据可外存 |
| 暂停/返工单 | 原因、范围、处置路线、批准人、责任人、完成证据 | 异常闭环依据 |
| 完工申报 | 工单、合格/不合格/报废数量、时间、班组、差异说明 | 不等同于成品已入库 |

### 状态流转

单件在制品参考状态机：

```text
已创建 → 待开工 → 加工中 → 工序完成 → 待下工序 → … → 已完工
              ├─采集失败/缺陷→ 已暂停 → 待返工 → 返工中 → 待复验 → 待下工序
              ├─不可修复→ 已报废
              └─流程撤销→ 已作废（仅限无有效实绩或经受控冲销）
```

“工序完成”守卫条件包括必扫物料/关键件齐全、设备参数和工序内检验项满足过站规则、工艺顺序正确；重复提交同一次过站必须返回原结果。“解绑”不是删除关系，应新增解除事件并校验下游是否已经使用该绑定。“已完工”只表示制造维度达到路线完整、执行数量平衡且无未关闭的执行异常，不以最终质量放行为前提；此时独立的质量状态可以是“待检/待放行”，由 FQC 及后续处置驱动为合格、冻结或不合格。

### 数据关系

生产工单包含多件整锁 SN；每个 SN 沿工艺路线产生多条过站记录，过站引用工序、工位、人员、设备和制造基线。整锁 SN 通过装配绑定连接主板 SN、指纹模组 SN、锁体/电机物料批次；同一子件在同一时刻只能有效绑定一个父件。烧录记录同时关联主板 SN、整锁 SN、固件制品和设备。参数采集关联过站尝试，失败重试产生新尝试而不覆盖旧数据。返工单连接原缺陷、返工路线、拆换件、复验结果和最终处置。

### 系统边界

MES 权威记录工单执行、在制状态、过站、绑定和制造实绩；设备/SCADA 保存原始控制与高频数据，MES 保存结果、关键参数和原始日志索引；PLM/工艺系统提供受控作业依据；QMS 管理质量标准与不合格处置；ERP 接收汇总完工和消耗。PLC 不应直接决定 ERP 工单状态，ERP 也不能人工补一个完工数量来替代 MES 的单件执行链。离线工位数据回传时必须仍遵守版本、顺序和幂等规则。

### 智能锁案例

**行业假设示例**：整锁 SN `LOCK-260728-000123` 在电子装配工位绑定主板 `PCB-SN-88421` 和指纹模组 `FP-SN-39210`，锁体来自批次 `BODY-0726-C`。烧录平台根据主板 HW-B 与 Zigbee 配置下载固件 `2.3.4`，上报 SHA-256 摘要和回读成功。功能测试依次记录电机电流、指纹识别次数、密码键盘、Zigbee 入网和连续开闭锁结果。某次电机电流超限时该 SN 被暂停，不能直接进入包装；更换电机后走返工路线并复验，历史失败和新电机批次都保留。

### 异常分支

典型异常是测试设备已显示 PASS，但 MES 因网络超时未收到结果。闭环为：工位保持该 SN“结果待确认”，不允许再次无条件加工或跳站 → 设备端以唯一测试会话 ID 缓存结果 → 网络恢复后重发，MES 按会话 ID 幂等写入 → 若设备无结果，由授权人员发起补采而非手工填 PASS → 新测试尝试关联原会话和原因 → 若实物已被移动则扫描追回并核对 → 过站成功后解除暂停 → 统计接口失败根因并验证缓存/监控改进 → 核对受影响会话均有唯一结果后关闭接口异常。若设备重发两次不同判定，进入数据冲突队列，由设备与质量人员确认，系统不得“最后写入覆盖”。

### 关键指标

- 工单产量达成率与小时产出，需分别展示合格、返工、报废数量。
- 一次通过率 FPY = 无返工一次完成各工序的产品数 / 投入产品数。
- 单件生产周期、工序节拍和在制等待时间。
- 设备数据自动采集成功率、补采率和接口延迟。
- 关键件绑定完整率、错料/错版防错拦截次数以及返工率。

### 常见误区

1. 只在末工序记录完工数量，不记录单件过站和物料绑定，追溯只能停留在工单级。
2. 把设备 PASS 当作过站全部条件，忽略人员资质、物料、工艺顺序和质量冻结。
3. 返工时删除原失败或直接把状态改回合格，丢失真实制造历史。
4. 设备超时就让操作员重复点提交，造成重复扣料、重复绑定或一件多次过站。

### Java 全栈开发关注点

- **高并发状态机**：过站采用“当前状态+期望版本”的条件更新；在同一事务写过站、绑定/消耗和 Outbox，唯一约束防止同一 SN/工序/尝试重复成功。
- **设备协议与幂等**：网关把设备协议转换为版本化事件，包含设备 ID、测试会话 ID、SN、设备时间和序列号；服务端处理重复、乱序、时钟漂移和晚到数据。
- **追溯写模型**：绑定使用有效期或事件模型，解绑/换件追加记录；历史表按时间和工厂分区，关键关联键建立索引，禁止物理删除。
- **离线与补偿**：工位客户端使用本地队列、签名数据和有限离线许可；恢复后按事件序号上传，冲突进入人工处理而非静默覆盖。
- **权限审计与可观测性**：跳站、补录、解绑、强制完工是高风险命令，需要二次授权、原因和审计；链路追踪贯穿终端—网关—MES—设备日志。

2. 为什么返工必须保留原失败记录并使用受控返工路线？换下的关键件关系应怎样表达？

## 6. 质量管控

### 业务目标

本阶段以贯穿来料、过程、成品和出货的质量控制保证产品满足规范，并使不合格能够识别、隔离、评审、处置、复验和改进。范围包括 IQC（来料检验）、IPQC（过程检验）、FQC（最终检验）、OQC（出货检验）、首检、巡检、功能测试、不合格评审、返工复验和 CAPA。完成标志是检验批/单件有可解释的判定，合格品被放行，不合格实物与系统状态一致，处置和复验形成闭环。

### 触发与前置

- 采购到货触发 IQC，开线/换型/换料/参数变更触发首检，生产节拍触发 IPQC 巡检，制造维度的整锁完工事件创建 FQC 待检任务，发货批次触发 OQC；“制造已完工”不等于“质量已放行”。
- 前置为已发布检验方案、产品/工艺版本、特性定义、测量方法、抽样标准、缺陷代码、判定规则和量具校准状态。
- 需要明确按物料批次、工单、工序、整锁 SN 或包装箱抽样，以及严重/主要/次要缺陷的处置权限。
- 测试设备结果与人工检验要有统一单位、精度、上下限和版本；让步接收、偏离许可必须限定范围和有效期。

### 参与岗位

IQC/IPQC/FQC/OQC 检验员执行检验；质量工程师维护标准、分析缺陷并主持评审；生产和工艺提供过程调查与返工方案；供应商质量推动来料纠正；设备/计量人员维护测试台与量具；仓储/生产负责物理隔离；计划和销售评估交付影响；授权评审委员会决定返工、返修、让步、退货或报废。

### 业务步骤

1. 按到货、工单、换线、巡检周期、完工或出库事件创建检验任务，冻结适用的检验方案版本。
2. 系统依据抽样规则选择样本或要求全检，检验员核对对象、设备/量具校准和环境条件。
3. 采集定量值、定性结果、缺陷代码、照片和设备日志，记录实际值与当时规格上下限。
4. 规则引擎对单项和检验批判定；超限或关键缺陷立即触发停止/隔离，不能等日报汇总。
5. 对不合格创建 NCR，定位物料批次、工序、设备、班次、整锁 SN 和可能影响范围。
6. 评审选择返工、返修、挑选、让步接收、退供应商或报废，并明确方案、责任人和期限。
7. MES 按批准路线执行返工，QMS/MES 创建复验任务；复验合格后由授权质量角色放行。
8. 对系统性问题开展根因分析和 CAPA，验证措施有效性，并将结论反馈供应商、工艺或产品版本。

### 关键单据与字段

| 单据/对象 | 关键字段 | 说明 |
| --- | --- | --- |
| 检验方案/特性 | 阶段、适用版本、特性、单位、规格限、方法、抽样、缺陷等级 | 发布后不可覆盖历史 |
| 检验任务/检验批 | 来源单据、批次/工单、方案版本、样本量、状态、检验员 | 连接触发业务 |
| 检验结果 | 样本/SN、特性、实测值、判定、设备、时间、附件 | 保存原始值和判定 |
| NCR 不合格单 | 不合格号、对象、缺陷、数量、发现点、影响范围、质量状态 | 启动隔离与评审 |
| 评审/处置单 | 根因初判、处置类型、返工方案、让步范围、责任人、审批 | 处置必须有权限 |
| 复验记录 | 原 NCR、返工/挑选批、方案、结果、放行人 | 形成质量闭环 |
| CAPA | 根因、纠正、预防措施、负责人、期限、效果验证 | 面向防再发 |

### 状态流转

不合格品参考状态机：

```text
已发现 → 已隔离 → 待评审 → 已定处置
  ├─返工/返修→ 处理中 → 待复验 → 已放行/再次不合格
  ├─挑选→ 挑选中 → 合格部分已放行 + 不合格部分继续处置
  ├─让步→ 待审批 → 有条件放行
  ├─退货→ 待退供应商 → 已退货
  └─报废→ 待批准 → 已报废
```

“已隔离”要求系统冻结与物理区域/标识一致；“已放行”必须引用复验结果或有效让步审批；不允许检验员既提交原不合格又单独无依据改为合格。检验结果修正采用更正记录，保留原值、原因和批准。

### 数据关系

检验方案版本包含多项检验特性；检验任务引用触发来源（到货单、工单、工序、完工批或出库单）和方案快照。一个检验批包含多个样本，一个整锁 SN 有多个特性结果。NCR 可来源于一个或多个失败结果，并通过影响分析连接物料批次、设备、班次、工单和受影响 SN。处置单连接返工路线/报废/退货凭证，复验记录引用 NCR 与实际处理批次，CAPA 可聚合多个同类 NCR。

### 系统边界

QMS 通常权威管理质量标准、检验任务、不合格、评审和 CAPA；MES 执行生产现场首检、巡检、功能测试和返工并执行质量门禁；WMS/ERP 根据 QMS 放行结果改变库存状态；设备系统保存测试原始曲线。若检验功能内嵌 MES，仍需区分制造状态和质量状态两个维度，不能以“工序完成”自动代表“质量放行”。QMS 的放行事件需带对象、数量、版本和处置依据。

### 智能锁案例

**行业假设示例**：总装后的智能锁执行 FQC，全检密码键盘、指纹识别、Zigbee 通信、电机电流和连续开闭锁。SN `LOCK-260728-000123` 的电机峰值电流超过工艺上限，设备上报实际曲线索引，MES 将单件质量状态改为隔离并创建 NCR。分析发现同一电机批次另有 47 件已装配，于是 QMS 扩大影响范围冻结这些 SN。评审决定更换电机并全检；每件走返工路线、记录新电机批次并复验，全部完成后才解除冻结。

### 异常分支

典型异常是巡检发现扭矩偏低，但该时间段已有产品进入下一工序。闭环为：立即暂停相关工位和设备 → 锁定从“上次合格巡检时间”到“本次发现时间”的生产窗口 → 通过过站、设备、班次和工装记录圈定受影响 SN → 物理隔离在制与已包装品 → 计量/设备确认扭矩枪校准，工艺分析参数 → QMS 制定全检或抽样加严方案 → 合格品重新放行，不合格品返工复验 → 修复设备并通过首件确认后复产 → CAPA 验证巡检频率、报警或防错改进 → 所有影响对象有最终状态后关闭 NCR。不能只修设备而不追查已流出的时间窗产品。

### 关键指标

- IQC/IPQC/FQC/OQC 各环节一次合格率与缺陷率，统计对象和分母必须明确。
- FPY/直通率及返工复验通过率。
- NCR 平均关闭周期、逾期数和重复发生率。
- 客诉逃逸率，即出货后发现而厂内质量门未拦截的问题比例。
- 测量系统/设备数据有效率、量具超期使用次数，以及 CAPA 按期有效率。

### 常见误区

1. 把所有质量活动放到成品终检，过程缺陷到最后才发现，返工成本高且影响范围大。
2. 只记录 PASS/FAIL，不保存实测值、规格版本、设备和样本，无法趋势分析或复判。
3. 系统冻结了库存但实物没有隔离，或实物贴红牌但 WMS 仍可分配，形成双重风险。
4. 返工完成就直接放行，没有独立复验；CAPA 只填原因，没有效果验证。

### Java 全栈开发关注点

- **双状态模型**：制造状态与质量状态分离，业务命令同时检查二者；质量冻结事件可即时阻止过站、入库与出库。
- **规则与精度**：规格限、抽样和判定规则版本化；数值用 `BigDecimal` 与明确单位，禁止浮点误差或前端自行判定成为最终事实。
- **大数据与证据**：结构化结果存关系库，曲线/照片存对象或时序存储并保存内容哈希、权限和生命周期；追溯查询能定位原始证据。
- **审批与审计**：让步、报废、结果更正和放行按缺陷等级授权；使用追加式审计记录原值、新值、原因、人员和时间。
- **事件传播**：NCR 影响范围扩大时以版本化事件通知 MES/WMS/ERP；消费者幂等处理并回执，监控“质量已冻结但库存仍可用”的不一致。

## 7. 成品入库

### 业务目标

本阶段把制造已完工的整锁转化为包装明确、数量准确、库位可见的成品对象；质量仍待检的实物可以按规则进入隔离库位，物理收货或上架不等于可供销售。范围包括完工交接、包装作业、整锁 SN 与包装箱码/托盘码绑定、入库质检或放行确认、入库单、上架和库存状态同步。完成标志是实物已由生产责任区交接到受控库位，SN—箱码—入库单关系完整，包装、收货/上架、质量和账务四个维度各自有明确状态；只有满足企业定义的质量合格、账务有效及未被分配/冻结等条件时，库存才可用于销售。

### 触发与前置

- 生产工单末工序完工、质量放行或包装批次达到交接条件触发入库。
- 前置包括产品包装规范、标签模板与版本、箱装数量、SN 编码、箱码/托盘码规则、目标仓库库位和库存状态映射。
- 每件整锁必须完成必经工序、关键件绑定和规定测试；需 OQC 或入库抽检的产品不能直接变为可用库存。
- 生产、MES、WMS、ERP 要约定交接点：下线即转移、包装完成转移，或仓库扫码接收才转移。

### 参与岗位

包装操作员核对产品并包装；生产班组完成完工交接；质量人员确认放行、包装检验或入库质检；仓库收货员复核箱码、数量和外观并上架；仓储主管处理差异；计划/订单人员关注可用库存；ERP/WMS/MES 管理员处理接口对账。标签重打、拆箱换装和库存状态调整应由授权角色执行。

### 业务步骤

1. MES 汇总已完工整锁 SN，校验路线、测试、质量状态和工单数量，形成待包装队列。
2. 包装工位扫描整锁 SN，校验产品配置、颜色、标签语言、附件和包装材料版本，打印/校验单品标签。
3. 按装箱规则把多个整锁 SN 绑定到唯一包装箱码，达到箱容或执行尾箱确认后封箱；再按需要绑定托盘码。
4. 对包装外观、标签、附件数量和箱内配置进行检验；失败箱保持冻结并进入返包装流程。
5. 生产提交成品入库申请，包含工单、产品、数量、箱码和质量状态；WMS 创建收货/上架任务。
6. 仓库扫描箱码接收，系统展开并抽核箱内 SN，记录实收数量、库位、批次和差异。
7. WMS 上架后回传库存，ERP 生成或确认成品入库凭证；MES 更新交接状态，但保留制造完工时间。
8. 对尾箱、破箱、重打标签、退回生产等异常执行受控解绑/重绑和单据冲销，日终对账。

### 关键单据与字段

| 单据/对象 | 关键字段 | 说明 |
| --- | --- | --- |
| 完工交接单 | 工单、产品版本、合格数量、SN 范围/清单、交接方、时间 | 连接生产与仓储责任 |
| 包装任务 | 产品、包装版本、目标数量、标签模板、附件清单、状态 | 防止配置混包 |
| 箱码/托盘 | 包装箱码、产品/配置、箱容、尾箱标志、父托盘码、状态 | 可展开到整锁 SN |
| SN—箱码绑定 | 整锁 SN、箱码、绑定/解绑事件、工位、人员、时间、原因 | 保留换箱历史 |
| 成品入库单 | 入库单号、来源工单、仓库、产品、计划/实收数量、库存状态 | ERP/WMS 业务凭证 |
| 上架任务 | 收货单、箱码/托盘、建议/实际库位、操作人、完成时间 | WMS 实物定位 |
| 入库差异单 | 短少、混箱、破损、标签错误、涉及 SN、处置与复核 | 异常闭环 |

### 状态流转

包装箱/入库对象不能用一条线性状态链表示，应使用正交状态向量。参考模型如下：

```text
包装状态：待包装 → 装箱中 → 已封箱；已封箱 → 已打开 → 装箱中
收货/上架状态：待交接 → 待收货 → 已收货 → 待上架 → 已上架；差异时 → 待处理 → 已更正/已拒收
质量状态：待检 → 合格；待检/合格 → 冻结 → 待复验 → 合格/不合格
账务状态：待过账 → 已过账；已过账 → 待冲销 → 已冲销
```

对象的当前状态可表达为 `{包装=已封箱，收货/上架=已上架，质量=待检，账务=待过账}`，这表示实物已在隔离库位但尚不可销售，也尚未完成 ERP 过账。四个维度由各自主责事件迁移，不能由其中一个状态覆盖推导其他状态。“已封箱”要求箱内 SN 唯一、数量不超箱容、产品配置一致且标签有效；“已上架”只要求实际库位和实收数量确认；可用库存还需质量和账务等组合条件满足。箱码解绑必须检查是否已出库或被分配，已交付箱不能随意改装箱历史。

### 数据关系

一个生产工单产生多个整锁 SN；多个 SN 组成一个包装箱码，多个箱码可组成一个托盘码。一个入库单可包含多个工单和箱码，一个箱码在任一时刻只能位于一个有效库位，但历史移动形成多条库存事务。SN—箱码绑定是追溯桥梁，不能仅存箱内数量。成品对象分别保存包装状态、收货/上架状态、质量状态和账务状态及各自版本；“已上架+待检”“已上架+冻结”等组合是合法的隔离库存事实，查询可用量需按组合策略判断，不能把状态压成单一枚举。

### 系统边界

MES 权威管理完工 SN、包装执行和 SN—包装箱码绑定；WMS 权威管理收货、库位、容器和仓内移动；ERP 权威管理成品库存财务账和入库凭证；QMS 决定入库/OQC 放行。企业若由 WMS 完成包装，也必须让绑定事实回流追溯主线。MES 完工不等于 ERP 入库，WMS 收货也不必然等于质量可用；接口应明确每个事件的业务时点和库存状态。

### 智能锁案例

**行业假设示例**：每箱装 4 套相同配置智能锁，包装工位扫描 4 个整锁 SN 后生成箱码 `CTN-260728-0088`，系统检查颜色、开门方向、通信制式和固件标签一致，并验证说明书、电池和安装附件版本。仓库收货扫描箱码，随机展开核对其中一个 SN，然后上架到库位 `FG-A-03-02`。追溯关系同时保留四个 SN、箱码、入库单和库位；若客户只需散发一套，后续拆箱也必须形成箱码状态和新包装关系。

### 异常分支

典型异常是仓库扫码发现箱码显示 4 件，但实物只有 3 件。闭环为：WMS 暂停收货并把箱放入差异区 → 创建入库差异单，锁定该箱码和关联 SN → MES 查询绑定/解绑、包装工位和封箱记录，生产清点待包装区 → 若漏装，按批准流程打开原箱、补入正确 SN、重新检验和封箱；若绑定错误，先冲销错误绑定再扫描真实实物 → WMS 重新收货，ERP 仅按最终实收生成凭证 → 复核标签和库存 → 记录根因与包装防错措施并关闭差异单。不得直接把箱内数量字段从 4 改成 3 而不解释缺失 SN 去向。

### 关键指标

- 完工到入库周期，分解为待包装、待检、待收货和待上架时间。
- 入库一次准确率 = 无数量、配置、箱码和标签差异的入库任务 / 完成任务。
- SN—包装箱码绑定完整率与混箱拦截次数。
- 入库待检/冻结库存占比及平均滞留时长。
- 库位准确率、上架及时率和 ERP—WMS—MES 数量对账差异。

### 常见误区

1. 把 MES 完工、质量放行、WMS 收货和 ERP 入库当成同一个时点，异常时无法判断责任和补偿。
2. 箱码只记录产品和数量，不记录箱内整锁 SN，发货后无法准确追到单件。
3. 标签重打没有作废旧标签和审计，现场可能同时存在两个可扫标识。
4. 为修复短少直接改数量或删除绑定，不保存拆箱、退回和复核过程。

### Java 全栈开发关注点

- **正交状态与聚合约束**：分别持久化包装、收货/上架、质量和账务状态及版本，使用组合策略计算可用性；箱码聚合内校验箱容、同配置和 SN 唯一，数据库约束保证一个 SN 同时只有一个有效箱绑定，绑定/解绑采用事件记录。
- **打印可靠性**：打印请求带业务幂等键，区分重试打印和标签重制；重制必须作废旧序列、记录原因并可在扫描时识别旧标。
- **跨系统 Saga**：MES 交接、WMS 收货/上架、ERP 入库分别有状态和回执；失败通过冲销/重试补偿，不用“全成功才响应”的长分布式事务。
- **扫描性能与缓存**：箱码展开可能包含大量 SN，分页/批量校验并建立反向索引；移动端缓存标签模板时校验版本和有效期。
- **对账与监控**：定时按工单、入库单、箱码比对完工、实收和账务数量；差异生成可分派任务，不自动篡改任一主系统。

### 阶段自测

1. MES 完工、质量放行、WMS 收货、WMS 上架和 ERP 入库各自代表什么事实？
2. 箱码实物短少时为什么不能只修改箱内数量？怎样保持 SN、包装和库存链条可信？
3. 标签打印超时可能造成哪些重复与错标风险，幂等打印和标签重制应如何区分？

## 8. 发货与追溯

### 业务目标

本阶段把可用成品按销售订单正确交付给客户/渠道，并让每次交付都能回到制造全链路；发生售后故障、供应商缺陷或召回时，能够做正向与反向追溯、圈定范围、执行处置并反馈改进。范围包括销售出库、波次/拣配、箱码与 SN 复核、装车交接、序列号交付、出库回写，以及面向投诉、召回和分析的追溯。完成标志是订单、出库单、客户、箱码/整锁 SN、时间和物流信息关联完整，库存与账务一致，并能在可接受时间内回答“这件产品怎样制造”及“这批问题影响谁”。

### 触发与前置

- 已批准销售出库/发货通知触发拣配；客户投诉、供应商质量通知、工程风险或监管要求触发追溯与召回。
- 发货前置包括销售订单可交付数量、信用/审批、成品合格可用库存、客户配置/批次限制、承运与地址信息。
- WMS 必须能从箱码展开整锁 SN；MES 追溯链需连接物料批次、主板/指纹模组 SN、固件版本、工序和测试。
- 需明确保修起算、客户隐私、序列号交付范围、召回等级、通知责任和数据保留期限。

### 参与岗位

销售/订单运营创建发货需求并确认客户；仓库计划员建波次，拣货员和复核员扫描箱码/SN；物流人员装车交接；财务/ERP 完成出库账务；质量工程师发起追溯、风险评估和召回；售后收集故障现象与现场版本；生产、工艺、研发、供应商质量参与根因分析；信息化团队保障跨系统查询与审计。召回范围缩小必须由质量证据支持，不能只为降低成本而人为排除。

### 业务步骤

1. ERP 根据销售订单和审批生成发货通知/销售出库单，明确订单行、客户、产品配置、数量、地址和批次限制。
2. WMS 分配合格可用库存，按 FEFO/FIFO、客户指定批次、整箱优先等规则生成波次和拣货任务。
3. 拣货时扫描库位、箱码/托盘码，系统展开校验产品、配置、数量、质量、分配对象和库存状态。
4. 复核台再次核对订单、箱码、整锁 SN、标签和单证；拆箱零拣时形成新的有效包装关系。
5. 装车/承运交接记录车辆或运单、封签、交接人和时间；WMS 完成出库，ERP 生成销售出库凭证。
6. 将实际交付的箱码与整锁 SN 关联客户/渠道和订单行，按权限向售后或客户服务提供序列号交付清单。
7. 售后收到故障 SN 时反向追溯产品版本、固件、关键件、物料批次、过站、设备、测试、入库与发货。
8. 收到缺陷物料批次或固件风险时正向追溯所有受影响整锁 SN、库存位置、在制状态和已交付客户。
9. 质量评估风险并执行冻结、通知、召回、返修/升级；完成数量核对、效果验证和 CAPA 后关闭。

### 关键单据与字段

| 单据/对象 | 关键字段 | 说明 |
| --- | --- | --- |
| 发货通知/销售出库单 | 订单号/行、客户、产品配置、计划数量、交期、批次要求、地址 | ERP 商业交付依据 |
| 波次/拣货任务 | 波次、库位、箱码/托盘、分配数量、策略、操作人 | WMS 执行 |
| 发货复核记录 | 出库单、箱码、SN 清单、复核人、时间、差异 | 证明发对货 |
| 装车/物流交接 | 运单、承运方、车辆/封签、箱数、交接双方、时间 | 连接物流责任 |
| SN 交付记录 | 整锁 SN、箱码、订单行、客户/渠道、出库时间、保修起点 | 追溯客户去向 |
| 追溯查询/案件 | 触发对象、方向、条件、结果快照、查询人、用途 | 敏感查询需审计 |
| 召回/现场行动单 | 风险、范围版本、目标 SN/客户、通知、回收/升级状态、结论 | 闭环处置 |
| 售后故障单 | 故障 SN、现象、现场固件、安装环境、检测、处置、根因 | 反馈质量改进 |

### 状态流转

发货对象参考状态机：

```text
待分配 → 已分配 → 拣货中 → 待复核 → 已复核 → 待装车 → 已出库 → 已交付
       ├─库存/质量异常→ 分配失败/已冻结 → 重新分配
待复核 ─错货/破损→ 差异处理中 → 重新拣配/取消
已出库 ─物流异常→ 运输异常 → 已交付/退回入库/理赔关闭
```

召回案件可独立使用“草稿 → 风险评估 → 已批准 → 通知中 → 执行中 → 效果核对 → 已关闭”的状态机。“已出库”要求 WMS 实物扣减和 SN 交付清单确定；“已交付”可依据签收事件。召回关闭必须核对目标、已联系、已回收/升级、拒绝/失联和豁免数量，不得只填一个完成日期。

### 数据关系

销售订单行可产生多个发货通知和出库单；出库单包含多个箱码，箱码展开到整锁 SN，每个 SN 形成客户/渠道交付记录。整锁 SN 反向连接包装、入库、工单、过站、固件版本、主板/指纹模组 SN 和物料批次。正向追溯以物料批次、关键件 SN、固件版本、设备或时间窗为起点，经绑定与过站找到受影响整锁，再区分在制、库存、已发货和售后状态。召回案件保存每次范围计算的版本与依据，避免源数据变化后无法解释当时通知范围。

### 系统边界

ERP 权威管理销售出库单、客户和账务；WMS 权威管理拣配、装车前实物和库存扣减；MES 权威管理制造谱系与 SN；QMS 权威管理风险、不合格、召回和 CAPA；CRM/售后系统管理客户沟通和维修服务。追溯服务可以建立跨系统读模型或图关系，但数据仍标明来源、版本和同步时间。客户个人信息按最小权限读取，制造人员通常只需看到渠道或脱敏客户标识。

### 智能锁案例

**行业假设示例**：客户报告整锁 SN `LOCK-260728-000123` 偶发无法联网。反向追溯显示其主板 `PCB-SN-88421` 来自批次 `PCB-0721-A`，固件为 `2.3.4`，Zigbee 测试当时通过，产品装在箱码 `CTN-260728-0088` 并由订单行 `SO-10086/20` 发往某渠道。进一步分析确认特定主板批次与该固件组合存在边界问题。正向追溯找到所有同组合整锁 SN，区分仍在库、在途和已交付对象；在库立即冻结，已交付由售后推送受控升级，完成后回写行动结果。

### 异常分支

典型异常是供应商通知某主板物料批次可能存在安全风险。闭环为：QMS 创建风险案件并锁定原始通知 → 追溯服务从供应商批次映射企业物料批次和主板 SN → 经装配绑定定位整锁 SN → 按在制、待检、库存、在途、已交付、已维修分类 → MES/WMS 即时冻结未出厂对象，ERP 阻止新发货 → 质量与研发评估固件缓解、换板或召回策略 → 召回审批后向渠道/客户发通知并生成逐 SN 行动任务 → 回收、换板或升级结果逐件记录与复验 → 对未联系和拒绝处理对象持续跟踪 → 目标数量对账、风险复评与 CAPA 有效性确认后关闭。每次扩大或缩小范围都保存规则、查询时间和批准证据。

### 关键指标

- 发货准时率与订单足量交付率，按承诺日期和订单行统计。
- 拣配/复核准确率、错发率和出库差异关闭周期。
- 追溯查询响应时间与追溯链完整率，例如关键件、固件、测试、客户去向是否齐全。
- 召回触达率、处置完成率和平均关闭周期。
- 售后故障率/千台、同批次聚集度和问题重复发生率。

### 常见误区

1. 只把产品型号和数量写入出库单，不记录实际交付的箱码与整锁 SN，无法精准召回。
2. 认为追溯只是一个查询页面，平时不治理绑定完整性、来源版本和跨系统对账。
3. 正向追溯只查仓库库存，遗漏在制、在途、已交付、维修换件和拆箱后的关系。
4. 召回用 Excel 手工维护且覆盖范围版本，无法证明通知了谁、处理了什么、还有多少未闭环。

### Java 全栈开发关注点

- **追溯读模型**：通过事件或 CDC 建立以 SN、物料批次、箱码和订单为索引的跨系统读模型；每条边保留来源和有效时间，支持按“当时状态”查询。
- **查询性能与一致性说明**：深链查询使用图遍历或分层批量查询，限制深度/节点数并异步导出大结果；页面标明数据截至时间，关键召回在源系统二次核验。
- **权限与隐私**：按用途和角色控制客户、手机号、地址等信息，导出加水印并记录查询条件、操作者和案件号；服务间使用最小权限。
- **召回工作流**：范围计算、批准、通知、行动、复验和关闭使用显式状态机；逐 SN 任务幂等，批量操作可续跑，失败项单独重试。
- **接口安全与审计**：物流签收、售后回传可能来自外部，需签名、时间窗、防重放和 schema 版本；所有手工补录保留证据和审批。

### 阶段自测

1. 从客户故障整锁 SN 反向追溯到供应商物料批次，需要经过哪些关键关系和系统？
2. 从缺陷主板批次正向追溯时，为什么必须区分在制、库存、在途、已交付和已维修对象？
3. 召回范围为何需要版本化快照？怎样在查询性能、数据新鲜度、客户隐私和审计之间取得平衡？

## 结语：用一个 SN 验证端到端理解

学习或评审 MES 方案时，可以随机选择一个已交付整锁 SN，要求系统给出以下证据链：它服务哪个销售订单和配置；使用哪个产品版本、EBOM/MBOM、工艺路线与固件版本；来自哪个生产工单；消耗哪些物料批次并绑定哪块主板、哪个指纹模组；经过哪些工序、工位、设备和人员；测试与质量处置如何；装入哪个包装箱码、何时入哪个库位；最后由哪个出库单交付给哪个客户/渠道。再选择一个物料批次，反向执行正向追溯，确认所有在制、库存和已交付对象均可被圈定。

如果其中任何一段只能靠人员回忆、临时拼表或覆盖历史数据才能解释，就说明数字线程仍有断点。修复断点时，应先确认业务责任与数据所有权，再设计接口、状态机和界面；不要先从增加一个字段或页面开始。
