# 智能锁 MES 学习助手初始化设计

## 1. 项目目标

本项目用于帮助一名 Java 全栈开发系统理解智能锁离散制造与销售企业的 MES 全流程。首版以端到端业务知识地图为核心，不把页面做成孤立的 MES 模块百科。

学习者完成首版内容后，应当能够：

- 讲清从销售需求到成品发货与售后追溯的完整业务链路。
- 识别各阶段的参与岗位、关键单据、核心状态及异常分支。
- 说明 ERP、PLM、MES、WMS、QMS 与设备系统的职责边界。
- 沿 BOM、批次、固件版本和整锁 SN 追踪一台智能锁的完整制造履历。
- 从 Java 全栈开发视角识别状态机、接口幂等、并发、权限、审计和追溯等实现重点。

## 2. 场景边界

### 2.1 企业背景

内容面向智能锁离散制造与销售企业。典型产品及物料包括锁体、前后面板、主板、指纹模组、电机、电池组件、结构件、包装材料和固件。

### 2.2 端到端范围

首版覆盖以下八个阶段：

1. 销售需求
2. 产品与工艺准备
3. 计划排产
4. 物料齐套
5. 生产执行
6. 质量管控
7. 成品入库
8. 发货与追溯

MES 是知识地图的中心，但范围向上游延伸到销售订单、产品定义和生产计划，向下游延伸到仓储、发货及售后追溯，以便解释 MES 数据从哪里来、向哪里去。

## 3. 内容组织方案

首页采用“端到端数字主线”，从销售需求一路展开至发货追溯。模块视角和岗位视角作为辅助索引，不取代主流程。

### 3.1 三种浏览视角

- 流程视角：按八阶段顺序学习，默认视角。
- 模块视角：按工单、工艺、物料、设备、质量、追溯和报表等主题定位知识。
- 岗位视角：按销售、计划、工艺、仓储、班组、质量、设备和开发等角色定位职责。

### 3.2 每个阶段的细节模板

每个阶段必须包含：

- 业务范围、业务目标、触发条件、前置条件和完成标志。
- 参与岗位及职责边界。
- 5–10 个可执行的业务步骤。
- 输入单据、输出单据及重要字段。
- 正常状态流转，以及允许和禁止的状态转换。
- BOM、工艺路线、工单、物料批次、固件版本、设备、人员和整锁 SN 等数据关系。
- ERP、PLM、MES、WMS、QMS 和设备系统之间的数据归属与交互。
- 至少一个智能锁业务案例。
- 缺料、报废、返工、让步接收、设备停机或数据采集失败等适用的异常分支。
- 关键指标、常见误区和排查思路。
- Java 全栈开发关注点。
- 阶段自测题及“学完应能回答”的问题。

### 3.3 智能锁数字线程

知识地图需要显式说明以下关系：

销售订单 → 产品型号与版本 → EBOM/MBOM → 工艺路线 → 生产计划 → 生产工单 → 领料批次 → 工序过站 → 主板烧录与固件版本绑定 → 指纹模组及其他关键件装配绑定 → 整锁 SN → 功能与外观测试 → 包装箱码 → 成品入库 → 销售发货 → 售后追溯。

## 4. 文件架构

- `AGENTS.md`：定义学习助手角色、企业背景、协作方式、内容标准和输出约束。
- `README.md`：说明项目用途、目录结构、使用方式和维护入口。
- `docs/learning-log.md`：记录用户问题、分析依据、明确假设、内容决策、验证结果和后续学习方向。不得记录模型私有的逐步思维链。
- `docs/mes-domain-map.md`：保存完整、可持续维护的 MES 领域知识。
- `index.html`：静态学习驾驶舱的语义化页面结构和完整内容。
- `assets/styles.css`：视觉体系、布局、响应式和无障碍样式。
- `assets/app.js`：视角切换、搜索筛选、节点展开和本地学习进度。

页面和 Markdown 必须共享相同的八阶段名称及核心术语，防止知识表达分叉。

## 5. 静态页面设计

### 5.1 页面区域

1. 顶部概览：企业场景、学习目标及系统边界。
2. 流程导航：八阶段端到端主线和当前学习状态。
3. 阶段详情：按统一细节模板呈现知识。
4. 数字线程：展示关键对象及追溯关系。
5. 模块索引与岗位索引：提供交叉入口。
6. 学习检查：显示完成数量、自测问题及建议的下一阶段。

### 5.2 交互

- 支持关键词筛选。
- 支持按流程、模块和岗位切换视角。
- 支持阶段详情展开与收起。
- 支持标记阶段完成，并使用浏览器 `localStorage` 保存进度。
- 没有 JavaScript 时，核心知识仍可按文档顺序阅读。

### 5.3 视觉与响应式

页面采用清晰克制的工业控制台风格，以深蓝灰为基础色、制造橙为强调色、状态绿表示完成状态。桌面端展示横向流程轨道和详情区域；窄屏设备转为纵向阶段卡片。页面不依赖网络字体、外部脚本、图片服务或构建工具，可直接打开 `index.html` 使用。

## 6. AGENTS.md 行为规范

学习助手应：

- 默认使用中文，以智能锁离散制造为例解释概念。
- 先把问题放回端到端流程，再解释局部模块。
- 区分行业通用知识、企业特定假设和待确认事实。
- 将业务、数据、系统和开发实现四个层面关联起来。
- 对用户提出的新学习问题，更新 `docs/learning-log.md`；形成稳定结论后同步领域文档和静态页面。
- 避免捏造公司专有流程、系统字段或接口；无法从项目内容确认时应明确标注假设。
- 产出内容时优先给出流程、状态、单据、数据归属、异常和验证方式。

## 7. 质量与验证

首版完成时应验证：

- 所有约定文件存在，内部链接和静态资源路径有效。
- HTML、CSS 和 JavaScript 无明显语法错误。
- 八阶段名称在 `AGENTS.md`、领域文档和页面中保持一致。
- 搜索、视角切换、阶段展开和学习进度保存正常工作。
- 页面在桌面和手机宽度下均可阅读与操作。
- 键盘用户可以访问主要控件，交互控件具有可识别文本和焦点样式。
- 关闭 JavaScript 后仍能读取核心流程内容。
- 每个阶段都满足细节模板，没有只写标题或一句话概览。

## 8. 首版非目标

- 不连接真实 ERP、PLM、MES、WMS、QMS 或设备接口。
- 不实现账号、服务端、数据库或多人学习进度。
- 不把未经确认的公司专有规则写成事实。
- 不追求覆盖全部制造行业，首版专注智能锁离散制造。

## 9. 后续扩展

首版之后可增加：

- 详细数据库模型、接口契约和领域事件。
- 典型业务时序图和异常处理演练。
- MES 项目需求调研清单及岗位访谈题库。
- 基于 Spring Boot 与前端框架的教学示例。
- 与真实公司流程核对后的差异清单。
