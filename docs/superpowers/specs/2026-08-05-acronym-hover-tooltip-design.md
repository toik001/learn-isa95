# 英文缩写悬浮释义设计

## 背景与目标

当前学习页面使用 `<abbr title="英文全称｜中文释义">` 标注英文缩写，并通过 `cursor: help` 显示帮助光标。浏览器原生 `title` 提示出现较慢、样式不可控，学习者不能稳定地获得即时释义。

本次改动为所有已有缩写增加统一的小型悬浮 tip。tip 只显示英文全称和中文释义；“为什么这样命名”、体系位置和智能锁场景继续保留在独立的“英文缩写词典”页面中。

## 范围

- 覆盖首页、工业自动化架构页和 `pages/` 下的全部学习页面。
- 复用现有 `<abbr>` 静态标注，不扫描或猜测新的英文缩写。
- 以 `glossary.html` 的“英文全称”和“中文”两列为内容口径，校准标注脚本中与词典不一致的文本。
- 不在 tip 中加入“为什么这样命名”、来源链接或智能锁案例。
- 不改变右上角“英文缩写表”入口和完整词典页面结构。

## 方案

### 静态数据

`scripts/annotate-acronyms.mjs` 继续负责生成 `<abbr title="英文全称｜中文释义">缩写</abbr>`。生成数据与 `glossary.html` 对齐，已有标注也能在脚本再次运行时更新，避免旧页面保留过期释义。

静态 `title` 是无 JavaScript 时的降级能力。页面源文件仍包含释义，因此核心内容不依赖 JavaScript 才能理解。

### 悬浮交互

新增全站共用的轻量脚本。脚本初始化后：

1. 通过事件委托识别带 `title` 的 `<abbr>`。
2. 首次使用某个缩写时读取并解析 `英文全称｜中文释义`。
3. 复用一个全局 tooltip 元素显示两行紧凑内容，而不是为每个缩写创建节点。
4. 鼠标进入时立即显示，移动到另一缩写时更新内容，离开时隐藏。
5. tooltip 优先显示在缩写下方；空间不足时显示在上方，并限制在视口左右边界内。
6. 页面滚动、窗口尺寸变化或按下 Escape 时隐藏，避免 tip 停留在错误位置。

增强成功后，脚本把原生 `title` 内容保存到数据属性并移除当前 DOM 中的 `title`，避免浏览器原生提示与自定义 tip 重叠；同时保留可访问名称。脚本未加载或初始化失败时，静态 `title` 仍由浏览器显示。

### 样式

首页和详情页现有两份样式表分别加入同一组 tooltip 样式：深色背景、浅色文字、轻微阴影和清晰的英文/中文层级。tooltip 使用固定定位、较高层级和 `pointer-events: none`，不遮断链接或卡片交互；宽度受限，窄屏不会溢出。

## 文件边界

- `assets/acronym-tooltip.js`：解析释义、管理单个 tooltip、处理显示隐藏与视口定位。
- `assets/styles.css`、`assets/detail.css`：tooltip 视觉样式。
- `scripts/annotate-acronyms.mjs`：统一词典口径、更新既有标注、为学习页面写入脚本引用。
- HTML 学习页面：保留静态 `<abbr title>`，增加正确相对路径的 tooltip 脚本引用。
- 测试：覆盖交互行为、边界定位、全站资源引用和词典数据一致性。

## 异常与降级

- 释义缺少分隔符时，将完整 `title` 作为英文/主释义显示，不抛出异常。
- 找不到 `<abbr>` 时不创建可见内容，也不影响页面其他交互。
- 自定义脚本发生异常时，不移除尚未处理节点的 `title`，页面继续依赖浏览器原生提示。
- tip 不执行远程请求，不依赖服务端或 `file://` 下不可用的接口。

## 验收标准

- 任一学习页面的已标注缩写在鼠标悬停时立即出现紧凑 tip。
- tip 显示英文全称和中文释义，文字与“英文缩写词典”页面一致。
- 鼠标移出、滚动、窗口变化或 Escape 后 tip 隐藏。
- 屏幕左右边缘和上下空间不足时 tip 仍位于可视区域。
- 自定义 tip 与浏览器原生 `title` 不重复显示。
- JavaScript 关闭时仍可通过原生 `title` 查看释义，并可打开完整词典。
- 所有自动化测试通过，HTML/CSS/JavaScript 无明显语法错误。

## 非目标

- 不新增缩写搜索、收藏、弹窗详情或词典筛选。
- 不把“为什么这样命名”塞入小型 tip。
- 不根据页面正文动态推断未登记缩写。
- 不改变八阶段业务内容、系统边界或术语定义范围。
