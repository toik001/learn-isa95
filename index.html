01

CRM / ERP · MES 能力反馈

销售需求

业务目标 / 完成标志

把预测与客户订单转换为可配置、可承诺、可变更控制的制造需求。 完成标志是订单行的配置、数量、交期和变更基线确认，并有 ATP/CTP 依据。

打开销售需求完整详情页 →

触发

预测周期到期、客户下单、渠道补货、促销计划或销售订单变更，都会启动需求评审。

前置条件

客户/渠道、产品型号、销售配置规则、计量单位、交付地点及 ATP/CTP 口径已明确。

数据关系

销售订单包含订单行；订单行与生产工单可多对多，必须用需求分配记录保留数量来源与去向。

从触发到完成

  1. 汇总预测、渠道补货与确定订单，保留预测冲减规则。
  2. 把颜色、开门方向、通信制式等销售选项映射到受控产品配置。
  3. 先按合格可用库存执行 ATP，不足时结合物料、瓶颈与换线执行 CTP。
  4. 计划、工程、采购与质量评审急单、特殊配置和交付风险。
  5. 回写承诺日期与拆批方案；变更时建立新版本并分析下游影响。
智能锁案例

某渠道订购 2,000 套深灰右开 Zigbee 锁。合格库存只能首周交 600 套， CTP 根据主板到料和换线窗口承诺次周生产 1,400 套，并冻结对应配置与固件分支。

岗位、单据与状态

关键岗位

销售/渠道运营、订单运营、计划员、产品/工艺工程师、采购、仓储、质量。

关键单据与字段

销售订单行（订单号、行号、配置、数量、需求/承诺日期）； ATP/CTP 评审记录（库存、瓶颈、到料日、建议交期）；订单变更单（版本、差异、影响对象）。

参考状态机

草稿 → 待配置校验 → 待供给评审 → 已承诺 → 已释放计划；变更后进入变更评审，而非覆盖原订单。

系统边界、异常闭环与指标

系统边界

CRM/ERP 拥有客户、合同、订单与承诺；PLM 提供配置规则；MES 只反馈在制、停机、预计完工和质量隔离事实。

典型异常

Zigbee 改 Wi-Fi：冻结继续释放 → 区分未开工/已领料/已装配 → 校验主板、固件与标签 → 退料或返工 → 多系统对账 → 关闭变更。

指标

  • 订单准时承诺率、承诺达成率
  • 订单变更率、受影响在制数量
  • ATP/CTP 人工改期比例
Java 开发关注点与阶段自测

实现关注点

显式命令驱动状态迁移；订单 ID、行 ID 与变更版本组成幂等键；乐观锁防并发覆盖；保存 ATP/CTP 输入快照与人工原因；敏感插单分权审计。

常见误区

把订单等同工单；ATP 不区分冻结/待检库存；配置使用自由文本；直接覆盖交期和数量。

自测

  1. 订单行与工单为何是多对多，分配关系如何保存？
  2. 订单开工后改通信制式，哪些数据和实物受影响？
  3. MES 要提供哪些事实才能让 CTP 可信？
02

PLM / ERP / MES / QMS

产品与工艺准备

业务目标 / 完成标志

把“设计上是什么”转换为现场可执行的制造基线。完成标志是 EBOM、MBOM、 工艺路线、检验方案、工位参数与固件版本相互兼容并已批准发布。

打开产品与工艺准备完整详情页 →

触发

新产品导入、量产发布、工程变更、供应商物料替换、质量改进或设备升级触发准备。

前置条件

物料编码、图纸规范、工作中心、工位设备和人员技能等主数据已建档，发布责任已明确。

数据关系

产品版本连接 EBOM，EBOM 行映射 MBOM 行；路线再关联参数、检验与固件，工单快照冻结整套基线。

从触发到完成

  1. 在 PLM 建立产品版本、EBOM、图纸规范与工程变更。
  2. 转换 EBOM 为 MBOM，明确虚拟件、投料工序、损耗和替代组。
  3. 发布主路线、返工路线、作业指导、工位参数与设备程序。
  4. 把硬件版本、通信模组与允许的固件版本建立多条件兼容关系。
  5. 试制验证通过后发布制造基线；变更按日期、批次或工单受控生效。
智能锁案例

智能锁 V2 工单冻结 MBOM-R05、路线-R03、检验方案-Q07 与固件 2.3.4。 HW-B 主板允许 2.3.x，HW-A 只允许 2.1.x；后来发布 2.3.5 不会悄悄改变已开工产品。

岗位、单据与状态

关键岗位

研发、结构/电子、工艺、质量、设备工程师，主数据管理员、生产代表与信息化团队；发布和审核职责分离。

关键单据与字段

产品版本、EBOM、MBOM、工艺路线、工位参数、检验方案、固件发布单和工程变更单；每类对象都需版本、状态、生效范围与来源关系。

参考状态机

草稿 → 评审中 → 待试制 → 已验证 → 已发布 → 已冻结/已失效；已发布对象只能产生新版本，不能原地覆盖。

系统边界、异常闭环与指标

系统边界

PLM 管产品定义、EBOM 与变更；ERP 管物料经营主数据；MES 消费受控 MBOM/路线并保存工单快照；QMS 管检验标准；制品库管固件二进制与签名。

典型异常

新主板无兼容固件：工位拦截 → 隔离批次与在制 → 核对硬件/替代/发布状态 → 修复同步或走新固件发布 → 重烧与复验 → 关闭技术异常。

指标

  • 制造基线一次发布通过率
  • EBOM—MBOM 差异关闭周期
  • 版本原因停线时长、固件错版拦截次数
Java 开发关注点与阶段自测

实现关注点

不可变版本与工单快照；发布采用事务落库加 Outbox；固件校验哈希、签名、硬件适用范围；缓存失效事件可重放；前端展示版本逐项差异。

常见误区

把 EBOM 与 MBOM 当同一张表；路线只有工序名；固件只用文件名识别；工程变更覆盖已下达工单的历史依据。

自测

  1. EBOM 转 MBOM 为什么要保存行级来源？
  2. 新路线如何只对新工单生效，同时保留旧工单证据？
  3. 防止烧错固件至少需要哪些校验信息？
03

ERP / APS · MES 执行反馈

计划排产

业务目标 / 完成标志

把需求转换成时间、数量、产线和优先级明确的可执行计划。 完成标志是工单冻结受控版本并通过物料、产能校验后下达 MES。

打开计划排产完整详情页 →

触发

销售订单、预测补库、安全库存、返工补产或售后备件需求触发 MPS/MRP 与排程。

前置条件

MBOM、路线、库存与在制快照、采购到料、工作中心日历、标准工时和设备日历有效。

数据关系

MPS 汇总需求，MRP 展开物料；计划拆为生产工单和工序计划，并以需求分配连接订单来源。

从触发到完成

  1. MPS 汇总订单与预测并扣减成品、在制和已确认供给。
  2. MRP 按 MBOM 展开净需求，考虑损耗、在途、替代和提前期。
  3. 把计划订单按追溯粒度、交付批次和换线经济性拆分为生产工单。
  4. 校验班次、设备、夹具、维护与物料可用日，形成有限产能排程。
  5. 冻结近期计划并下达 MES；滚动重排保留版本、约束与人工原因。
智能锁案例

深灰与银色锁共 3,000 套，APS 先连续排两个深灰工单，再排银色以少换一次线； 第三个工单因指纹模组晚到顺延。工单冻结配置、MBOM、路线和固件版本。

岗位、单据与状态

关键岗位

主计划员、物料计划员、车间调度、生产主管、采购、仓储、工艺/质量与设备工程师。

关键单据与字段

MPS、MRP 建议、生产计划、生产工单、工序计划和排程版本；核心字段包含来源需求、产品版本、数量、资源、起止时间、优先级与锁定标记。

参考状态机

计划建议 → 已创建 → 已排程 → 已冻结 → 已下达 → 执行中 → 已完工 → 已关闭；变更进入评审，执行异常可暂停或终止。

系统边界、异常闭环与指标

系统边界

ERP 管 MPS/MRP 与经营数量，APS 管有限排程建议，MES 管现场派工和实绩；WMS 提供物料可用日，QMS 提供冻结，设备系统提供资源可用性。

典型异常

指纹模组延迟：定位受影响工单与订单 → 评估替代、换序、拆单或调拨 → 审批重排版本 → 调整备料 → 回告交期风险 → 四方状态一致后关闭。

指标

  • 计划达成率、排程稳定性
  • 瓶颈负荷率、换线时间占比
  • 缺料/版本/设备导致的重排次数
Java 开发关注点与阶段自测

实现关注点

下达、拆分、暂停使用命令与乐观锁；排程作为可取消异步长任务；统一班次跨日语义；工单事件按来源 ID+版本幂等；拖拽排程必须提交原因。

常见误区

把 MRP 直接当排程；用单一状态混合创建、冻结和下达；盲目提前生产；重排覆盖旧版本与解释依据。

自测

  1. MPS、MRP、生产工单、工序计划各回答什么？
  2. 已备料或开工后取消工单，需要哪些补偿？
  3. 交期、物料与换线冲突应如何可解释地展示？
04

WMS / ERP / MES / QMS

物料齐套

业务目标 / 完成标志

让正确、合格、可追溯的物料在正确时间到达正确线边位置。 完成标志是工单需求与实物扫描核对、关键批次可用且账卡物一致。

打开物料齐套完整详情页 →

触发

已下达或即将开工的工单触发备料，也可由拉动信号、配送节拍或线边最低库存触发补料。

前置条件

MBOM、投料点、仓库/线边库位、库存状态、批次规则和替代组已发布且物料质量可用。

数据关系

物料需求与库存批次通过分配/领料明细形成多对多；投料再把批次或关键件 SN 连接到工序与整锁。

从触发到完成

  1. 按工单和 MBOM 计算需求，扣减已领、线边可用和可复用余料。
  2. WMS 按 FIFO/FEFO、同批优先与质量状态分配库存。
  3. 扫描物料、批次、容器与数量完成拣货、复核、配送和线边接收。
  4. MES 校验产品版本、替代关系、有效期与投料工序后记录实际消耗。
  5. 缺料走调拨、替代、分批、换序或延期；完工前完成领退料对账。
智能锁案例

500 套工单中，主板按批次、指纹模组按 SN、螺钉按数量追溯。 第二批主板仍待检，只允许已放行的 300 件到可投料区，计划先生产 300 套。

岗位、单据与状态

关键岗位

物料计划员、仓库拣货/复核/配送、线边物料员、班组、质量、采购、工艺工程师与计划员。

关键单据与字段

齐套清单、备料/拣货单、领料/调拨单、投料记录、替代料申请、退补料/超领单和缺料异常；必须保留工单、批次、容器、状态、数量与去向。

参考状态机

待计算 → 待分配 → 已分配 → 拣货中 → 待配送 → 已到线边 → 已齐套；缺料、错料、质量冻结和工单取消分别走处置分支。

系统边界、异常闭环与指标

系统边界

WMS 管库位、容器和仓内实物；ERP 管库存账和领退料凭证；MES 管线边投料、消耗与绑定；QMS 决定冻结/放行；PLM/ERP 提供替代关系。

典型异常

到线主板与领料单批次不符：拦截并物理隔离 → 复核容器与库存 → 冻结已装配 SN → 重新拣配 → 冲销/补记 → 盘点与防错验证后关闭。

指标

  • 开工前齐套率、缺料停线时长
  • 拣配准确率、线边库存周转
  • 超领率、领退料对账一次通过率
Java 开发关注点与阶段自测

实现关注点

库存分配使用条件更新或预留表；扫码事件 ID 保证弱网重发幂等；跨 WMS/ERP/MES 使用 Saga 与冲销；批次规则版本化且可解释；高风险调整分权审计。

常见误区

把已分配当已到线；所有物料统一追溯粒度；替代料口头批准；退料不引用原批次与原领料记录。

自测

  1. 已分配、已领料、已到线、已投料分别是什么事实？
  2. 批次、SN、数量三种追溯粒度如何选择？
  3. WMS 移库成功而 ERP 记账失败如何补偿？
05

MES / 设备系统 · 单件制造事实

生产执行

业务目标 / 完成标志

把已下达工单转化为受控、可证明的制造过程。完成标志是每个整锁 SN 按冻结路线完成必经工序，绑定、固件、参数和测试证据完整且执行异常已关闭。

打开生产执行完整详情页 →

触发

已下达工单满足开工条件后触发派工，也可由班组接班、节拍拉动或上游工序完成触发。

前置条件

制造基线、齐套物料、人员资质、设备校准、工装、作业指导和 SN 编码规则均有效。

数据关系

一个生产工单包含多个整锁 SN；每个 SN 产生多条过站记录，并通过绑定连接关键件、物料批次和固件。

从触发到完成

  1. 班组按工序计划派工，校验人员、工位、设备、工装和物料。
  2. 生成整锁 SN，并按路线记录每次进入、尝试、失败与成功过站。
  3. 扫描主板、指纹模组和物料批次，校验后与整锁 SN 建立装配绑定。
  4. 烧录受控固件并回读摘要；采集扭矩、电流、通信和开闭锁测试。
  5. 异常进入暂停/返工路线；末工序核对路线、绑定、质量结果与数量后申报完工。
智能锁案例

LOCK-260728-000123 绑定 PCB-SN-88421、FP-SN-39210 与锁体批次， 烧录 2.3.4 并保存摘要。电机电流超限后暂停，更换电机、返工复验，旧失败与旧件关系不删除。

岗位、单据与状态

关键岗位

生产主管、班组长、操作员、物料员、设备/工艺工程师、质量人员和 MES 管理员。

关键单据与字段

派工任务、整锁 SN、过站记录、装配绑定、烧录记录、参数采集、暂停/返工单与完工申报；实际人员、设备、时间、版本和结果不可缺失。

参考状态机

已创建 → 待开工 → 加工中 → 工序完成 → 待下工序 → 已完工；失败可暂停、返工、复验或报废。“已完工”不等于质量已放行。

系统边界、异常闭环与指标

系统边界

MES 管工单执行、过站、绑定与实绩；设备/SCADA 管原始控制和高频数据；PLM 提供工艺依据；QMS 管质量处置；ERP 接收汇总完工与消耗。

典型异常

设备 PASS 但 MES 超时：SN 保持结果待确认 → 设备按测试会话 ID 重发 → MES 幂等写入 → 必要时授权补采 → 核对唯一结果 → 改进缓存与监控后关闭。

指标

  • 小时产出、工序 FPY、整路线 RTY、返工与报废
  • 单件周期、工序节拍、在制等待
  • 采集成功率、绑定完整率、错版拦截次数
Java 开发关注点与阶段自测

实现关注点

SN 状态条件更新；同一事务写过站、消耗与 Outbox；测试会话 ID 处理重复乱序；绑定以事件/有效期表达；离线队列可续传；跳站、补录、解绑必须审计。

常见误区

只记工单完工数量；设备 PASS 自动等于过站；返工删除原失败；超时后重复点击造成重复扣料或绑定。

自测

  1. 过站接口怎样同时避免重复过站、扣料和消息丢失？
  2. 解绑和换件为什么必须追加历史记录？
  3. 设备 PASS 但 MES 超时时为何不能手填合格？
06

QMS / MES · 独立质量状态

质量管控

业务目标 / 完成标志

贯穿 IQC、IPQC、FQC、OQC，使不合格可识别、隔离、评审、处置、复验和改进。 完成标志是判定可解释，实物与系统状态一致，处置及 CAPA 形成闭环。

打开质量管控完整详情页 →

触发

采购到货触发 IQC，换线/换料触发首检，末工序完工触发 FQC，发货批次触发 OQC。

前置条件

检验方案、抽样标准、缺陷代码、判定规则、量具校准和适用产品/工艺版本已确认。

数据关系

检验任务引用到货、工单、工序或完工等触发来源；失败结果连接 NCR、处置、复验与 CAPA。

从触发到完成

  1. 按到货、换线、巡检、完工与出库事件创建任务并冻结检验方案。
  2. 核对样本、量具校准与环境，保存实测值、规格限、设备和证据。
  3. 规则判定超限后立即停线/隔离，创建 NCR 并计算影响范围。
  4. 评审返工、挑选、让步、退货或报废，MES 执行批准路线。
  5. 独立复验并由授权角色放行；系统性问题进入 CAPA 和效果验证。
智能锁案例

FQC 发现某整锁电机峰值电流超限，QMS 由电机批次扩展冻结另 47 个 SN。 评审决定逐件换电机并全检，记录新批次与复验结果后才解除冻结。

岗位、单据与状态

关键岗位

IQC/IPQC/FQC/OQC 检验员、质量/供应商质量工程师、生产、工艺、计量设备、仓储、计划与授权评审人。

关键单据与字段

检验方案、检验任务/批、特性结果、NCR、评审处置单、复验记录与 CAPA；保存样本/SN、实测值、规格版本、证据、结论与批准人。

参考状态机

已发现 → 已隔离 → 待评审 → 已定处置；随后进入返工复验、挑选、让步、退货或报废分支，不能直接把不合格改成合格。

系统边界、异常闭环与指标

系统边界

QMS 管标准、任务、不合格和 CAPA；MES 执行现场检验、返工与质量门禁；WMS/ERP 消费放行状态；设备系统保留原始曲线。

典型异常

巡检发现扭矩偏低：暂停工位 → 按上次合格到发现时间圈定 SN → 隔离 → 校准与分析 → 全检/加严 → 返工复验 → 首件确认复产 → CAPA 验证后关闭。

指标

  • 各检验环节首次合格率、返工复验通过率
  • NCR 关闭周期、逾期与重复发生率
  • 客诉逃逸率、CAPA 按期有效率
Java 开发关注点与阶段自测

实现关注点

制造与质量双状态；规则与规格版本化；数值用 BigDecimal 和明确单位；曲线/照片保存哈希与权限；让步和更正追加审计；冻结事件跨系统幂等传播。

常见误区

终检替代过程质量；只保存 PASS/FAIL；系统冻结与实物隔离不一致；返工后未经独立复验就放行。

自测

  1. 制造完成和质量待放行为何必须分开？
  2. 怎样用时间窗、设备与过站数据圈定影响 SN？
  3. 只保存 PASS/FAIL 会损失哪些审计能力？
07

MES / WMS / ERP / QMS

成品入库

业务目标 / 完成标志

把已完工整锁转为包装明确、库位可见的成品对象。 完成标志是 SN—箱码—入库单关系完整，包装、上架、质量和账务四类状态各自明确。

打开成品入库完整详情页 →

触发

生产工单末工序完工、质量放行或包装批次达到交接条件时，触发包装和入库作业。

前置条件

包装规范、标签版本、箱码/托盘规则、目标仓库与库位、库存状态映射和交接点已明确。

数据关系

多个 SN 组成一个箱码，多个箱码可组成托盘并进入入库单；绑定事件和库存移动共同保留历史。

从触发到完成

  1. 汇总完工 SN，校验路线、测试、质量状态与工单数量。
  2. 扫描配置和附件，按受控包装/标签版本完成单品包装。
  3. 将多个整锁 SN 绑定唯一箱码，尾箱确认后封箱并按需绑定托盘。
  4. WMS 扫箱收货、展开抽核、记录实收与库位，再完成上架。
  5. ERP 过账并与 MES/WMS 对账；拆箱、重打和差异必须走冲销与重绑。
智能锁案例

每箱 4 套同配置智能锁，箱码 CTN-260728-0088 绑定四个整锁 SN。 上架到 FG-A-03-02 后仍可能处于待检/待过账，因此实物已上架不代表销售可用。

岗位、单据与状态

关键岗位

包装操作员、生产班组、质量人员、仓库收货/上架、仓储主管、计划/订单与 MES/WMS/ERP 管理员。

关键单据与字段

完工交接单、包装任务、箱码/托盘、SN—箱码绑定事件、成品入库单、上架任务和入库差异单；字段覆盖版本、数量、库位、状态、人员和时间。

正交状态向量

包装：待包装→已封箱；收货/上架：待交接→已上架；质量：待检→合格/冻结；账务：待过账→已过账。四者不能压成一个枚举。

系统边界、异常闭环与指标

系统边界

MES 管完工 SN、包装执行和绑定；WMS 管收货、库位与移动；ERP 管成品账与凭证；QMS 决定入库/OQC 放行。每个事件要标明业务时点。

典型异常

箱码显示 4 件但实物 3 件：暂停收货并进差异区 → 锁定箱与 SN → 查包装事件 → 补装或冲销重绑 → 最终实收过账 → 复核防错后关闭。

指标

  • 完工到入库周期、上架及时率
  • 入库一次准确率、绑定完整率
  • 待检/冻结滞留、三系统对账差异
Java 开发关注点与阶段自测

实现关注点

分别持久化四类状态与版本；约束一个 SN 只有一个有效箱绑定；打印重试与标签重制使用不同幂等语义；入库跨系统 Saga 可补偿；箱码展开分页索引。

常见误区

把完工、放行、收货和入库视为同一时点；箱码不落 SN；标签重制不作废旧标；为修短少直接改数量或删绑定。

自测

  1. MES 完工、WMS 上架、QMS 放行、ERP 过账各是什么事实？
  2. 短少时为什么不能只修改箱内数量？
  3. 打印超时与标签重制的幂等策略有何不同？
08

ERP / WMS / MES / QMS / 售后

发货与追溯

业务目标 / 完成标志

把正确成品交付给正确客户，并让每次交付回到完整制造证据链。 完成标志是订单、客户、箱码/SN、物流与出库关联完整，正反向追溯和召回可闭环。

打开发货与追溯完整详情页 →

触发

已批准发货通知触发拣配；客户投诉、供应商质量通知、工程风险或监管要求触发追溯。

前置条件

合格可用库存、客户配置和批次限制、箱码展开能力、完整制造谱系及物流信息已具备。

数据关系

销售订单行可产生多个出库单；出库单包含多个箱码，箱码展开整锁 SN 并形成客户/渠道交付记录。

从触发到完成

  1. ERP 按订单和审批生成发货通知，WMS 分配合格可用库存。
  2. 按波次扫描库位、箱码与 SN 拣货，复核产品、配置、数量和质量。
  3. 装车交接并完成 WMS 出库、ERP 凭证和逐 SN 客户交付记录。
  4. 售后由故障 SN 反查产品、固件、关键件、工序、测试、入库与客户去向。
  5. 由缺陷批次正查受影响在制、库存、在途与已交付 SN，执行冻结、召回与 CAPA。
智能锁案例

某锁偶发无法联网，反查到 PCB-0721-A 主板批次与固件 2.3.4 的组合风险。 正向圈定同组合 SN：在库冻结、在途拦截、已交付对象推送受控升级并逐件回写结果。

岗位、单据与状态

关键岗位

销售/订单运营、仓库计划/拣货/复核、物流、财务、质量、售后、生产/工艺/研发、供应商质量与信息化团队。

关键单据与字段

发货通知/销售出库单（订单号/行、客户、产品配置、计划数量、交期、批次要求、地址）； 波次/拣货任务（波次、库位、箱码/托盘、分配数量、策略、操作人）； 发货复核记录（出库单、箱码、SN 清单、复核人、时间、差异）； SN 交付记录（整锁 SN、订单行、客户/渠道、出库时间、保修起点）； 追溯/召回案件（触发对象、方向、范围版本、结果快照、行动状态）。

参考状态机

待分配 → 已分配 → 拣货中 → 待复核 → 已复核 → 待装车 → 已出库 → 已交付；召回另走风险评估、批准、通知、执行、效果核对与关闭。

系统边界、异常闭环与指标

系统边界

ERP 管客户、销售出库和账务；WMS 管拣配与库存扣减；MES 管制造谱系；QMS 管风险、召回和 CAPA；售后系统管客户沟通与维修。

典型异常

供应商批次安全风险：映射企业批次与主板 SN → 找整锁 SN → 按在制/库存/在途/交付分类 → 冻结与通知 → 逐 SN 行动复验 → 数量对账和 CAPA 后关闭。

指标

  • 准时足量交付、拣配复核准确率
  • 追溯响应时间、链路完整率
  • 召回触达/完成率、售后故障率
Java 开发关注点与阶段自测

实现关注点

事件或 CDC 构建带来源与有效时间的追溯读模型；深链查询限制深度并支持异步导出；客户信息最小权限；召回逐 SN 工作流幂等可续跑；外部回传验签防重放。

常见误区

出库只记型号数量；平时不治理绑定完整性；正向追溯遗漏在制与维修换件；召回 Excel 覆盖范围版本。

自测

  1. 故障 SN 反查供应商批次要经过哪些关系与系统？
  2. 正向追溯为何必须区分在制、库存、在途和交付？
  3. 召回范围快照如何兼顾新鲜度、隐私与审计？
