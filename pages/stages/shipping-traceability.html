LAYER 01 · BUSINESS

业务层：交付是数字线程的落点，也是质量反馈的起点

发货由批准的发货通知触发；追溯可由客诉、供应商质量通知、工程风险或监管要求触发。完成标志是订单、客户/渠道、箱码、SN、物流和制造谱系完整关联，风险行动逐件闭环。

关键岗位

订单运营、仓库计划/拣货/复核、物流、财务、质量、售后、工艺/研发、供应商质量和信息化。

进入条件

发货授权、客户配置、合格可用库存、批次限制、箱码展开、制造谱系和地址/物流信息完备。

退出条件

逐 SN 客户去向可确认，出库与财务对账完成；追溯案件的范围、行动和效果均已验证。

  1. 创建发货通知并分配

    ERP 按订单行、客户限制和审批生成通知；WMS 只从质量可用、未被其他订单占用的库存分配。

  2. 波次拣货与复核

    扫描库位、托盘/箱码，展开核对产品配置、数量、质量、批次要求和订单分配。

  3. 装车、出库与交付记录

    完成物流交接、WMS 出库、ERP 凭证，并建立每个 SN 到订单行、客户/渠道和保修起点的关系。

  4. 售后反向追溯

    由故障 SN 反查型号/版本、工单、关键件/批次、固件、工序、设备、测试、箱码和交付。

  5. 风险正向追溯

    由供应商批次、固件或设备程序圈定受影响 SN，并按在制、库存、在途、已交付和维修中分类。

  6. 召回与效果确认

    冻结、拦截、通知、升级/维修/退换，逐 SN 记录触达、行动、复验和关闭；最终对账范围数量。

智能锁案例：某锁偶发无法联网，反查发现主板批次 PCB-0721-A 与固件 2.3.4 的组合风险。正向追溯将同组合 SN 分成在库冻结、在途拦截和已交付三组；已交付客户执行受控升级，并逐 SN 回写新固件哈希与验证结果。

LAYER 02 · DATA

数据层：交付记录把制造谱系接到客户去向

发货通知 / 出库单

交付授权

订单号/行、客户、产品配置、计划数量、日期、批次限制、地址、审批、仓库和状态。

分配 / 拣货 / 复核

实物执行

库存单元、箱码/托盘、库位、分配数量、策略、操作人、复核差异、装车和物流单号。

SN 交付记录

客户去向

整锁 SN、订单行、客户/渠道、出库时间、交付/安装时间、保修起点和当前服务状态。

追溯 / 召回案件

范围与行动快照

触发对象、方向、查询版本、范围快照、风险等级、批准、逐 SN 行动、触达和效果。

发货与召回参考状态

  1. 待分配
  2. 已分配
  3. 拣货中
  4. 待复核
  5. 已复核
  6. 待装车
  7. 已出库
  8. 已交付

分配失败可重新分配 → 待分配 / 取消 / 已关闭。召回另有风险评估 → 待批准 → 通知中 → 行动中 → 效果核对 → 已关闭。

追溯方向起点必须覆盖
反向故障整锁 SN订单、产品/制造版本、工单、用料/关键件、固件、过站、测试、箱码与客户。
正向物料批次 / 固件 / 设备程序受影响 SN 及其当前所处在制、库存、在途、交付或维修状态。
召回对账批准范围快照应行动、已触达、已完成、失败、豁免和失联数量必须守恒。

LAYER 03 · SYSTEM

系统层：追溯是跨系统读模型，不是某一张“万能表”

系统贡献证据数据边界
ERP / CRM订单、客户/渠道、出库财务与承诺客户数据最小化暴露，MES 不复制全部隐私。
WMS / 物流分配、拣配、箱码移动、出库和在途提供实物去向，不修改制造谱系。
MES工单、SN、绑定、固件、工序和测试制造谱系权威来源，保存来源与版本。
QMS / 售后风险、NCR/CAPA、客诉、维修换件和召回行动维修换件形成新有效关系，原装配历史不删除。

LAYER 04 · IMPLEMENTATION

实现层：事件化读模型、范围快照和可续跑工作流

  • 追溯读模型消费 ERP/WMS/MES/QMS 事件构建图或邻接表，边带来源系统、业务时间、有效期和同步时间。
  • 查询保护限制深度、节点数和时间窗；大范围正向查询转异步任务并输出带版本的文件。
  • 时间语义区分事件发生时间、系统接收时间和关系有效时间，处理迟到、乱序和补录。
  • 范围快照召回批准时固定对象列表或查询条件+数据水位，后续新增对象通过增补版本管理。
  • 逐件工作流召回行动按 SN 幂等执行、可重试、可暂停；总体状态由逐件结果聚合而非手工勾选。
  • 隐私与审计制造人员默认只见渠道/脱敏客户；导出、查看联系方式和批量通知均记录用途与操作者。

CONTROL

异常闭环与指标

  • 箱码可查但成员缺失：暂停出库 → 回查包装事件和 WMS 实收 → 盘点实物 → 修复关系并重新验证追溯完整性。
  • 供应商风险批次编码不一致：建立供应商批次到企业批次映射 → 保存匹配依据和置信度 → 人工复核模糊对象。
  • 已交付对象无法触达：保留多渠道尝试、失败原因和后续计划；不得为了关闭率把未触达标成已完成。
准时足量交付按订单行承诺日期和数量衡量
追溯响应 / 完整率查询耗时及应有关联中有效证据比例
召回触达 / 完成率基于批准范围快照逐件聚合
