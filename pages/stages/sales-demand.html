LAYER 01 · BUSINESS

业务层：从“客户想要”到“制造能承诺”

触发可以是客户下单、渠道补货、预测滚动、促销备货或订单变更。完成不是“保存了一张订单”，而是订单行的配置、数量、交期、交付地点和变更基线都有明确责任人及 ATP/CTP 依据。

关键岗位

销售、订单运营、主计划员、产品经理、工艺工程师、采购/仓储、质量与财务信用控制。

进入条件

客户与渠道有效；型号、销售配置规则和计量单位可识别；收货地点、批次限制和服务要求明确。

退出条件

配置可制造，交期有依据，风险和例外已审批，订单行进入可计划状态；后续变化必须形成新版本或变更单。

  1. 接收需求并拆到订单行

    把型号、颜色、开门方式、通信制式、面板、电池、固件区域版、包装和数量拆成结构化配置。

  2. 执行配置校验

    检查互斥与依赖，例如某通信模组要求特定主板和固件；不能只校验“物料编码存在”。

  3. 执行 ATP/CTP 评估

    ATP 看可用成品与已确认供给；CTP 再看关键物料、产能、换线、检验和外协约束。

  4. 冻结订单行基线

    确认数量、承诺日期、优先级与配置版本，记录评估时点、规则版本和人工覆盖原因。

  5. 受控处理变更

    识别受影响的计划、工单、备料、在制和已交付对象，决定新旧需求的切换点与补偿动作。

智能锁案例：客户订购 2,000 套深灰色蓝牙智能锁，要求支持企业 App 和指定包装。订单评审发现企业 App 需要主板 V3 与固件 2.3.x；交期承诺必须同时引用主板到料日、烧录工位能力和包装材料可用日。

LAYER 02 · DATA

数据层：订单行不是工单，分配关系不能省

销售订单 / 订单行

经营需求载体

订单号、行号、客户/渠道、产品、配置版本、数量、单位、承诺日期、交付地点、客户批次限制、状态和变更版本。

需求评审

承诺证据

评审时间、ATP/CTP 快照、关键约束、可承诺数量/日期、例外、审批人和规则版本。

需求分配

多对多桥接

订单行 ID、计划/工单 ID、分配数量、来源系统、有效状态。一个工单可服务多个订单，一个订单也可拆给多个工单。

变更影响

历史与补偿

变更前后值、版本号、原因、影响对象、处理决定、补偿进度。禁止直接覆盖已经参与下游执行的字段。

参考状态流

  1. 草稿
  2. 待配置校验
  3. 待供给评估
  4. 待审批
  5. 已确认
  6. 已转计划
  7. 已关闭

取消、拒绝和变更评审是旁路状态；应分别记录原因与影响，不应把所有情况压成一个“无效”。

关系基数为什么重要
销售订单 → 订单行一对多交期、配置和交付状态通常在行级不同。
订单行 ↔ 生产工单多对多拆单、并单、补产与库存履约都需要显式数量分配。
订单行 → 变更版本一对多保留每次承诺依据和下游影响范围。

LAYER 03 · SYSTEM

系统层：经营承诺归 ERP，制造能力由多个系统共同证明

系统主责本阶段交互
CRM / ERP客户、价格、信用、订单和承诺保存订单基线，发起评审与变更，接收可承诺结果。
PLM产品与销售配置约束的设计依据验证型号/选件是否有可发布产品定义。
APS / ERP 计划供给与产能评估提供 ATP/CTP、关键约束与可用日期。
MES产线能力与历史实绩反馈节拍、良率、换线、工位与在制事实，不修改订单承诺。
WMS / QMS实物可用量 / 质量可用性排除冻结、待检、已分配和不可用库存。

LAYER 04 · IMPLEMENTATION

实现层：把配置、承诺和变更做成可追责的契约

  • 聚合与版本订单行是独立并发边界；使用版本号或 ETag 防止两个审批人相互覆盖。
  • 幂等接口订单同步键建议由来源系统 ID、行 ID 和版本组成；重复事件返回同一处理结果。
  • 规则可解释配置失败需返回规则编号、冲突选项、规则版本和修复建议，不能只有“参数错误”。
  • 事务消息本地事务写订单快照与 Outbox，再异步分发给计划/MES；消费端按事件 ID 防重。
  • 变更影响查询按订单行展开工单、备料、在制、入库和发货对象，先出影响快照再审批。
  • 权限审计承诺日期、客户配置和人工覆盖规则是高风险字段，记录旧值、新值、理由与操作者。

CONTROL

异常闭环与指标

  • 配置不存在：拒绝直接下达 → 转产品/工艺评估 → 新建受控配置或建议替代 → 回写客户决定。
  • 交期不可满足：展示物料、产能、质量和外协瓶颈 → 比较拆单、替代、加班、延期方案 → 重新承诺并留痕。
  • 已开工后改单：冻结自动覆盖 → 识别在制和已采购影响 → 批准继续旧版、返工或重制 → 数量与成本对账。
订单一次确认率无需补充或返审即形成可计划订单行的比例
承诺达成率按确认日期足量交付的订单行比例
变更响应时长从变更提出到影响评估和决策完成
