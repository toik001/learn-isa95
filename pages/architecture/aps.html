APS：把需求排成可执行顺序

APS 在产能、物料、换型、维护和交期约束下计算资源与时间；MES 接收已发布计划并反馈现场实绩。

典型层级：L4/L3主权：计划版本 / 约束结果来源等级：B

边界APS 是高级计划能力类别，实际可能由 ERP、MES 或独立产品提供；求解目标和冻结窗口须由企业确认。

AUTHORITATIVE EXPLANATION

官方产品解释与白话

Siemens强调 APS 使用高级算法和约束进行生产计划与排程。

白话：ERP 告诉我们“什么时候要多少”，APS 回答“在哪条线、哪个班次、按什么顺序做比较可行”。

CONSTRAINT MODEL

输入、硬约束和软目标

输入

需求、路线、工时、班次、能力、物料、维护窗口和在制。

硬约束

设备不兼容、物料未到、资质不足、维护锁定。

软目标

少换型、少延期、负荷均衡、重点客户优先。

VERSION STATE

计划不能原地覆盖

  • 草案
  • 求解中
  • 可行/部分可行
  • 已发布
  • 已冻结
  • 重新排程
  • 失效

MES 的任务要引用明确计划版本；重排只影响尚未开始或允许调整的任务。

SMART LOCK CASE

两种锁共用烧录与老化资源

A100 与 B200 共用烧录站。B200 指纹模组晚到且 A100 有急单，APS 调整顺序并保留瓶颈资源；设备故障后 MES 回传能力下降，APS 只重排未冻结部分。

IMPLEMENTATION

Java 实现重点

  • 三种时间区分建议、承诺和实际时间。
  • 冻结窗口防止频繁重排扰乱现场。
  • 可解释冲突输出无解原因而非只有空结果。
  • 版本引用执行事实永远指向当时发布计划。
