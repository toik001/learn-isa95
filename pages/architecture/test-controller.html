测试控制器 / IPC：把测量编成一次可追溯测试

工业 PC 或专用控制器调用仪器、通信适配器和夹具，按受控计划执行步骤并保留原始证据；MES 决定业务授权和过站。

典型层级：L1/L2主权：测试执行 / 原始测量来源等级：A/C

教学节点“测试控制器/IPC”是依据 NIST OT 架构和离散制造实践形成的节点，不是 ISA-95 强制产品名称；实际可由 PLC、IPC 或专机共同承担。

ARCHITECTURE ROLE

为什么它不应只是一个 PASS 接口

NIST OT 指南说明 OT 控制和监视物理过程。复杂测试还需把电源、万用表、相机、无线通信与夹具组织成可重复步骤。

白话：测试控制器证明“仪器按哪个计划测到了什么”；MES 证明“这次测试是否被授权并可让这把锁过站”。

SESSION STATE

产品失败、设备故障、结果未知分开

  • 已创建
  • 设备自检
  • 已接受
  • 执行中
  • 待上传
  • 已上传
  • MES 已确认

仪器自检失败属于设备故障；通信中断可能是结果未知；测量越限才是产品不合格。

SMART LOCK CASE

整锁多步骤功能测试

IPC 通过 BLE、Zigbee 或 UART 与主板通信，控制电源和夹具，执行指纹、密码、电机、低电压和通信测试。每次重测使用新 attempt，并保留授权和前次失败。

IMPLEMENTATION

Java 实现重点

  • 会话快照计划、软件、仪器、工装和校准一并冻结。
  • 步骤结构结果可检索，不只存大段文本日志。
  • 重测治理attempt_no、原因、批准人和前后关系齐全。
  • 证据一致摘要、原始数据、最终判定能相互校验。
