OT 安全：按风险分区，按用途通信

安全设计不是在 ERP 和 PLC 之间加一道防火墙，而是界定系统、划分区域与通信管道，并让远程维护、程序发布和账户全程受控。

OFFICIAL DEFINITION

两套官方框架解决什么

NIST SP 800-82 Rev.3强调 OT 与物理环境交互，具有独特的安全、可靠性和性能要求。ISA/IEC 62443-3-2 公开预览要求界定系统边界、划分区域与通信管道，并分别评估风险和目标安全等级。

白话：同一风险和保护要求的资产放进一个“安全房间”，房间之间只开有登记、有守卫、用途明确的“门”。

ZONES & CONDUITS

建议的六类区域

区域典型资产边界原则
企业 ITERP、PLM、办公终端不得直接访问 PLC
制造运营MES、WMS、QMS、EAM通过受控服务进入现场
工业 DMZ代理、中继、跳板、文件中转不能透明桥接两侧
监督区SCADA、Historian、工程站白名单访问控制区
单元控制区PLC、机器人、测试 IPC自治控制、最小上行
安全相关区安全 PLC、急停、光栅业务系统不得写安全动作

CONTROLS

最低控制集

  • 人员、服务、设备身份分开
  • MFA 与限时远程维护
  • 跳板审计和会后撤权
  • 最小端口与方向白名单
  • 程序签名、哈希和回滚
  • PLC/机器人/组态配置备份
  • 证书轮换与吊销
  • 不破坏安全状态的应急预案

SMART LOCK CASE

MES 不直接任意写 PLC

MES 把 SN、工序和已批准参数引用发送给单元网关；网关只允许操作约定握手区。PLC 控制夹具与测试节拍。工程师改程序必须经跳板、变更和验证，修改后评估已生产 SN 的影响。

JAVA BOUNDARY

应用开发要守住的线

  • 命令白名单只开放定义过的业务动作，拒绝任意点位写入。
  • 凭证治理密钥和证书不固化在代码、镜像或日志。
  • 细粒度权限查看、下发已发布参数、维护、发布程序分权。
  • 重放防护命令带 ID、时效、序号和双向身份。
