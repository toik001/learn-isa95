NODE 11 · LEVEL 1—LEVEL 3

HMI / Andon：操作窗口与异常呼叫

HMI 让操作者观察设备并执行授权操作；Andon 让缺料、质量、设备和安全异常被看见、受理、升级和关闭。

典型层级：L1—L3主权：交互 / 呼叫事件来源等级：A/C

本页导航

  • 释义
  • 界面设计
  • Andon 状态
  • 场景
  • Java 边界
安全边界网页或普通 HMI 的按钮不能代替安全功能；任何控制请求仍须由控制器校验状态与联锁。

OFFICIAL CONTEXT

两个概念分别解决什么

NIST OT 指南中的 HMI 是操作者观察过程状态并与控制系统交互的界面。Andon 在本页作为可视化异常呼叫与响应机制解释。

白话：HMI 回答“设备现在怎样、我能做什么”；Andon 回答“哪里需要谁来支援、多久响应、是否真正恢复”。

INTERACTION DESIGN

操作界面的四条底线

  • 首页优先模式、安全、关键状态和首要报警
  • 手动动作显示前置条件与拒绝原因
  • 报警可确认、可抑制但不可无痕删除
  • 维护画面与生产操作分权
  • 危险动作需要明确目标与二次确认
  • 颜色不是唯一状态表达方式

ANDON STATE

复位不等于异常关闭

  • 已创建
  • 已受理
  • 响应中
  • 物理恢复
  • 业务确认
  • 关闭

事件应记录类型、工位、工单、SN、响应人、首次响应时间、恢复时间和原因。

SMART LOCK CASE

螺钉来料异常

操作者选择“物料质量”呼叫班组与质量。HMI 保持设备安全状态；MES 冻结受影响 SN，QMS 决定处置。只有实物问题和业务影响都确认完成后才能关单。

JAVA BOUNDARY

Web 能做与不能做

  • 适合异常呼叫、状态展示、业务确认和审计。
  • 不适合安全回路、毫秒级动作和确定性闭环。
  • 事件幂等通知可以重发，Andon 事件只能创建一次。
  • 升级规则版本化响应时限、岗位和静默策略。
