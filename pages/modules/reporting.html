报表模块

报表的难点不是画图，而是让口径、粒度、时间、版本和数据水位一致；指标必须能钻取到组成它的订单、工单、SN、工序或事件。

主线：事实 → 口径 → 聚合 → 钻取聚合：指标快照高风险：口径漂移 / 重复计数

METRIC CONTRACT

每个指标先写六项契约

业务问题

指标为谁的哪个决策服务，不能先有图再找含义。

分子 / 分母

明确纳入、排除、去重和异常数据处理。

粒度

订单行、工单、SN、工序尝试、设备状态或时间片。

时间

业务时间、班次归属、时区、迟到数据和重算窗口。

版本

口径版本、计划版本、组织结构和数据水位。

钻取

从汇总值回到具体事实与排除原因。

CORE METRICS

容易混淆的制造口径

指标参考定义提醒
工序 FPY该工序首次尝试合格 SN / 首次进入该工序 SN返工后合格不能计入首次通过。
整路线 RTY完整路线各必经工序 FPY 的乘积不是“最终合格数 / 投入数”的别名。
计划达成率冻结计划内按期完成量 / 冻结计划量必须固定比较的计划版本。
OEE时间开动率 × 性能开动率 × 合格品率计划停机、标准节拍和质量分母需统一。

JAVA IMPLEMENTATION

实现切面

  • 事实分层保留原子事件表，派生宽表/汇总表，任何汇总可回溯来源。
  • 事件时间按业务时间开窗，设置迟到水位并支持有限窗口重算。
  • 口径版本指标定义、SQL/代码版本、维度快照和发布人一起保存。
  • 性能看板读预聚合，明细异步导出；避免生产交易库承担大范围分析。

VERIFY

验证清单

  • 同一 SN 多次测试是否被重复计入产出
  • 跨午夜班次是否归到正确生产日
  • 计划达成是否引用同一冻结版本
  • RTY 是否按必经工序完整路线计算
  • 迟到设备数据是否触发受控重算
  • 看板数值能否钻取到原子事实
