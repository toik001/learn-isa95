MODULE 01 · WORK ORDER

工单模块

工单不是一张“任务表”，而是对某个产品版本、数量、制造基线和执行范围的受控授权；它把销售/补库需求连接到现场实绩。

主线：需求 → 工单 → 派工 → 完工聚合：生产工单高风险：拆分 / 取消 / 超产

END-TO-END MAP

工单在八阶段中的落点

阶段工单能力关键交接
销售需求订单行形成制造需求，建立需求分配订单行、分配数量、交期和配置版本。
计划排产创建、拆并、排程、冻结与下达工单产品/MBOM/路线/检验/固件快照。
物料齐套按工单展开需求、领退补料需求行、批次分配和齐套状态。
生产执行派工、开工、WIP、完工与报废逐 SN 实绩和数量守恒。
成品入库完工交接、入库与工单结清箱码、实收、消耗和差异。

DOMAIN MODEL

对象、状态与不变量

ProductionOrder

生产工单

来源、产品、制造版本、计划数量、工厂/产线、优先级、起止、状态和版本号。

DemandAllocation

需求分配

订单行/补库需求到工单的数量桥接，支持拆单、并单和补产。

OrderSnapshot

制造快照

MBOM、路线、检验、固件和规则发布 ID，工单下达后保持不可变。

OperationDispatch

工序派工

工序、资源、班次、派工数量、开始/完成实绩和执行者。

  1. 已创建
  2. 已排程
  3. 已冻结
  4. 已下达
  5. 执行中
  6. 已完工
  7. 已关闭

不变量：分配量不超过需求剩余量；完工量 + 报废量不超过授权投入；已执行工单不能物理删除；关闭前物料、WIP、质量和入库差异必须清零或批准保留。

BUSINESS CONTROL

关键命令与异常路径

下达

校验版本发布、数量、资源、物料策略和质量限制；MES 明确接受或拒绝。

拆分 / 合并

重新分配来源需求和已发生事实；开工后通常只拆未执行余量。

暂停 / 恢复

保留暂停原因、影响对象和恢复条件，不把暂停当取消。

取消 / 终止

补偿预留、领料、在制和订单承诺；已发生事实保留并对账。

JAVA IMPLEMENTATION

实现切面

  • 聚合并发工单使用乐观锁；状态迁移由领域命令完成，禁止 Controller 直接改状态。
  • 幂等下达来源工单 ID + 版本为业务键，重复下达返回相同 MES 工单 ID。
  • Outbox状态和事件同事务写入，避免工单已下达但下游没收到。
  • 审计拆单、超产、取消、手工完工保存前后值、原因和批准。

VERIFY

验证清单

  • 一个订单行拆给两个工单后数量是否守恒
  • 同一版本重复下达是否只生成一个工单
  • 已领料工单取消是否产生退料/冲销待办
  • 历史工单能否还原当时制造基线
  • 关闭前是否仍存在在制或未入库完工
  • 并发暂停与完工是否只有一个成功
