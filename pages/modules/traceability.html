MODULE 06 · TRACEABILITY

追溯模块

追溯不是事后查一张表，而是在八阶段持续积累带来源、版本和有效时间的关系，最终形成从订单到客户、从缺陷批次到全部受影响对象的双向证据链。

主线：版本 → 批次 → SN → 箱码 → 客户聚合：追溯关系 / 读模型高风险：断链 / 错链 / 隐私

EVIDENCE BUILD-UP

八阶段逐步补齐证据

  1. 销售需求

    订单行、客户/渠道、配置与承诺。

  2. 产品与工艺准备

    产品、EBOM/MBOM、路线、规格与固件版本。

  3. 计划排产

    需求分配、工单和制造快照。

  4. 物料齐套

    供应商批次、企业批次、容器和领料。

  5. 生产执行

    整锁 SN、关键件、过站、设备、固件和测试。

  6. 质量管控

    样本、NCR、处置、复验与放行。

  7. 成品入库

    箱码/托盘、入库单和库位。

  8. 发货与追溯

    出库单、订单行、客户去向、维修与召回。

RELATION MODEL

每条关系都要有来源和有效时间

节点

业务对象

订单行、版本、工单、批次、关键件 SN、整锁 SN、工序、测试、箱码、客户和案件。

边

业务关系

分配、组成、消耗、绑定、执行、装箱、入库、交付、维修换件和召回行动。

时间

三种时钟

业务发生时间、关系有效时间、系统接收时间；迟到事件不能覆盖未来事实。

来源

可信证据

来源系统、来源 ID、事件 ID、版本、同步时间和数据质量状态。

QUERY

两类核心查询

反向追溯

从故障整锁 SN 回到订单、制造版本、工单、关键件/批次、固件、过站、测试、箱码与客户。

正向追溯

从物料批次、固件或设备程序找到受影响 SN，并按在制、库存、在途、交付和维修分类。

完整性验证：随机抽取已交付 SN 反查，再随机抽取主板批次正查；两端数量和关系必须相互印证。

JAVA IMPLEMENTATION

实现切面

  • 事件读模型订阅各域事件构建邻接关系，不让在线跨库 JOIN 成为唯一方案。
  • 查询保护限制深度/节点数；大范围查询异步导出并携带数据水位。
  • 关系有效期解绑、换箱、维修换件关闭旧关系并追加新关系。
  • 数据治理断链、孤儿节点、循环包装和重复有效绑定建立持续质量检查。

VERIFY

验证清单

  • 一个 SN 能否还原当时版本而非当前版本
  • 关键件换件前后关系是否都可查询
  • 箱码能否展开唯一、完整 SN 清单
  • 供应商批次是否可映射企业批次
  • 正向查询是否覆盖在制、库存、在途和交付
  • 客户数据是否按角色脱敏与审计
