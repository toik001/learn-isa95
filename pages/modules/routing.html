工艺在八阶段中的落点

阶段能力证据
产品与工艺准备从 MBOM 定义路线、工序、资源、检验和返工路径发布版本与生效范围。
计划排产用标准工时和资源约束形成工序计划路线快照与工序负荷。

质量管控按处置决定进入返工路线并复验原失败、返工来源和新结果。

DOMAIN MODEL

路线不是工序名称列表

RoutingVersion

路线版本

产品/制造版本、工厂、状态、生效范围、来源变更和发布人。

Operation

工序

工序编码、类型、前后关系、工作中心、标准工时和必经/可选标记。

OperationRule

门禁规则

前序、人员资格、设备/工装、物料、参数、质量、数据完整和允许结果。

ReworkPath

返工路线

触发缺陷、进入点、必做工序、复验点、退出条件和批准角色。

EXECUTION CONTROL

过站门禁与返工控制

  1. 识别上下文

    根据 SN、工单快照和当前 WIP 找到唯一有效路线。

  2. 验证前置

    前序成功、人员资质、设备校准、物料绑定、固件和质量状态全部满足。

  3. 记录尝试

    每次执行有尝试号与输入快照，不只覆盖最终结果。

  4. 异常转路径

    失败暂停正常路线，由批准处置选择返工入口与复验点。

  5. 检查退出

    返工完成后验证必做步骤和复验，才恢复正常路线。

智能锁例：电机电流超限不能直接回到最终测试。返工路线要求拆机、解绑旧电机、绑定新电机、重新装配、扭矩确认和功能复验。

JAVA IMPLEMENTATION

实现切面

  • 不可变发布路线发布后生成稳定 ID，工单引用快照，不查询“当前最新版”。
  • 规则执行器规则输出编号、输入、版本和原因；规则失败可解释、可测试。
  • 图校验发布前检测无起点、断路、循环和不可达工序，返工回边单独建模。
  • 版本缓存按发布 ID 缓存；失效事件可重放，找不到版本时阻断而非降级到最新版。

VERIFY

验证清单

  • 旧工单在新路线发布后是否仍按旧版执行
  • 跳过前序是否被后端而非仅前端拦截
  • 返工是否保留原失败和旧件关系
  • 路线图是否存在循环或不可达节点
  • 人员/设备资格过期是否即时阻断
  • 规则失败能否给出具体原因与版本
