FACT MODEL

不要混淆四类物料事实

需求

某工单按 MBOM 应该在某工序消耗什么、多少。

分配

某库存单元的数量为某需求暂时保留，尚未移动。

领料 / 移动

实物从仓库到线边，库存位置与责任发生变化。

投料 / 绑定

物料实际被某工序、工单或整锁 SN 消耗和使用。

退料必须引用原领料/投料与原批次；补料必须说明原缺口或换件原因；倒冲适合低价值稳定耗用，不能替代关键件逐件绑定。

TRACEABILITY

按风险选择追溯粒度

粒度智能锁对象控制
数量螺钉、胶、包装辅料批次 + 数量，关注损耗和超领。
批次锁体、电池、塑胶结构件供应商批次映射、质量状态和有效期。
SN主板、指纹模组、电机唯一有效绑定、换件历史和防重复。

JAVA IMPLEMENTATION

实现切面

  • 库存预留条件更新或预留表防超卖，数据库守住可用量不为负。
  • 扫码事件终端事件 ID + 业务约束，弱网重复提交返回首次结果。
  • 数量守恒需求、领料、投料、退料、报废按统一单位计算并持续对账。
  • 系统补偿WMS、MES、ERP 用 Saga 状态、重试与冲销处理部分成功。

VERIFY

验证清单

  • 两个工单并发分配是否可能占用同一库存
  • 冻结批次能否阻止拣货、投料和出库
  • 退料是否还原原批次和原领料关系
  • 关键件换件后旧绑定是否仍可查
  • 已分配与已投料数量是否被混用
  • 单位换算和小数精度是否一致
