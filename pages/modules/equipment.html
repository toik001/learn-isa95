DOMAIN MODEL

设备不是一串 IP 地址

Equipment

设备资产

编码、类型、产线/工位、能力、协议端点、状态、校准和维护策略。

ProgramRecipe

程序配方

版本、文件哈希、参数、适用产品/硬件、生效范围、批准和下发状态。

EquipmentState

状态事件

运行、待机、故障、维护、离线的开始结束、原因和来源质量。

TestSession

业务会话

会话 ID、SN、工序、设备、程序、开始结束、原始数据、结果和序号。

DATA ACQUISITION

设备采集必须先绑定业务会话

  1. MES 创建会话

    下发 SN、工序、配方 ID 和期望参数范围。

  2. 设备确认上下文

    回报设备身份、实际程序和会话接受结果，错版直接拒绝。

  3. 采集与判定

    高频数据留在设备平台；MES 保存摘要、业务结果和原始数据索引。

  4. 可靠上传

    按会话 ID 与结果序号重发，服务端防重、排序并识别缺口。

  5. 异常闭环

    超时保持待确认；禁止把“未收到”自动判为 FAIL 或 PASS。

JAVA IMPLEMENTATION

实现切面

  • 协议适配设备协议与领域命令隔离，统一映射会话、参数、报警和时间戳。
  • 幂等乱序会话 ID + 序号去重；迟到事件不倒退已关闭业务状态。
  • 存储分层关系库保存业务摘要，对象/时序库存原始曲线，二者用哈希和索引连接。
  • 观测性记录连接、下发、接收、解析、判定各阶段耗时和失败码。

VERIFY

验证清单

  • 设备实际程序与 MES 下发版本不一致是否阻断
  • 重复 PASS 是否只生成一次过站
  • 断网缓存恢复后是否保留原业务时间与序号
  • 校准过期是否禁止开始会话
  • 原始曲线是否能从业务结果定位
  • OEE 是否区分计划停机与故障停机
