智能锁数字线程

数字线程不是一张大宽表，而是由八阶段产生的业务对象、稳定标识、不可变版本和带有效期关系组成的证据网络。

起点：销售订单行核心：整锁 SN终点：客户 / 售后 / 召回

原则业务键便于人员理解与对账，来源系统 ID 用于稳定关联；两者都应保留，不能互相替代。

CHAIN

八阶段如何传递关联键

  1. 销售需求

    订单号、行号、配置版本和承诺日期。

  2. 产品与工艺准备

    产品、EBOM/MBOM、路线、检验、固件发布 ID。

  3. 计划排产

    需求分配、工单号、制造快照和排程版本。

  4. 物料齐套

    物料批次、供应商批次、容器、关键件 SN。

  5. 生产执行

    整锁 SN、过站、绑定、设备会话、固件和测试。

  6. 质量管控

    检验任务、样本、NCR、处置、复验和放行。

  7. 成品入库

    盒/箱/托盘码、入库单、库存单元和库位。

  8. 发货与追溯

    出库单、订单行、客户/渠道、维修和召回案件。

IDENTITY

四类关键标识

业务编号

订单号、工单号、箱码等面向人员；可因迁移或规则调整而变化，需与来源 ID 并存。

来源系统 ID

系统内稳定唯一，用于接口关联和防重；必须标明来源系统。

版本 / 发布 ID

指向不可变定义，不用“当前版本”解释历史事实。

事件 ID

标识一次事实传播，用于去重、重放、对账和审计。

RELATIONS

每条关系至少保存这些属性

属性用途示例
关系类型明确语义，避免万能 parent_id分配、消耗、绑定、装箱、交付。
有效时间表达换件、换箱、转交绑定时间 / 解绑时间。
来源与版本识别权威和重复/迟到MES 事件 ID、WMS 单据版本。
数量 / 单位支持多对多和数量守恒订单行分配 300 套。
原因 / 引用解释修正与例外换件引用 NCR 和返工单。

IMPLEMENTATION

Java 实现建议

  • 领域内强一致绑定、过站、装箱等不变量在本地事务和数据库约束中守住。
  • 跨域最终一致Outbox 发布事实，消费者幂等构建追溯读模型。
  • 时间语义同时记录业务发生、关系有效和系统接收时间。
  • 数据质量持续检查孤儿、断链、重复有效绑定、包装环和版本缺失。
  • 查询保护限制图查询深度/规模，大范围正向追溯异步生成。
  • 隐私最小化制造读模型只保留必要客户标识，联系方式按用途授权。

END-TO-END EXAM

用一个 SN 验证全链路

随机选择已交付整锁 SN，要求在可接受时限内给出：订单配置、产品与制造版本、工单、关键件与物料批次、固件、每次过站和测试、质量处置、箱码、入库库位和客户去向。再任选其中一个主板批次正向圈定全部受影响对象，并按在制、库存、在途和已交付分类。
