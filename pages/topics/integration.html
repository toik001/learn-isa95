跨系统一致性

ERP、PLM、MES、WMS、QMS 和设备系统无法共享一个数据库事务。可靠方案是明确主权、让事实可重放、让部分成功可见、让补偿和对账成为正式业务能力。

可靠发布：Outbox可靠消费：Inbox / 幂等部分成功：Saga / 冲销 / 对账

  • 契约

原则最终一致不等于“迟早会对”；必须有明确状态、重试上限、人工接管、冲销语义和持续对账。

CONTRACT

一份可运营的事件/接口契约

Identity

身份

事件 ID、来源系统、来源对象 ID、对象版本、业务键和 Trace ID。

Time

时间

业务发生时间、发布/接收时间、生效时间和时区。

Payload

业务载荷

状态、数量、单位、版本、引用对象；字段有兼容和废弃策略。

Result

处理结果

接受、重复、业务拒绝、暂时失败、永久失败及可行动错误码。

PATTERNS

四个基础模式

Transactional Outbox

业务状态和待发布事件同本地事务提交；发布器可重试，避免“库已写、消息丢”。

Inbox / 幂等消费

消费者以事件 ID 去重并保存结果；业务唯一键继续防语义重复。

Saga

把跨系统长事务拆成步骤，每步有成功、失败、重试、补偿与人工接管。

Reconciliation

定时按业务键、版本、数量和状态比较主从系统，发现沉默丢失与长期漂移。

PARTIAL SUCCESS

用成品入库理解部分成功

  1. MES 创建入库请求

    状态“待 WMS 接收”，请求 ID 固定。

  2. WMS 实收并上架

    实物已在仓，返回实收/差异；MES 更新“已接收待过账”。

  3. ERP 记账失败

    不能把 WMS 实物回滚成不存在；进入“待过账”，持续重试并告警。

  4. 恢复或冲销

    若业务决定撤销，生成 WMS 退回和 MES 撤销等补偿单据，引用原步骤。

  5. 三方对账关闭

    箱码、数量、凭证和状态一致后才标记完成。

OBSERVABILITY

接口要能回答“卡在哪里”

维度指标 / 日志用途
发布Outbox 积压、最老事件年龄、发布失败发现消息未离开来源系统。
消费延迟、重复率、永久失败、隔离队列判断消费能力与契约问题。
业务Saga 步骤状态、补偿次数、人工待办年龄识别部分成功长期悬挂。
对账差异数量、金额/数量、最大持续时间发现沉默丢失和错误修复。

TEST

故障注入清单

  • 业务提交后消息代理不可用
  • 消费者成功后响应丢失导致重投
  • 事件乱序和旧版本迟到
  • WMS 成功、ERP 永久失败
  • 补偿命令重复执行
  • 对账任务自身重跑与分页变化
  • 下游限流与长时间不可用
  • 人工修复后原消息再次到达
