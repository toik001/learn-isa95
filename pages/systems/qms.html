SYSTEM 05 · QMS

QMS：质量判定与闭环主权

QMS 管标准、检验、不合格、评审、CAPA 与放行；MES 和 WMS 执行现场/库存门禁并回传证据。制造系统不能因“已经做完”自行改成质量合格。

主权：标准 / NCR / 处置 / 放行下发：检验 / 冻结 / 返工接收：结果 / 执行证据

DATA OWNERSHIP

QMS 主责与现场执行

权威数据

检验规范、抽样、NCR、MRB、处置决定、复验、CAPA、冻结与放行。

MES 执行

过程检验采集、WIP 冻结、返工路线、逐 SN 处置和复验实际。

WMS 执行

库存状态限制、物理隔离、移库和放行后的可用性恢复。

设备贡献

量具/测试台身份、校准、原始测量和曲线，不自行决定 MRB 结论。

INTERFACES

质量指令必须带范围和版本

QMS 指令对象消费端必须返回
检验任务批次、SN、工序或出货批样本、原始值、规格版本和执行状态。
冻结 / 放行批次、SN、箱码或库存单元命中数量、失败对象、当前状态和时间。
处置 / 返工NCR 范围内对象逐对象执行、用料/换件、结果和数量。
CAPA原因与措施范围实施证据、验证指标和观察窗口。

INDEPENDENT RELEASE

放行不能由制造状态推导

制造状态“已完工”表示路线执行完；质量状态“已放行”表示风险经授权判断允许流转。二者分别由 MES 和 QMS 产生，通过对象 ID 与版本关联。成品入库/出库要同时检查两者，并继续检查包装和库存状态。

RISKS

常见边界错误

  • QMS 只下发批次冻结，MES 未展开已绑定整锁 SN。
  • MES 本地改成合格但没有 QMS 放行 ID。
  • 复验合格覆盖原失败与 NCR，无法解释处置。
  • 两个系统都维护检验标准且版本不一致。

BOUNDARY CHECK

边界验收

  • 标准权威来源和版本是否唯一
  • 冻结范围是否有快照或数据水位
  • MES/WMS 是否返回逐对象执行结果
  • 再次失败是否回到重新评审
  • 放行是否引用检验与处置证据
  • 跨系统是否持续核对质量状态
