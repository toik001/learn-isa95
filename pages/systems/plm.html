SYSTEM 02 · PLM

PLM：受控产品定义

PLM 证明产品在设计上是什么、为何变更和哪个版本已发布；MES 证明工单和 SN 实际用了哪个发布版本，两者之间靠不可变发布 ID 连接。

DATA OWNERSHIP

PLM 主责什么

权威数据

产品型号、设计版本、图纸、技术规范、EBOM、设计替代和工程变更。

可能主责

MBOM、路线、工艺文件、固件和检验规格；具体边界取决于企业工具链。

MES 保存

发布物的只读快照/引用、实际执行版本和现场反馈，不修改设计定义。

返回 PLM

试制问题、错版拦截、节拍/良率、替代使用和现场改进建议。

PUBLISH CHAIN

发布不是简单同步一张表

  1. 设计评审

    版本、差异、适用范围和变更原因明确。

  2. 制造化验证

    MBOM、路线、质量、设备程序与固件组合完整。

  3. 正式发布

    生成不可变发布 ID、版本、状态和生效范围。

  4. 多系统分发

    ERP/MES/QMS 消费并校验依赖，回传接受或失败。

  5. 生效与失效

    避免版本范围重叠/空档，历史引用永远可解析。

WORK-ORDER SNAPSHOT

工单为什么必须冻结版本

工单下达时冻结产品、MBOM、路线、检验和固件发布 ID。之后 PLM 新版本发布不应自动改变已下达工单；若确需切换，必须走工程变更影响评审并对未开工、已备料、已开工和已完工对象分别决定。

RISKS

常见边界错误

  • MES 永远查询 PLM“最新版”，导致历史工单无法复现。
  • 只同步 BOM 头版本，不同步行来源和生效范围。
  • 固件只按文件名识别，没有哈希、签名和硬件范围。
  • 工程变更覆盖已发生制造事实而不做影响分析。

BOUNDARY CHECK

边界验收

  • 已发布版本是否不可原地修改
  • 工单是否引用稳定发布 ID
  • MBOM 行能否回到 EBOM 行
  • 跨系统是否能核对同一版本组合
  • 生效范围是否检测重叠与空档
  • 历史版本文件是否长期可取证
