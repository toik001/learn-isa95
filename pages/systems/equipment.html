DATA OWNERSHIP

设备侧与 MES 各自证明什么

设备侧权威

控制步骤、采样点、程序日志、安全报警、原始曲线和设备本地时间。

MES 权威

SN/工单/工序上下文、制造版本、业务门禁、过站、绑定和业务结果。

共同契约

设备 ID、测试会话 ID、程序版本/哈希、参数单位、结果码、序号和时间戳。

存储分层

高频原始数据留在时序/对象存储，MES 保存摘要、哈希、结果和定位索引。

SESSION BOUNDARY

一次业务执行只能有一个可识别会话

  1. MES 授权

    创建会话并下发 SN、工序、配方和校验信息。

  2. 设备确认

    校验身份与实际程序，返回接受或具体拒绝。

  3. 设备执行

    记录控制步骤、测点、报警和本地结果。

  4. 可靠上传

    用会话 ID + 序号重发摘要和原始数据地址。

  5. MES 业务判定

    结合路线、版本、质量和幂等约束形成业务事实。

TIME & RELIABILITY

三种常见异常语义

超时

表示结果未知，不等于 FAIL；会话进入待确认并允许同 ID 重发。

重复

同一会话同序号返回首次结果，不重复过站或扣料。

乱序

以序号和状态守卫处理；迟到开始事件不能覆盖已完成状态。

RISKS

常见边界错误

  • PLC 直接写 MES 业务表，绕过路线、身份和权限校验。
  • 每次重试创建新会话，造成一把锁多条有效 PASS。
  • 只保存最终判定，不保存实际程序和原始数据索引。
  • 设备时间未同步，跨系统事件无法正确排序。

BOUNDARY CHECK

边界验收

  • 会话 ID 是否端到端唯一并可重发
  • 实际程序是否与期望发布版本一致
  • 参数名称、单位和精度是否版本化
  • 超时是否保持未知而非自动改判
  • 原始数据能否由业务结果定位
  • 时钟偏差是否监控与校正
